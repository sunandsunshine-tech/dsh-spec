# Agent Note: 独立技能通过工作流判断组合

Status: implemented

[English](2026-11-19-independent-skills-compose-through-workflow-judgment.md) | 中文

## 问题

技能可以独立安装，但真实任务经常把多个技能的通用能力放进同一个场景。若一个技能通过导入兄弟技能的命令、记录格式或调用顺序来连接两者，那么兄弟技能缺失或被替换时，规则就会失效。把全部关系搬进一个 orchestrator，又会让它拥有本应属于参与技能的政策。

技能需要一个持久边界：它们的相邻能力可以组合，但不因此成为依赖，也不让任一方知道另一方的实现。

## 决策

每个技能只拥有自己边界内的通用能力，不拥有调用者。它陈述使用该能力所需的事实、操作和完成证据，并在没有参与同一任务的其他技能时仍可独立工作。

组合由执行任务的模型根据任务、可用技能和项目证据作出工作流判断。模型选择适用技能，解析项目值，向每个能力提供显式输入，并组合结果。技能不调用兄弟技能，不把它写成依赖，也不复制或解析其命令、路径、记录格式、内部顺序或默认值。技能点名兄弟技能时，只在完整陈述通用要求之后，以带可用性限定的可选示例出现。

跨边界交接携带通用事实，而不是任一方的内部表示。它提供接收能力所定义的有限输入，也可以包含由必需检查的拥有者提供的 readiness 结果。接收方校验自己拥有的规则，但不从私有格式推断提供方的领域语义。

控制只保留给授权、不可逆动作、安全和必需校验。不可逆操作可以固定“准备、readiness、提交”的边界，因为错误成功无法修复。判断操作是否 ready 的语义选择仍由模型或工作流负责；机械门禁只验证交给它的状态和外部 readiness 证据。

## 备选方案

**让一个技能成为另一个技能的硬依赖。** 这能提供单一调用路径，却破坏独立安装，并把可选能力变成不需要它的任务也会发生的失败。

**建立一个拥有全部跨技能关系的通用 orchestrator 技能。** 它集中了组合，但 orchestrator 必须复制每个参与方的政策，新增组合也会扩大它的安装与评审面。

**合并参与技能。** 这消除了交接，却把互不相关的触发、运行要求和所有权决定合并给只需要其中一种能力的采用者。

**把通用规则复制进两个技能。** 两个技能都能独立工作，但规则出现两个所有者并会漂移，复制出的细节还会把兄弟技能实现写成必需项。

**让一个技能直接读取另一个技能的记录并调用其命令。** 这能得到方便的一体化路径，却把私有格式和调用顺序公开，并破坏等价实现。

**在提示词中固定组合后的命令序列。** 这能让一个已知技能对显得确定，却阻止模型根据可用能力、项目约定和实际 scope 调整路径。

## 后果

- 技能的任意子集仍可安装和使用；组合行为依赖模型识别可用能力及其暴露的证据。
- 跨技能行为通过独立安装场景和组合任务场景评估，而不是假定只有一个端到端命令。
- 任务可以替换同一通用能力的实现而不修改任一技能，只要新实现提供相同事实和完成证据。
- 不可逆操作获得机械的准备与 readiness 边界，语义选择仍由模型负责。
- 提示词陈述结果、约束和证据；只有实现或安全边界需要时才固定命令顺序。
