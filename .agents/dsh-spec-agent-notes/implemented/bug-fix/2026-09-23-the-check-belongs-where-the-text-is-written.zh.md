# Agent Note: 自检要待在写文本的地方

Status: implemented

[English](2026-09-23-the-check-belongs-where-the-text-is-written.md) | 中文

## 问题

一个 agent 在写 PR 说明时,从文本内部对着维护者说话:它说如果维护者认为分类不对它就改,把副本该钉在哪里这件事交出去,规定了几个 PR 的合并顺序,还引用了维护者要求过什么。这些每一句都是这套集合已经点过名的失败——读者规则说,一句写给提出这个改动的人的句子,就是写给错的读者的句子;泄漏技能的形状清单里有 stack 与 PR vantage、review choreography、reviewer-addressed justification。缺的不是规则,而是规则到达不了,缺了三条。

**没有一条规则点名这个表面。** 泄漏技能枚举了四个表面——comments、API documentation、docs、decision records——PR 说明一个都不是;散文标准的十二个位置里也没有它。

**带检查的那一半,在写作发生的地方是关着的。** 读者规则的自检住在 `prose.reader` 里,而本仓库不应用任何规范:`norms explain prose.reader --root .` 的回答是 `applied: no`,`.agents/dsh-spec/norms/` 也不存在。每次会话到达这里的是那条常驻令,它陈述了规则,**没有带检查**。

**写的人一条检查都没跑。** 自检、泄漏技能的 one test、散文标准的工作流都在手边,一条都没跑;而没有任何门禁读 PR 文本,所以流程里没有任何一步会在一篇说明上停下来。

## 决策

**检查要待在写文本的地方,而不只住在拥有这条规则的文档里。** 常驻令现在把问句带在规则旁边:草稿的每一句都对着一个问题过——它是在陈述事实,还是在称呼读者?

**模板里的注释只说这一节写什么,管声音的规则留在规则那里。** reviewer notes 的注释现在只列这一节要报告的事实;它原本唯一那个问句形状的条目——写的人拿不准什么——改成「实现时遇到、却说不清的东西,以及为什么」:一个古怪的机制,或一个真实作用不明的 API——留着不动,或试过之后放弃。那是要陈述的事实,不是抛出去的提问,而这一节正是陈述它的地方。把读者规则复述在那儿,会是一条已经有归属的规则的第二个副本,而「一个事实一个落点」防的正是这种漂移。

**别的都不动。** 读者规则本来就对每一篇文本成立,不需要哪份清单点名 PR 说明才算数;泄漏技能自己的表面清单漏掉了什么,记在下面,而不是在这里加宽。

## 曾考虑的替代方案

**只记下这次事故,别的什么都不改。** bug-fix 笔记正是本仓库放过往事故教训的地方,所以它本身就够得上一次完整改动。它落选,是因为下一个写作者会撞上同样三个空位:一份没点名这个表面的范围清单、一个落在未被应用目录里的检查、以及一条在示范称呼的模板注释。

**把读者规则复述进模板注释。** 它能在写的人动手的地方接住他,也就是上面那条缺口。它落选,是因为模板里的注释说的是这一节写什么:规则复述在那里,就是一条已有归属的规则的第二个副本,规则下一次变更就把这个副本落在后面。

**把 PR 文本加进泄漏技能的表面清单。** 形状本来就在那个技能里,缺口只有一个从句。它在这次改动里落选,是因为那份文本是要交付出去的,而它的范围句一移动就是对上游的一处有意偏离,那是它自己的一个决定;所以这里只把缺口记下来。

**靠写作者的自律。** 读者笔记已经写着没有东西在守这条规则。它落选,是因为在一次会话里自律失败了两次,而规则就在眼前:缺的是现场,不是意愿。

**加一道门禁。** 对一条老是被错过的规则,门禁是这套集合通常的答案,而它恰好是这次不会有用的那个:PR 文本不在树里,没有任何门禁读它,而为它写检查需要一个本仓库没有的表面。

## 后果

规则和它的检查现在一起出现在 agent 每次会话都会读的那份文本里。模板注释仍然只是「这一节写什么」的陈述,只是把它那个问句形状的条目改成要报告的东西,于是写作现场要的是事实而不是提问;代价是常驻令多了一个问句、模板注释改了一个条目,两者都不是门禁。

跑检查的仍然是写的人。它是一句摆在写作者面前的问题,而不是脚本能判失败的东西;读者笔记记下的那种「无人执行」,并没有因此改变。

## 暂缓

- 把 PR 说明与 PR 评论写进泄漏技能的范围。它动的是交付文本,并且是对上游的有意偏离,所以是它自己的一个决定;在此之前,覆盖这些形状的那几个分类只到达那个技能点名的四个表面。
