# Agent Note: 从 DSH UI 技能锻造 dsh-spec-web-ui-review

Status: implemented

[English](2026-11-20-forging-dsh-spec-web-ui-review.md) | 中文

## 问题

技能集合覆盖评审、交付、提示词、持久文本和项目指令，但没有一套项目级程序来验证浏览器渲染的 UI 变更。代码评审可以阅读 diff，测试套件也可以通过，而组装后的页面仍可能裁掉操作、丢失状态、影响未追踪的消费方，或者在没有渲染证据时被声称已通过视觉验收。

DeepSeek Harness 带有一套成熟的 UI 变更工作流和响应式交互规则。它们的机制可以迁移，但源文本点名 DSH token、客户端包、产品页面、平台 clearance 变量、设计师名单和强制 GUI GIF 策略。原样复制会给采用者另一个项目的视觉系统和评审策略。

## 决策

技能集合交付 `dsh-spec-web-ui-review`，作为项目级的浏览器 UI 变更评审技能。它拥有按影响分级检查、最低渲染检查、共享组件消费方追踪、响应式与输入状态覆盖、比较证据保存、结果报告，以及对未检查范围的如实交接。

采用者项目拥有视觉系统、组件 API、支持的浏览器、主题与宽度、本地化机制、审批策略和具体设计值。技能读取这些声明，不引入第二套 token 或样式目录。

用户可见的浏览器 UI 行为变更默认生成浏览器录制证据。技能陈述通用要求，不点名证据实现；依赖层加入具体录制技能后，可以提供带可用性条件的示例。项目可以声明等价证据形式。缺少渲染证据或录制能力时，技能显式交接，而不是声称完成视觉验收。

技能由一个 `SKILL.md` 和技能根的 `THIRD_PARTY_NOTICES` 组成。它不携带脚本，也不依赖兄弟技能。安装副本镜像已落地目录。

- 交付与语言：技能正文为英文，description 追加中文触发词。
- 默认值：检查真实渲染 UI；用户可见的浏览器 UI 行为变更在单一隔离运行中录制浏览器证据，除非项目提供等价形式或覆盖。
- 边界：技能不生成视觉身份，不维护样式或调色板目录，不替代通用 Web 指南审计，也不执行无关 UI 修改。

## 目标裁定

| # | 裁定 | 原因 | 可逆方式 |
|---|---|---|---|
| R1 | 目标是面向软件项目的项目级 Web UI 评审技能，而不是 DSH 客户端开发技能。 | 通用项目提供自己的设计系统、支持界面和评审策略。 | 恢复上游产品范围与固定系统。 |
| R2 | 项目声明拥有视觉与组件规则；项目留空时，技能拥有渲染证据工作流和必要检查。 | 工作流可以迁移，而另一个项目的 token、值、路径和审批不能。 | 将技能绑定到一个项目的设计系统。 |
| R3 | 对于用户可见的浏览器 UI 行为变更，默认使用浏览器录制证据。项目可以声明截图、视频或其他等价形式；一对截图记录两个状态，带标注的 fixture（测试前置数据）属于受控证据，不等同于组装后应用通过验收。缺少证据或能力时属于交接。 | 渲染行为不能仅凭 CSS、源码或单元测试确定，而采集与编码机制仍可替换。 | 移除默认值，或把证据缺失视为成功。 |
| R4 | 本技能负责提出证据要求、分析受影响范围并评审渲染结果。所选证据机制负责采集、编码、编码校验和发布；它不是评审流程的依赖项。 | 每个技能都独立安装，项目也可以提供另一套录制机制。 | 把一种媒体实现并入评审技能，或将其设为强制依赖。 |
| R5 | 技能保持纯文字。 | 检查、设计判断和消费方覆盖属于语义决定；没有项目无关命令能决定它们。 | 当新要求可机械决定时增加脚本。 |
| R6 | 外部设计生成系统和通用 UI 指南系统仍置于本技能之外。Taste Skill、UI UX Pro Max 和 frontend-design 可以为视觉设计提供参考，但都不负责本项目支持的消费方、状态、证据策略或渲染验收。 | 它们回答不同问题：视觉方向与通用规则合规不能替代项目级渲染验证。 | 把具体外部能力并入本技能。 |
| R7 | 检查是递归但有边界的：追踪受影响消费方，只检查变更可能影响的状态、主题、宽度和数据。 | 固定矩阵昂贵且不完整；共享变更只用一个孤立示例也不充分。 | 用通用全量清单或固定截图数量替代影响分级。 |

### 模型评估

位于 `tests/skill-evals/evidence/2026-11-20-pr114/` 的干净上下文评估针对三个场景运行了 candidate 与 no-skill profile。candidate 通过全部 12 项断言；baseline 通过 10 项。candidate 和 baseline 都识别出了消费方覆盖和缺少渲染器时的交接。在截图覆盖场景中，fixture 故意包含模拟焦点处理；candidate 未将其采纳为原生焦点的证据，并报告了这一缺口，而 baseline 把截图视为完整证据。

最终触发语料包含五个正例查询和五个近失查询。全部十个查询都符合预期触发结果，每条留存的 trace 都记录了已安装技能的 hash。

## 曾考虑的替代方案

**复制 DSH UI 技能并重命名路径。** 它会保留一套较大的评审流程，但其中的 token、产品页面、平台 clearance、审批名单和强制 GIF 策略仍是另一个项目的规则，只是换了名称。

**把浏览器 GIF 技能设为硬依赖。** 它会提供唯一证据路径，却阻止独立安装，也排除使用等价录制机制的项目。

**只交付通用 Web 指南清单。** 它覆盖常见无障碍与交互规则，却不能验证项目的组装页面、消费方、设计系统和目标状态。

**加入视觉风格生成器。** 它会增加设计方向，却把技能从变更验证变成产品身份创作，并与外部设计技能重复。

**要求固定宽度、主题和状态矩阵下的截图。** 它看似全面，但局部变更无法影响其中许多组合，而一个组装后的消费方仍可能漏掉共享组件的真实依赖。

**把 GIF 保持为事后可选项。** 它让评审更轻，却允许用户可见变更在没有持久演示的情况下声称完成。

## 后果

- 技能集合增加一个可独立安装的浏览器 UI 评审技能。
- 没有录制机制的项目获得显式证据交接；具备等价机制的项目仍受支持。
- 共享组件变更需要消费方证据，而不是一个代表性 fixture。
- 技能不增加 DSH token、组件路径、设计师名单、产品页面规则、脚本或硬兄弟依赖。
- 模型证据覆盖消费方发现、渲染证据复用、缺少能力时的交接、截图覆盖、模拟焦点未被采纳以及十个触发查询。其他产品上下文、视觉系统、采集机制和评审人不在该证据范围内。
- 回滚：回退落地提交；固定上游基线保持不变。
