# Agent Note: 锻造通用的性能调查技能

Status: implemented

[English](2026-11-24-forging-dsh-spec-performance-investigation.md) | 中文

## 问题

性能请求往往以“让它更快”开始，最终却止于局部微基准、未经测量的优化，或某个组件变快了，但用户操作并未改善。上游 `dsh-speed-up-perf` 技能有一套有力的调查流程，但它的示例、基准基础设施、产品路径、机器校准和固定预算大多属于 DeepSeek Harness，并不适用于一般软件项目。

## 决策

本包交付 `dsh-spec-performance-investigation`，它改编自 `dsh-v0.2.3-alpha.2`（`4b399c39a6d1479cd84ca591b4d7c88e24d38a96`）中的 `.agents/skills/dsh-speed-up-perf/SKILL.md`，读取日期为 2026-11-24。本技能把性能工作转化为一项生产环境中的用户操作、一份可比基线、一个已观察到的瓶颈、一项单一因果改动、一个端到端结果、行为与资源证据、一个负控制，以及一份边界明确的报告。

该技能只有一份 `SKILL.md` 和技能根目录下的通知文件。它不包含脚本、参考文件、包或运行时依赖。软件变更与质量组将它作为独立技能安装，不依赖 `dsh-spec-ci-test-reliability`、`dsh-spec-pre-push-checks` 和 `dsh-spec-code-review`；这三个技能分别继续负责测试套件的偶发失败与耗时、选择待推送的检查，以及对照项目规则评审实现。

### 意图与边界

| 设置 | 值 |
|---|---|
| 名称 | `dsh-spec-performance-investigation` |
| 目标 | 在生产路径上取得经过测量的性能结果，定位其开销，并交付保持行为的优化或有依据的诊断 |
| 边界 | 不是基准平台、通用阈值、测试可靠性工作流、通用代码评审、视觉设计流程或容量模型，也不保证局部组件的性能提升会改变用户路径 |
| 交付物 | `skills/dsh-spec-performance-investigation/SKILL.md` 与 `THIRD_PARTY_NOTICES`、安装副本、开发评估语料与证据、本记录及其中文对侧文件 |
| 受众与领域 | 在软件项目中处理后端、浏览器、CLI 或端到端运行时路径的 agent |
| 运行时与工具 | 不交付运行时依赖；采用方的生产入口和测量设施决定可用的工具 |
| 交付语言 | 英文，并在 description 末尾附加中文触发语言 |

### 来源约束

| 单元 | 上游位置 | 约束 |
|---|---|---|
| S1 | Description | 在以下场景触发：性能调查与优化、真实基准或门禁、响应性剖析，以及经过测量且保持行为的修复 |
| S2 | Opening | 把宽泛的提速请求转化为可复现的用户路径测量；将这项工作视为指导，而不是配额 |
| S3 | Establish scope and current authority | 确定用户可见的终点、工作负载、约束、允许的细微差异和停止规则，并确切说明当前权威来源 |
| S4 | Survey user paths, then rank candidates | 调查真实操作，并按用户延迟、CPU 与分配开销、内存、出现频率和置信度对经过测量的候选排序 |
| S5 | Build realistic synthetic benchmarks first | 使用生产入口、固定且贴近现实的工作负载、可比的时钟与状态、原始样本、行为检查，以及项目自有的测量设施 |
| S5a | Build realistic synthetic benchmarks first | 获准检查本地语料或遥测时，只提取聚合 workload 特征，绝不把 prompt、输出、路径、身份、凭据、录制或可识别片段写入 fixture、日志或产物 |
| S6 | Prove the regression, then remove work | 捕获基线证据、比较可证伪的原因、选择最大的安全确认收益、一次只改变一个因果因素、重新运行父路径，并要求提供负控制 |
| S7 | Preserve behavior and resource ownership | 在改变性能时保持输出、顺序、持久性、取消、并发、保留与释放不变 |
| S8 | Deliver a bounded, reviewable result | 报告工作负载、改动前后值、终点语义、行为证据、负控制、检查和排除项；对证据薄弱的结果不予采纳或列入后续跟进 |
| S9 | DSH product and benchmark specifics | Session、transport、Web、仓库基准路径、Node／浏览器 harness、机器校准、固定预算和 CI 通道都属于来源项目专有内容 |

### 裁定

- **技能不附带基础设施。** 性能工作流因语言、剖析器和运行时而异；打包基准会缩小受众范围。技能要求提供生产路径和可比测量，而不要求引入新框架。
- **默认先测量，再改动。** 项目未声明采样策略时，默认每侧执行一次预热、采集至少五份测量样本，并尽可能交错进行。噪声较大或针对尾部的任务需要更多样本。
- **不存在通用的性能阈值。** 没有项目预算时，结果报告绝对值及其比值；若请求设置门禁，必须根据测得的工作负载与噪声推导。
- **测试可靠性的边界由语义划定。** 用户路径的延迟、吞吐、响应性和保留内存属于本技能。测试执行缓慢、不稳定或发生资源争用时，仍由 `dsh-spec-ci-test-reliability` 负责。
- **私有语料内容不进入证据。** 获准检查只产出聚合维度；原始 prompt、输出、路径、身份、凭据、录制和可识别片段不得进入 fixture、日志、截图、Pull Request 或产物。
- **技能名称反映工作流。** 技能并不是以上游 DSH 产品或某个固定基准机制命名的，并且支持诊断，但不授权实施优化。
- **该技能提供一致性，不保证每次都能得到更好的优化。** 一个 no-skill 后端基线也已经完成测量、优化并保持输出不变。额外价值在于强制执行候选比较、负控制、浏览器与端到端边界，以及能力缺失时的交接，避免有能力的模型在复杂工作中跳过其中一项。

### 风险与回退

- 如果模型评估显示，本技能在测量、边界和负控制决策上并不优于 no-skill baseline，它就可能沦为泛泛的“先剖析、再优化”建议。若出现这种情况，不得发布。
- 后端 no-skill 基线已经解决了该 fixture。技能证据支持一致的调查方法与能力边界，不声称它在所有任务上都比任何有能力的模型找到更好的优化。
- 五次样本的默认值对某些尾部或高噪声工作负载而言过小。技能要求按需增加样本，绝不把最低样本数视为统计确定性。
- 所附证据证明了具有代表性的后端、浏览器、端到端行为和缺少能力时的行为，但并未证明所有运行时或剖析器。
- 回退方式是删除技能目录、安装副本、通知文件、评估语料、文档表格行，以及本记录所在单元。

## 曾考虑的替代方案

**几乎逐字照搬 `dsh-speed-up-perf`。** 它落选，因为 DSH 的 Session、transport、Web、基准路径、校准和固定预算会变成对其他项目并不成立的要求。

**随技能交付基准脚本和通用计时 schema。** 它落选，因为有用的基准必须使用采用方真实的生产入口和工作负载；与语言无关的脚本要么固化一条玩具式路径，要么膨胀为一个平台，而本技能明确避开这样的平台。

**将性能调查并入测试可靠性。** 它落选，因为套件耗时和偶发失败涉及测试执行拓扑，而用户路径的延迟、吞吐和响应性需要生产环境测量和保持行为的优化。

**为后端、浏览器和端到端模式分别增加参考文件。** 它落选，因为该技能足够简短，只需一个入口，而共享的测量约定比三套彼此割裂的实操手册更重要。

## 后果

- 软件变更与质量组包含的技能从五个增加到六个，而每个技能仍可独立安装。
- 即使项目没有基准框架，也会得到一条具体的采样、剖析、负控制和报告路径。
- 本技能有意不提供固定阈值、剖析器封装、基准 harness 或通用优化清单。
- 评审人必须判断所测量场景是否真正代表所指定的用户操作；技能会让这一范围及排除项清晰可见。
- 只处理简单性能案例的项目可能看不到超过模型默认表现的收益；它更强的价值在跨层、受能力约束或对证据敏感的工作中。
