# Agent Note: 将性能工作重构为 dsh-spec-speed-up-perf

Status: implemented

[English](2026-11-25-reforge-performance-as-dsh-speed-up-perf.md) | 中文

## 问题

先前的 `dsh-spec-performance-investigation` 技能保留了主要测量顺序，却压缩了若干职责，而这些职责是否彼此区分会改变结果：benchmark、门禁、剖析与证据的边界；由项目选择的工具；测量语义；标识与隐私约束；环境依赖；冷启动与进程内存处理；允许的行为差异；以及明确的证据限制。该名称还丢掉了上游语义词干，削弱了来源可辨识性。

## 决策

本包交付 `dsh-spec-speed-up-perf`，它是 DeepSeek Harness `dsh-v0.2.3-alpha.2`（`4b399c39a6d1479cd84ca591b4d7c88e24d38a96`）中 `.agents/skills/dsh-speed-up-perf/SKILL.md` 的通用化移植，读取于 2026-11-26。它取代并整合了先前的性能调查记录，并应用[单来源移植保留上游语义词干](../../proposed/architecture/2026-11-25-single-source-ports-retain-upstream-semantic-stem.zh.md)。原技能的源目录及其安装副本均已移除，且未保留别名。

跟踪：#166（父 issue #135）。Pull request：#179。

### 设置

| 设置 | 值 |
|---|---|
| 名称 | `dsh-spec-speed-up-perf` |
| 目标 | 取得经过测量的生产路径性能结果，定位其开销，并交付保持行为的优化或有依据的诊断 |
| 边界 | 不是 benchmark 平台、通用阈值、测试可靠性工作流、通用代码评审、视觉设计流程、容量模型，也不保证局部收益会改变用户路径 |
| 交付物 | `skills/dsh-spec-speed-up-perf/SKILL.md` 与 `THIRD_PARTY_NOTICES`、其安装副本、开发评估语料与证据、本记录及其中文对侧文件 |
| 受众与领域 | 在具有后端、浏览器、CLI（命令行界面）或端到端运行时路径的软件项目中工作的 agent |
| 运行时与工具 | 不随附运行时依赖；采用方的生产入口和测量设施决定可用工具 |
| 交付语言 | 英文，并在 description 末尾附加中文触发语言 |

### 裁定

- **保留语义词干。** 该直接通用化移植命名为 `dsh-spec-speed-up-perf`，既不是按意图命名的替代项，也不是别名。
- **测量决策保持彼此独立。** benchmark 提供可比样本，门禁应用项目自有的规则，剖析结果归因开销，证据记录决策及其限制。任何一项都不能替代另一项。
- **工具属于项目和环境。** 缺少浏览器、剖析器或测量设施时会执行交接；该技能不会下载、安装或假定存在替代品。
- **不存在通用阈值。** 项目没有预算时，报告绝对值和比值。项目已声明门禁时，保留其来源值，并根据重复工作负载的噪声推导任何新门禁。
- **采样默认值仅在策略未作规定时适用。** 兜底做法是每侧预热一次，并采集至少五份测量样本；尾部或高噪声工作需要更多样本。
- **冷启动与内存具有不同语义。** 冷运行使用全新进程；可达的保留状态不同于临时分配、分配器高水位行为和峰值压力。
- **稳定标识与顺序在收窄投递范围后仍然保持。** 按行限定或等价的订阅只有在保持标识不变、集合顺序不变、更新顺序不变以及初始事件即时送达的情况下，才能减少失效。
- **可见差异需要授权，并需要负责该行为的证据。** 性能工作不会隐含地允许更改输出、日志、传输格式或生命周期。
- **该技能不附带基础设施。** 性能工作流因语言、剖析器和运行时而异；随附的 benchmark 会固化一条玩具式路径，或成为该技能排除的平台。
- **测试可靠性边界由语义划定。** 用户路径的延迟、吞吐、响应性和保留内存属于这里。缓慢、不稳定或资源争用的测试执行仍归测试可靠性负责。
- **证据类型始终带标注。** 历史主张、新的本地测量、生产遥测、项目门禁结果和 CI 证据不可互换。

### 能力结论

浏览器能力存在与能力缺失两个分支都有当前模型证据。能力存在路径使用仓库之外的临时 Chrome for Testing 安装；能力缺失路径屏蔽了浏览器访问。技能本身不会安装任一侧的能力。

委派是可选执行路径。具备隔离执行能力时，只要广度值得，就可以委派独立测量领域。不具备时，必需的结果仍可在主上下文中完整产出；缺少隔离不是交接条件。当前行为运行禁用了 subagent，因此执行的是能力缺失路径，并且不主张委派扇出证据。未来一项范围较广的多领域任务，是能力存在路径可继续推进的证据路径。

### 风险与回退

- 如果后续运行未能保留 benchmark、门禁、剖析和证据之间的区分，通用正文就可能退化成泛泛的“优化前先剖析”建议。
- 无技能基线已经解决了小型后端 fixture，因此已确立的价值是一致证据纪律和能力边界，而不是更好的基础优化。
- 五份样本的默认值对某些尾部或高噪声工作负载而言过小；该技能要求增加样本，绝不把最低样本数视为统计确定性。
- 浏览器计时取决于所提供的 Chrome 构建和宿主渲染路径；当前 headless 软件渲染证据不能证明所有 GPU 或合成器路径。
- 回退方式是恢复先前的技能目录和安装副本，移除新的评估／证据身份，并恢复先前的记录。无论是否回退，历史证据仍是历史。

## 曾考虑的替代方案

**几乎逐字复制上游技能。** 它保留每项上游职责，却把 DSH 路径、预算、校准和产品工作流带入无关项目。

**保留先前的通用正文，只重命名。** 它解决了可发现性问题，却让促使本次重构的测量与证据边界保持不变。

**没有职责映射就移除 DSH 基础设施。** 它避免生态系统专属假设，却可能悄悄丢掉每个 benchmark、门禁、剖析或证据步骤存在的原因。

**交付 benchmark 脚本和通用计时 schema。** 它落选，因为有用的 benchmark 必须使用采用方的真实入口与工作负载；与语言无关的脚本会固化一条玩具式路径，或膨胀成该技能明确避免的平台。

**把性能工作并入测试可靠性。** 它落选，因为套件耗时和不稳定涉及测试执行拓扑，而用户路径的延迟、吞吐和响应性需要生产环境测量。

**为后端、浏览器和端到端模式分别增加 reference。** 它落选，因为该技能短到只需一个入口，共享的测量、控制和证据约定比三套互不相连的实操手册更重要。
