# Agent Note: 写笔记的触发条件跟着 dsh 收窄

Status: implemented

[English](2026-09-21-the-note-trigger-follows-dsh.md) | 中文

## 问题

本技能集合交付的约定此前写的是:**每个非平凡变更**都必须新增或更新一份 Agent Note,而"非平凡"是一张清单——行为、架构、跨文件共享的约定、流程或工具、测试策略、磁盘/线缆/配置格式,或任何维护者可能重新审视的决定。

dsh 在 `dsh-v0.1.6-alpha.2`(移植这份文本时所依据的发布)里把它收窄了:笔记只写给**代码、测试与现有文档都解释不了的、具有长期价值的决策理由**,机械性或局部编辑豁免。它根 `AGENTS.md` 里那条常设指令随之改动——它之前的文本要求每个非平凡变更都带笔记——而机制代码、笔记说明文件与搜索排除都没有动。

## 决策

收窄后的文本由笔记技能承载：它的约定就是每个采用项目加载的那一份，于是 agent 写决策记录时遇到的触发句子，与约束它的约定，说的是同一件事。

注入的那一小节里有一句是本技能集合自己的:**在对话里达成的决定也算数**,约定里也带着它。其余部分与 pin 一致。

## 曾考虑的替代方案

**保留宽触发条件,记成一次偏离。** 会有更多决定被写下来,本仓库自己的历史也证明这个习惯抓得住东西。它落选,是因为触发条件属于笔记机制本身:一套交付的触发条件与 dsh 的不同,世界上就同时存在两份同名约定。

**等一个稳定版再跟。** 基线会动得更少。它落选的理由与当初定基线的理由相同:笔记机制有自己的节奏,而改动了它的 alpha 恰恰是最值得跟的那个发布。

## 后果

- 每个项目的笔记约定都等于我们所钉修订上 dsh 的约定；约定随笔记技能交付，因此只需让一份副本保持同步。
- 收窄后的约定管的是「这份笔记该为什么而写」；笔记技能的描述要求 agent 在非平凡变更之前，先判断这次变更是否需要一份持久记录，而机械性或局部编辑豁免。
- 约定是陈述触发条件的唯一表面；没有任何常设指令重述它，因此读者遇到的是收窄后的规则，而不是第二句更宽的话。
- 验证:`pnpm test` 与 `node scripts/verify-corpus.ts --base-ref=HEAD` 通过;约定的"何时需要写一份"一节与 `submodules/dsh/.agents/notes/README.md` 携带同一条规则,只是把它的 `same PR` 换成了我们的 `same change`;向空项目 `install` 注入的常设指令与本次改动之前完全相同。
