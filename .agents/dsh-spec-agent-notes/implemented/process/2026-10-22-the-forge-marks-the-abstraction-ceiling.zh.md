# Agent Note: 锻造技能标记了技能的抽象上限

Status: implemented

[English](2026-10-22-the-forge-marks-the-abstraction-ceiling.md) | 中文

## Problem

两个抽象元技能被锻造——一个对象分析技能和一个自适应工作流技能——在干净室里离线与联网测试，随后被维护者否决。它们的执行是称职的；它们的收敛不是。干净室显示：开放的对象范围导致临时裁定的要素粒度；没有外部规范可查时，标准镜像对象自身的断言；测试实例只被检查、没有被执行。否决给下一次提案留下一个问题：抽象上限在哪里，什么理由才足以跨过它。

## Decision

锻造技能 `dsh-spec-skill-forge` 就在上限上。它的抽象可以成立，因为它服务的领域闭合了三个锚点：

- 对象闭合：Agent Skill 有外部固定的形态——`SKILL.md` 入口、frontmatter、references 与 scripts、负责触发的 description。
- 产物闭合：技能目录加一份记录，字段、语言与落地位置都是固定的。
- 标准有锚：Agent Skills 规范、`verify-skill-spec.mjs`、token 预算、正向/负向/验证三类锚点与四式处置。多数检查是机械的，其余可以直接判断。

比锻造技能更抽象的技能，必然丢掉至少一个锚点：开放的对象 schema、自由形态的产物，或只指向对象自身断言的判据。锚点一丢，可接受输出的空间就超过提示能约束的量，收敛无论措辞或模型规模都会失败。

因此不再尝试比锻造技能更抽象的技能。泛化向下，不向上：每个域实例化一个锻造式技能，带着该域闭合的对象、产物与标准。两个被否决的三件套保持为否决记录，不作为实验保留。

### 上限检验

一个技能只有在三个锚点同时成立时，才可以声称超出具体任务的抽象：

| 锚点 | 检验 |
|---|---|
| 对象闭合 | 实例由技能不发明的外部 schema 或规范界定 |
| 产物闭合 | 交付物有固定字段与可检查的形状 |
| 标准有锚 | 检查是机械的或直接有证据的，而不只是技能或对象自身的断言 |

一条不成立，方法就是具体任务的辅助物。两条不成立，它就是散文。

### 一般模型

这个决定依赖一条规律：收敛需要闭合的外部锚点。方法留下一个未闭合的锚点，就多出一片解释空间，任何措辞都收不窄它。三个天花板由这条规律推出：

| 天花板 | 为什么成立 |
|---|---|
| 通用情境下的无人值守 | 无人值守要求边界与验收事先闭合。通用情境会产生锚点无法预先覆盖的情况，只能由人来设定或修补。 |
| 极大提速 | 偶然复杂度可以压缩，本质复杂度不能。生成变便宜之后，锚定与验收成为瓶颈，总时间因此保留下限。 |
| 不理解也能断言 | 判定“对”需要理解对象。没有理解就只剩“像对”，没有可信的判对者，循环闭不上。 |

地板是本质复杂度加上人的理解与责任。天花板可以上移；地板不动。

### 天花板上移的两种方式

两条路径记录在 `docs/breaking-the-ceiling.md` 及其配图里。它们是解释，不是今天要提出的新技能。

- 公共收敛契约：无数人把各自领域的对象、产物、验收、失败处理、来源与组合接口写成结构化、可执行、开放的知识，让锚点成为公共基础设施。
- AI 在开放空间收敛：用“提出—执行—验证—修正”的闭环，加上内生锚点、不确定性校准与独立验证，而不是更长的提示。

两条路互相抬高：公共知识给 AI 锚点，AI 帮人类维护契约。两者都只是渐近地放宽可接受的抽象，都不能消掉地板。

### 重新引入的条件

高于锻造技能的提案，只有在点名了补上缺失那一角的形式化锚点时才会被重新考虑：机器可检查的对象 schema、带校验器的产物 schema，或带通过/失败协议的标注语料。更强的模型或更好的提示不算。

## Alternatives considered

**把锻造技能再向上泛化一层。** 它落败，因为下一层会打开对象或产物；两个被否决的技能就是那次尝试。

**把两个技能保留为实验技能。** 它们落败，因为缺少形式化锚点时它们的输出无法检查；保留它们会让人把它们当作已经收敛的技能使用。

**依赖更大的模型或更强的提示。** 它落败，因为限制来自可接受输出的空间，而不是模型能力；更清楚的措辞不会增加锚点。

**为被否决的技能写一个形式化检查器。** 它落败，因为没有对象或产物 schema 可作为检查依据，为场合临时发明一个，本身就又成了没有锚点的抽象。真实的 schema 才是重新引入的路径。

**只把结论留在否决记录里。** 它落败，因为那些记录是两个判决，而不是解释判决的上限规则；第三个提案会把它们读成意外。

**把上限只写成散文，不写 Agent Note。** 它落败，因为未来的会话会重新争论这个问题；否定性保证需要一份常驻记录。

**现在就把两条抬升路径做成新技能。** 它们落败，因为今天还没有所需的形式化锚点。把它们写下来是在解释天花板，不是在提出技能。

## Consequences

- 一条否定性保证成立：未来会话不再提出高于锻造技能的技能，除非上限检验带着点名的形式化锚点通过。
- 泛化按域进行。每个域得到一个锻造式技能，带自己闭合的对象、产物与标准，而不是一个横跨所有域的技能。
- 对没有 schema 的工作，具体提示仍是默认。上限检验与一般模型陈述的是理由，不是偏好。
- 两个被否决的三件套留在 `rejected/`，作为这条否定性保证的证据，它们的 Status 行承载判决。
- 推理的范围超出技能。`docs/breaking-the-ceiling.md`、`docs/abstraction-ceiling.svg` 与 `docs/breaking-the-ceiling.svg` 为人类读者记录三个天花板、地板与两条抬升路径。
- 仓库因此带有一条常驻规则，新技能被提出时会被读到；这是防止同类提案的代价。
