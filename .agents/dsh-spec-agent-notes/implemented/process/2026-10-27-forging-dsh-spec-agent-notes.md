# Agent Note: Forging dsh-spec-agent-notes from the upstream notes mechanism

Status: implemented

English | [中文](2026-10-27-forging-dsh-spec-agent-notes.zh.md)

## Problem

The skill set has no skill that owns the Agent Notes lifecycle. An adopting project can keep decisions in conversation or in ad-hoc documents, but it has no agent-facing contract for where a decision record lives, when to write one, what it must contain, how it moves between lifecycles, when to consolidate or delete it, and how a finished record is frozen so later sessions can trust it. Upstream `dsh` carries exactly that mechanism — a notes contract plus an archival workflow — but it is written into that repository's own conventions: its paths, its bilingual triplet, its gate commands, its seal exceptions. Copying it verbatim would carry another project's policy; leaving it out would drop a mechanism the pattern names.

## Decision

The skill `dsh-spec-agent-notes` is forged from the upstream notes contract and archive workflow, adapted to the general agent-usage domain and to readers who expect decisions to persist across sessions. The skill is a directory with:

- `SKILL.md` — the procedure an agent loads: supersession check, lifecycle and class placement, the uniform format, pruning and consolidation, the archive procedure, the checks, and the stop-and-hand over rules.
- `references/notes-contract.md` — the active-tree contract: layout, classification, when to write, file format, lifecycle moves, companions, pruning.
- `references/archive-contract.md` — the frozen archive: what enters, the unit, the archival change, the manifest, the frozen guarantee, sealing and verification, handover.
- `scripts/notes.mjs` — the adapted mechanical gate: `init` for the one-time tree skeleton, `check` for the active tree, and `archive`/`archive --write` for the frozen archive.
- `THIRD_PARTY_NOTICES` — the provenance declaration for the skill text and bundled gate adapted from upstream; the frontmatter `license` field names it.
- `package/dsh-spec-agent-notes/` — the TypeScript source of the gate with its `vite.config.ts` and `build.ts`; the bundled output is `scripts/notes.mjs`.
- `tests/agent-notes.test.ts` — the gate's tests, maintained in this repository and not shipped with the skill.

Default notes root: `.agents/dsh-spec-agent-notes/` directly under the project root, overridable with `--root` and named by an adopter's declaration; the archive root is always `<notes root>/archived`. Per [the 2026-10-28 forging record](2026-10-28-forging-dsh-spec-agent-experience.md), the provenance declaration is the skill-root `THIRD_PARTY_NOTICES` notice plus the frontmatter `license` field, and the skill-spec gate reports 15 checks including that field.

- Delivery language is English; the review language is Chinese, and additional Chinese trigger language is appended to the description because the review language differs from delivery.
- Runtime: Node.js 22.19+ or 24+; every command runs inside a Git checkout and there is no non-Git mode (R11).
- The description carries the trigger — use the skill before a non-trivial change to decide whether the change needs a durable record, plus the lifecycle actions; the body owns the write scope and the mechanical/local exemptions (R29).
- Cross-skill guidance: the `## Companions` section names the `dsh-spec-translate-docs` skill only as an availability-qualified example; the project's pairing gate remains the binding mechanism.

## Source and revision

Upstream source: `deepseek-ai/deepseek-harness`, tag `dsh-v0.2.1-rc.3`, commit `1f81c047fc48fa190a683e469daa699857e9afe8` — the latest release tag at the read date (2026-10-27). The `submodules/dsh` pin at that date was `687f282e8625c6b8d11ff58211a90524be2e4317` (`dsh-v0.2.1-rc.2`); it was neither fetched nor edited. The named recipe files — the notes contract, archive instructions, archive skill and the note gate scripts — are byte-identical between the pin and the latest tag, so the recipe did not move between the two revisions; the tag also carries unrelated non-notes script changes, which are not source for this skill. The latest tag is the source because the request names the newest upstream version.

Read as source from the upstream tree (the pinned `submodules/dsh` and tag `dsh-v0.2.1-rc.3`; the paths below are upstream paths, not this repository's installed copies):

- `.agents/notes/README.md` — the notes contract.
- `.agents/notes/AGENTS.md`, `.agents/notes/implemented/AGENTS.md`, `.agents/notes/archived/AGENTS.md` — the lifecycle, supersession and archive instructions.
- `.agents/skills/dsh-archive-agent-notes/SKILL.md` — the archival workflow.
- `.agents/notes/archived/manifest.json` — the manifest shape.
- `scripts/agent-note-tree.ts`, `scripts/verify-agent-note-format.ts`, `scripts/verify-agent-note-classification.ts`, `scripts/archived-agent-notes.ts`, `scripts/verify-archived-agent-notes.ts` — the structural, format and archive gates.

Not read as source: the repository's own notes-related skills and its earlier archive port (the `dsh-archive-agent-notes` skill and the `dsh-spec-manager` scripts, both removed), and any earlier forging or decision record. The adopter's notes mechanism supplies only the decision-record format for this note — a workspace instruction for where the record lives, not a design source.

## Constraint dispositions

Dispositions use the forge skill's values: **Keep** carries the original wording and sense with language and layout adjustments; **Adapt** instantiates a target value; **Re-bind** abstracts a vanished referent to its purpose and finds the target's equivalent; **Dissolve** records that the referent is gone and what check takes over. Target homes: `SK` = `SKILL.md`, `NC` = `references/notes-contract.md`, `AC` = `references/archive-contract.md`, `gate` = `scripts/notes.mjs`, `test` = `tests/agent-notes.test.ts`.

## Alternatives considered

**Carry the source's Chinese/English/sidecar triplet verbatim.** It lost because the target's audience is the general agent-usage domain, where a project's translation and consistency policy is its own; a verbatim triplet would impose the source repository's bilingual convention and make the archive gate depend on a sidecar format the skill does not own. The companion suffix is the equivalent means: the unit and its completeness stay mechanical, and consistency is delegated.

**Carry the fixed format-adoption date and the legacy markers.** They lost because they name source-corpus history. A general adopter has its own adoption date, so the date becomes an input and markers that never existed in the target are dropped; without the flag, a fresh adoption has no escape hatch.

**Carry the three Figma seal exceptions.** They lost because they authorize a one-off change to one source artifact; carrying them would invent target policy. The target grants no exceptions and treats a needed seal change as a handover.

**Carry a stricter freeze gate with Git-history forensics (merge-only deletions, grafts, replace refs, shallow detection, per-commit blob proofs).** It lost because the source mechanism defines the guarantee as an append-only manifest against a trusted baseline, and the trust for rewritten history belongs to the project's CI and protected branches. Adding history forensics would extend a mechanism that does not exist upstream, enlarge the gate beyond what the skill's audience needs, and make the skill brittle for adopters with ordinary Git workflows.

**Ship prose only and delegate every mechanical check.** It lost because the mechanical checks are part of the upstream mechanism and the archive freeze is evidence only if it is sealed and verified; a self-contained skill for general adopters cannot assume a project already has an equivalent gate.

**Keep the repository's installed notes skill as the design source.** It lost because the request excludes the repository's notes-related skills and their design, and the upstream revision is the named source.

**Use the pinned `dsh-v0.2.1-rc.2` submodule instead of the latest tag.** It lost because the request names the newest upstream version; the contract is byte-identical between the pin and the tag, so no recipe difference is introduced.

**Drop the semantic workflow and keep only the gate.** It lost because the mechanism's value is the decision practice — when a note is warranted, what beats another, when to prune or archive — and the gate exists to keep that practice honest, not to replace it.

**Keep the filename calendar validation and the class-directory strictness.** They lost because the source's walker checks the filename shape only and ignores directories without Markdown; both are ruled out (R21) rather than recorded as target extensions.

**Enforce companion completeness in the active tree.** It lost because a project may translate selectively; the archive unit is where completeness must hold, and the active tree stays permissive (R2).

**Carry the adopter's notes prose.** It lost because the request excludes that tree as a source; the skill prose is re-derived from the upstream files, and this record states its provenance rather than claiming a clean one.

**Read the archive baseline from an external notes root's own repository.** It lost because the target's baseline is the project's own Git history and no second trust boundary was specified; the root must stay inside the project, and a project that keeps its notes elsewhere hands over (R22).

**Accept a symlinked root or archive directory that resolves elsewhere.** It lost because the manifest would then have no trusted baseline and `--write` would have an effect outside the project; canonical containment is the cheap implementation of R22, and the regression tests pin it.

**Reject every symlinked archive root.** It lost because an inside-project symlink is an ordinary layout, and the failure was the lexical baseline path, not the symlink; reading the baseline at the resolved path inside the same repository keeps the layout while restoring the guarantee (R22). Repository identity is the absolute Git directory plus the worktree toplevel, so a worktree view that merely shares the project's Git directory is rejected.

**Support nested companion records.** It lost because the upstream triplet is flat and nesting would invent a unit model the source does not define; the gate rejects a companion as a unit source and a nested record is a project divergence (R25).

**Keep a repository-identity layer that enumerates Git layouts.** It lost because enumerating registered worktrees, gitfile views, per-worktree `core.worktree` and parent and sibling checkout entries grows without bound; anchoring the notes path to the current checkout plus the tracked-manifest check keeps the baseline in the same tree with far less mechanism (R22, R27).

**Keep upstream's replay of triplet completeness on every verification.** It lost because the declared suffix set is a target addition that may grow over time; replaying the current set over frozen history would make a later translation impossible without editing sealed units. Completeness is enforced at seal time and verification compares the manifest (R2, R23).

**Generate a notes-tree `AGENTS.md` template in `init`.** It lost because the skill's description and body already carry the trigger and rules; a generated policy file would duplicate them, drift, and be overwritten on updates, contrary to the repository's create-vs-update norm.

**Keep the gate's tests inside the shipped skill.** It lost because the repository owns its test suite and a skill should ship its gate, not its harness (R12); the tests stay under `tests/` and exercise the work-directory or landed script.

**Keep the candidate as first designed.** It lost because a simpler mechanism fits the target: a Git prerequisite, a skill-named root, declarative companions with manifest-only verification, an initialized skeleton, unchanged classes and repository-native packaging.

## Consequences

- The skill ships from `skills/dsh-spec-agent-notes/` with an installed copy under `.agents/skills/`; the directory carries the skill, the two reference contracts and the bundled gate, not a work directory and not Chinese review pairs.
- The repository's decision records and their Chinese companions live in `.agents/dsh-spec-agent-notes/`; the earlier notes mechanism and the `dsh-archive-agent-notes` installation are gone.
- The notes corpus keeps its existing bodies and companions; this record lives in `implemented/process`.
- The submodule baseline is pinned at `dsh-v0.2.2-rc.1` (`66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`).
- The notes-specific `dsh-spec-manager` modules are gone; no current code consumes them.
- The description asks an agent to use the skill before a non-trivial change; the body carries the write scope and the mechanical/local exemptions, so loading the skill is part of deciding whether a record is needed.
- **The gate's scope stays deliberately thin.** The gate does not enumerate Git layouts: it keeps canonical containment, the same-Git-directory anchoring and the tracked-manifest check (R22, R27), and the contracts state the residual local-layout trust boundary (R28); a request for a new layout check is answered from this record, not by growing the gate.
- **Archive semantics deviate from the upstream verifier.** Companion completeness and archive metadata are enforced only when sealing a new unit (R2, R23), `archived/AGENTS.md` is optional and ignored (R6), and a non-empty manifest must be tracked by Git (R27). A hand-added manifest entry that gives a sealed unit a new artifact passes manifest-only verification; the seal command and the project's review and CI are the enforcement point (R28).
- **The tracked-manifest check does not prove the working tree is the committed tree.** It proves the manifest is in the project's Git index; a local actor who can stage a manifest at the correct path is inside the trust model, which delegates history to CI and protected branches (R28). A force-pushed rewrite that also rewrites the manifest is undetectable without an external trusted `--base-ref` (R11, R28).
- **Classification relies on model semantics.** The upstream six classes are software-flavoured, so a general-domain agent must map its own decisions onto them; the mapping is an assumption (R18), and the adopter's own corpus is the evidence.
- **Git is a hard prerequisite.** A project without Git cannot use any command; the compatibility line states the install/init requirement, and the narrowed adopter set is intended (R11).
- **The archive half is a partial mechanism for some adopters.** The active lifecycle works in any decision domain; sealing a unit additionally requires Git and the unit's complete declared companion set (R2).
- **The corpus compatibility result is a recorded run, not an automated test.** A later source revision could invalidate a format assumption, so the corpus checks are re-run against the pinned submodule before a gate change.
- **A bundled script and its test suite are maintenance cost.** The script mirrors a small, named gate surface, the identity invariants are few, and the tests live in the repository's suite rather than in the shipped skill.
