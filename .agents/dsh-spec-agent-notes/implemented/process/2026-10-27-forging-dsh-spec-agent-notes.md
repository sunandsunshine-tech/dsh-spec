# Agent Note: Forging dsh-spec-agent-notes from the upstream notes mechanism

Status: implemented

English | [中文](2026-10-27-forging-dsh-spec-agent-notes.zh.md)

## Problem

The skill set has no skill that owns the Agent Notes lifecycle. An adopting project can keep decisions in conversation or in ad-hoc documents, but it has no agent-facing contract for where a decision record lives, when to write one, what it must contain, how it moves between lifecycles, when to consolidate or delete it, and how a finished record is frozen so later sessions can trust it. Upstream `dsh` carries exactly that mechanism — a notes contract plus an archival workflow — but it is written into that repository's own conventions: its paths, its bilingual triplet, its gate commands, its seal exceptions. Copying it verbatim would carry another project's policy; leaving it out would drop a mechanism the pattern names.

## Decision

The skill `dsh-spec-agent-notes` was forged from the upstream notes contract and archive workflow, adapted to the general agent-usage domain and to readers who expect decisions to persist across sessions, and landed. The landed skill is a directory with:

- `SKILL.md` — the procedure an agent loads: supersession check, lifecycle and class placement, the uniform format, pruning and consolidation, the archive procedure, the checks, and the stop-and-hand over rules.
- `references/notes-contract.md` — the active-tree contract: layout, classification, when to write, file format, lifecycle moves, companions, pruning.
- `references/archive-contract.md` — the frozen archive: what enters, the unit, the archival change, the manifest, the frozen guarantee, sealing and verification, handover.
- `scripts/notes.mjs` — the adapted mechanical gate: `init` for the one-time tree skeleton, `check` for the active tree, and `archive`/`archive --write` for the frozen archive.
- `package/dsh-spec-agent-notes/` — the TypeScript source of the gate with its `vite.config.ts` and `build.ts`; the bundled output is `scripts/notes.mjs`.
- `tests/agent-notes.test.ts` — the gate's tests, maintained in this repository and not shipped with the skill.

Default notes root: `.agents/dsh-spec-agent-notes/` directly under the project root, overridable with `--root` and named by an adopter's declaration; the archive root is always `<notes root>/archived`. After the first stop the human simplified the design — Git as a prerequisite, the skill-named root, seal-time companion completeness with a manifest-only verification, an `init` command, a thin checkout-anchored identity check, the upstream classes unchanged, and a TypeScript packaged script with repository tests. The redesign is recorded in § Redesign after the first stop; at landing the work directory was published into `skills/`, the installed copies were refreshed, and the repository's notes moved to the new default root.

## Redesign after the first stop

After the pre-redesign candidate reached human review, the human reviewed the design and asked for a simplification. These are the directions the rest of the record follows:

- **Git is a prerequisite.** Every command runs inside a Git checkout; a project without Git is told to install Git and initialize/commit, not handed a weaker archive mode (R11).
- **One root, with the archive inside it.** The default notes root is `.agents/dsh-spec-agent-notes/` directly under the project checkout root; `--root` may name another directory inside the project; the archive root is always `<notes root>/archived` (R1).
- **Pairing is declarative and seal-time.** `--companion` declares any set of suffixes and languages; the active tree stays selective; the archive enforces completeness only when sealing a new unit, and verification compares the manifest instead of replaying the current declaration over history (R2, R23).
- **The archive keeps the upstream skeleton.** Six class directories are required, `init` creates them with ignored `.gitkeep` placeholders in empty class folders, and `manifest.json` is required; `archived/AGENTS.md` is not required because the skill owns the rules, while an optional file of that name is permitted and ignored (R5, R6, R20).
- **Identity follows the logical checkout, not Git mechanisms.** The notes path is anchored to the current checkout root; the gate keeps containment and same-Git-directory checks and adds the tracked-manifest check (R22, R27), instead of enumerating worktrees, gitfile views and `core.worktree` spoofs. The residual local-layout trust boundary is stated in the contracts (R28).
- **The class set stays upstream.** The six names and definitions are unchanged; a general-domain agent maps its own work onto them semantically, and that reliance is recorded as an assumption (R18, § Unverified items).
- **Packaging follows the repository.** A TypeScript package source with a per-skill bundle, a parameterised root `skill:build`, and tests under `tests/` that are not shipped (R12, R13).
- **The trigger lives in the description; the scope stays in the body.** The description asks an agent to use the skill before a non-trivial change to decide whether that change needs a durable record, and keeps the lifecycle-action triggers. The upstream standing scope sentence — only lasting decision rationale, mechanical and local edits exempt — remains in the skill body rather than being duplicated in the description (R29).

## Alternatives considered

**Carry the source's Chinese/English/sidecar triplet verbatim.** It lost because the target's audience is the general agent-usage domain, where a project's translation and consistency policy is its own; a verbatim triplet would impose the source repository's bilingual convention and make the archive gate depend on a sidecar format the skill does not own. The companion suffix is the equivalent means: the unit and its completeness stay mechanical, and consistency is delegated.

**Carry the fixed format-adoption date and the legacy markers.** They lost because they name source-corpus history. A general adopter has its own adoption date, so the date becomes an input and markers that never existed in the target are dropped; without the flag, a fresh adoption has no escape hatch.

**Carry the three Figma seal exceptions.** They lost because they authorize a one-off change to one source artifact; carrying them would invent target policy. The target grants no exceptions and treats a needed seal change as a handover.

**Carry a stricter freeze gate with Git-history forensics (merge-only deletions, grafts, replace refs, shallow detection, per-commit blob proofs).** It lost because the source mechanism defines the guarantee as an append-only manifest against a trusted baseline, and the trust for rewritten history belongs to the project's CI and protected branches. Adding history forensics would extend a mechanism that does not exist upstream, enlarge the gate beyond what the skill's audience needs, and make the skill brittle for adopters with ordinary Git workflows.

**Ship prose only and delegate every mechanical check.** It lost because the mechanical checks are part of the upstream mechanism and the archive freeze is evidence only if it is sealed and verified; a self-contained skill for general adopters cannot assume a project already has an equivalent gate.

**Keep the repository's installed notes skill as the design source.** It lost because the request excludes the repository's notes-related skills and their design, and the upstream revision is the named source.

**Use the pinned `dsh-v0.2.1-rc.2` submodule instead of fetching the latest tag.** It lost because the request names the newest upstream version; the read-only clone proves the contract is identical, so no recipe difference was introduced.

**Drop the semantic workflow and keep only the gate.** It lost because the mechanism's value is the decision practice — when a note is warranted, what beats another, when to prune or archive — and the gate exists to keep that practice honest, not to replace it.

**Keep the filename calendar validation and the class-directory strictness.** They lost because the source's walker checks the filename shape only and ignores directories without Markdown; round 1 found both unruled, so they were removed and ruled out (R21) rather than recorded as target extensions.

**Enforce companion completeness in the active tree.** It lost because a project may translate selectively; the archive unit is where completeness must hold, and the active tree stays permissive (R2).

**Carry the adopter's notes prose.** It lost because the request excludes that tree as a source; the seven passages found across rounds 1 and 2 were re-derived from the upstream files and the record states the correction instead of claiming a clean provenance.

**Read the archive baseline from an external notes root's own repository.** It lost because the target's baseline is the project's own Git history and no second trust boundary was specified; the root must stay inside the project, and a project that keeps its notes elsewhere hands over (R22).

**Accept a symlinked root or archive directory that resolves elsewhere.** It lost because the manifest would then have no trusted baseline and `--write` would have an effect outside the project; canonical containment is the cheap implementation of R22, and the regression tests pin it.

**Reject every symlinked archive root.** It lost because an inside-project symlink is an ordinary layout, and the failure was the lexical baseline path, not the symlink; reading the baseline at the resolved path inside the same repository keeps the layout while restoring the guarantee (R22). Repository identity is the absolute Git directory plus the worktree toplevel, so a worktree view that merely shares the project's Git directory is rejected.

**Support nested companion records.** It lost because the upstream triplet is flat and nesting would invent a unit model the source does not define; the gate rejects a companion as a unit source and a nested record is a project divergence (R25).

**Keep the pre-redesign identity layer.** It lost because it enumerated Git layouts (registered worktrees, gitfile views, per-worktree `core.worktree`, parent and sibling checkout entries) and consumed most of the first review loop; anchoring the notes path to the current checkout plus the tracked-manifest check keeps the baseline in the same tree with far less mechanism (R22, R27).

**Keep upstream's replay of triplet completeness on every verification.** It lost because the declared suffix set is a target addition that may grow over time; replaying the current set over frozen history would make a later translation impossible without editing sealed units. Completeness is enforced at seal time and verification compares the manifest (R2, R23).

**Generate a notes-tree `AGENTS.md` template in `init`.** It lost because the skill's description and body already carry the trigger and rules; a generated policy file would duplicate them, drift, and be overwritten on updates, contrary to the repository's create-vs-update norm.

**Keep the gate's tests inside the shipped skill.** It lost because the repository owns its test suite and a skill should ship its gate, not its harness (R12); the tests stay under `tests/` and exercise the work-directory or landed script.

**Keep the first-stop candidate unchanged.** It lost because the human review asked for a simpler mechanism: a Git prerequisite, a skill-named root, declarative companions with manifest-only verification, an initialized skeleton, unchanged classes and repository-native packaging. The redesign is recorded above and the old candidate remains in history.

## Risks

- **Over-mechanisation returns.** The pre-redesign gate grew a repository-identity layer that consumed most review rounds. The redesign removes layout enumeration: the gate keeps canonical containment, same-Git-directory anchoring and the tracked-manifest check (R22, R27), and the contracts state the residual trust boundary (R28). A reviewer that asks for a new layout check is answered in the record, not by growing the gate.
- **Archive semantics deviate from the source in two upstream-fit places and one hardening.** Companion completeness and archive metadata are enforced only when sealing a new unit (R2, R23), so verification never replays them over frozen history; `archived/AGENTS.md` is optional and ignored (R6); and a non-empty manifest must be tracked by Git (R27). The stronger upstream verifier re-checks its fixed triplet and metadata on every run, so this is recorded rather than hidden. A second consequence: with manifest-only verification, a locally hand-added manifest entry that gives a sealed unit a new artifact passes verification; the seal command and the project's review/CI are the enforcement point, and a locally planted manifest is outside the stated trust boundary (R28). Each deviation is recorded and tested; a reviewer checks that they protect the same freeze role rather than weaken it.
- **The tracked-manifest check can create a false sense of local safety.** It proves the manifest is in the project's Git index, not that the working tree is the committed tree; a local actor who can stage a manifest at the correct path is inside the trust model, which delegates history to CI and protected branches (R28). CI remains the anchor.
- **Classification relies on model semantics.** The upstream six classes are software-flavoured; a general-domain agent must map its own decisions onto them. The mapping is an assumption, recorded as unverified (R18), and the adopter's own corpus is the evidence; a project that cannot make the mapping is a scope challenge, not a mechanical gate result.
- **Git is now a hard prerequisite.** A project without Git cannot use any command; the mitigation is a clear install/init instruction and the contract's compatibility line (R11). This narrows the adopter set and is intended.
- **A partial mechanism for some adopters.** The active half works with any decision domain; the archive half still requires Git and a complete declared companion set per sealed unit (R2). A non-Git project, or one that translates selectively, keeps the active lifecycle but cannot seal a unit without its full set. The limit is recorded rather than answered with a mechanism the source does not have.
- **Translation pairs are current at the final stop.** The work directory pairs and the record pair were regenerated and checked at the redesign stop (R14); the manager's repository-wide list still reports the work-directory pairs out-of-sync by format, and `publish` removes them before landing.
- **Packaging migration.** Moving the gate to TypeScript, introducing a package build and relocating the tests changes the built artifact while the mechanism stays the same; the mitigation is a build-parity check before the packaging commit and the skill gate on both the work directory and the landed copy. The bundle must remain a single self-contained ES module with no runtime dependencies.
- **Corpus drift.** The upstream corpus acceptance is a recorded run, not an automated test; a later source revision could invalidate a format assumption. The mitigation is to rerun the corpus checks against the pinned submodule before a future gate change.
- **Script maintenance.** A bundled script and its repository test suite are more to maintain than prose; the mitigation is that the script mirrors a small, named gate surface, the identity invariants are few, and the tests live in the repository's suite rather than in the shipped skill.
- **Rollback point.** Nothing has landed: the branch commits and the work directory are reversible by resetting the branch to `8921e45` and removing the work directory; `skills/`, `.agents/skills/` and `submodules/dsh` are untouched, so no installed state and no upstream pin needs repair.
