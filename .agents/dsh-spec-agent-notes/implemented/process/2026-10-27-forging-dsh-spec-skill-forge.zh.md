# Agent Note: 技能锻造中的声明式审查草稿

Status: implemented

[English](2026-10-27-forging-dsh-spec-skill-forge.md) | 中文

## 问题

锻造技能拥有自己的一套配对机制。它旧的 `review` 命令从文件名推断翻译配对，写包含源哈希的 `.i18n.yaml` 记录，并由 `review --check` 判断草稿是否最新。于是锻造技能既是草稿的生产者，又是草稿一致性的门禁。

笔记机制把这两件事分开。项目声明伙伴后缀；笔记技能按伙伴配对并移动笔记；两侧是否一致由项目的配对门禁负责。锻造技能应遵循同样的分工：配对是声明式的，一致性仍是采用者门禁的职责。

## 决策

锻造技能用已声明的伙伴取代自己的配对记录：

- `pair <name> [--companion <suffix>]...` 是只读的配对报告。`review` 只是生命周期阶段名，不是命令。它找出所有文件名以已声明后缀结尾的文件，移除后缀推导出 `.md` 来源，报告每个草稿/来源配对，并在已声明草稿没有来源时失败。
- `publish <name> --into <dir> [--companion <suffix>]...` 接受同一组声明，拒绝孤儿草稿，从工作目录移除已声明伙伴，复制工作目录，再移除它。
- 没有声明时就没有审查草稿。`pair` 仍会列出可能的草稿：去掉最短点号后缀后能对上已有 `.md` 源的文件，并标记为未声明。一个来源可以没有草稿、一份草稿或多份草稿；没有草稿不是错误。
- 已声明后缀可以命名翻译（例如 `.zh.md`）或项目的配对记录（例如 `.i18n.yaml`）。重叠后缀按最长后缀解析，与笔记机制一致。
- 锻造技能不写 `.i18n.yaml`，不保存源哈希，也没有 `pair --check`。配对是否最新由项目自己的配对门禁决定；锻造技能不导入该门禁，也不点名它。
- `publish` 前，采用者从工作草稿源中移除只属于审查草稿的内容；`publish` 原样复制源。

## 设计

工作目录仍然是唯一权威。已声明伙伴是工作目录下的普通文件，文件名以已声明后缀结尾；其来源是移除该后缀并追加 `.md` 后的同一路径。后缀遵循笔记的形状，不能是 `.md`；来源必须是普通文件。报告是一组 `草稿 → 来源` 行；孤儿在 `pair` 和 `publish` 中都是错误。没有声明时，报告列出点号后缀能对上已有 `.md` 源的疑似草稿；有声明时，在已声明配对之后追加未声明候选。

审查草稿及其配对记录对锻造技能而言是普通的工作目录内容。采用者的配对门禁写 `.i18n.yaml` 记录；锻造技能声明并移除它们，从不写或检查它们。`publish` 在复制前移除声明覆盖的文件；其他每个文件都复制。这让声明成为边界：后缀未传入的伙伴不是审查草稿，会作为内容落地。

变更是源码层面的：`package/dsh-spec-skill-forge/forge.ts`、随附的工作目录脚本、锻造技能 SKILL.md 的审查规则、生命周期测试、`package.json`、AGENTS/package README 的措辞，以及本记录。工作目录已发布到 `skills/dsh-spec-skill-forge/`，安装副本已刷新，本记录已移动到 `implemented/`。

## 曾考虑的替代方案

**保留锻造技能的源哈希记录并增加声明式后缀。** 那是第一次尝试：它让声明可配置，但让锻造技能继续拥有第二套配对机制。笔记机制不把一致性记录放在技能里；锻造技能也不应这样做。

**把 `dsh-translate-docs` 的章节哈希记录复制进锻造技能。** 锻造技能会因此拥有项目配对门禁的第二份实现，并依赖该门禁的格式。配对草稿和判断它是否最新是两件事；采用者的门禁已经拥有第二件。

**依赖固定的 `.zh.md` 约定。** 它假定一种审查语言，并禁止选择性和多份草稿。声明才是采用者的选择。

**硬依赖 `dsh-translate-docs`。** 共享工作流不是运行时依赖。锻造技能不应导入或调用翻译门禁；采用者决定在工作目录里运行哪个门禁。

## 后果

- 锻造技能现在只拥有声明、配对/来源报告、孤儿拒绝和 publish 移除；不拥有源哈希、一致性记录或 `--check`。
- 配对是否最新由项目配对门禁负责；锻造技能不导入也不调用它。审查草稿及其 `.i18n.yaml` 记录仍是采用者内容，由 `publish` 移除。
- `publish` 移除已声明伙伴并原样复制工作草稿源。执行者必须在发布前移除源中只属于审查草稿的内容；遗忘的切换行、回链或已移除草稿链接会落地。
- `pair` 命令是只读的。无声明报告按后缀关系列出候选伙伴；最短后缀规则和与 `.md` 源的邻近性使它成为启发式，它从不删除。
- description 反转规则和已有决策记录的当前来源规则在技能正文中；两者都由审查判断，而非机械检查。
- 落地技能以 97 行、约 3,022 tokens 通过门禁；生命周期套件 39 个测试，仓库套件 206 个，笔记树 31 notes / 62 companions。工作目录配对在清理前通过项目配对门禁。
- 代价和开放风险：锻造技能无法发现过期翻译；手工源清理未验证；`publish` 非事务，且在复制前移除已声明草稿；候选启发式会报告假阳性。VCS 是回滚手段。
