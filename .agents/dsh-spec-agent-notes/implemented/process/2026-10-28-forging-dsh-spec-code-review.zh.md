# Agent Note: 从上游 code-review 技能锻造 dsh-spec-code-review

Status: implemented

[English](2026-10-28-forging-dsh-spec-code-review.md) | 中文

## 问题

包的技能集包含锻造技能、agent-experience、agent-notes、prose-standard、find-simplifications、pre-push-checks 与 error-handling 技能。包里没有 code-review 技能，所以采用项目得不到一套 agent 可执行的流程，来对照项目自己声明的标准审查一个 pull request。上游 `dsh-code-review` 正是某个仓库的这套流程：一份面向审查者的技能，让审查者先确定审查基线与范围，在判断 diff 之前读拥有该变更的要求，检查一组阻断性要求，逐项走过只看代码无法覆盖的审查检查，并以固定形状报告发现。它的小节点名了那个仓库的路径与机制——`pnpm change-scope`、`packages/AGENTS.md`、defensive-patterns 页面、Cordis、客户端 UI 本地化门禁、Agent Notes 树、双语规则。原样搬运会引入另一个项目的策略，使技能在项目之外不可用；略去则丢掉这套包要抽取的一项审查机制。锻造必须保留机制，并把每个仓库专用指涉重绑定到采用项目自己的声明。目标受众与领域是软件工程。

## 决策

包交付 `dsh-spec-code-review`，它面向软件工程改编自上游 `dsh-code-review` 技能。技能目录包含 `SKILL.md` 与技能根的 `THIRD_PARTY_NOTICES`；技能镜像到 `.agents/skills/`，上游同名的安装副本已不存在。`AGENTS.md` 与根 `THIRD_PARTY_NOTICES.md` 点名该技能。

`SKILL.md` 保留上游的小节名称与顺序——Sources of truth、Blocking requirements、Manual checks、Reporting findings——以及每一节承载的机制：确定审查基线与变更范围；在判断 diff 之前读拥有它的要求；执行阻断性要求；逐项走过审查专用检查；以固定形状报告发现。改编内容即处置表所记：采用项目的声明取代某个仓库的文档列表；范围要求以自然语言陈述，点名 `dsh-spec-pre-push-checks` 示例并以版本控制兜底；标题命名拟议变更；M9 陈述一条权威归属与派生测试；核心审查职责保持无条件，机制型要求各自携带条件；包已交付的兄弟技能以括号示例出现；小节标题保持上游原词。description 已泛化并追加中文触发语言，frontmatter 的 `license` 字段指向技能根通知。技能不附带脚本、reference 或测试。alpha.2 基线的通用扩充——针对新表示的必需行为测试、生产方扩展点偏好与配置优先级测试——已承载于人工检查；基线新增的 `dsh-session-projection` 兄弟引用不搬用。

- 交付与语言：英文交付并附中文触发关键词；中文审查草稿（`SKILL.zh.md` 与其 `SKILL.i18n.yaml` 记录）在停止时产出并由 `publish` 移除，记录自身的中文对侧在落地时写入（R5、R6、R9）。
- 不附带脚本、package 源或测试；被审查项目的范围工具或版本控制提供变更范围（R2、R4）。

## 目标形态

技能是一个文件，沿用上游小节骨架：

- Frontmatter：`name: dsh-spec-code-review`；description 在审查对照项目声明标准的拟议变更时触发，并点名仅看代码无法覆盖的审查检查；追加中文触发语言；`license` 字段指向技能根通知。
- `# Reviewing a proposed change`：指导式框架、已核实的 base/head、变更范围、优先级顺序，以及“先读要求再判 diff”那一段。
- `## Sources of truth`：声明及其填充的类目——根与每个改动子树的常驻指令；它引用的设计或架构规则，每个产物一个拥有页面；文档与行文标准；它为改动领域点名的标准，例如行文、测试可靠性、错误处理或 UI/UX；测试策略与质量门禁；决策记录；成对变更的语言与术语政策。核心审查职责无条件；机制型要求各自携带条件。
- `## Blocking requirements`：六条编号要求，各自保留上游属性；机制型要求携带自己的条件，核心职责保持无条件。
- `## Manual checks`：审查专用检查，各自保留具体内容。
- `## Reporting findings`：缺陷、位置、影响与证据；内联与变更级；阻断与建议；已由绿色门禁强制的问题排除；回复与接收评审的规则。

## 约束处置

处置使用锻造技能的取值：**保留**（Keep）承载原始措辞与语义，仅调整语言与布局；**适配**（Adapt）实例化目标值；**重绑定**（Re-bind）把消失的指涉抽象到目的，再找到目标等价物；**消解**（Dissolve）记录指涉已消失，以及接管它的检查。约束列陈述来源要求，包含来源自身的名称；依据列陈述目标事实。目标落点：`SK` = 技能唯一的 `SKILL.md`；小节名沿用上面的目标形态。

## 目标裁定

| # | 裁定 | 理由 | 可逆方式 |
|---|---|---|---|
| R1 | 审查的要求来自采用项目的声明——`AGENTS.md` 或它指向的文件——以及该声明点名的产物。目标陈述要寻找的类目与映射流程，不是固定路径。核心审查职责适用于任何软件项目并无条件陈述；只有管理项目可能没有的外部机制的要求才以该机制为条件；自带回退的要求把未声明的标准记为缺口，而不是用来源仓库替换。 | 通用项目的标准是它自己的；固定列表只是换名的某个仓库策略，而无条件核心职责让薄声明不至于削弱审查本身。 | 改 sources 小节与各要求的条件。 |
| R2 | 变更范围以自然语言确定：改动路径，以及任何未提交、已暂存或未跟踪的工作，来源为项目声明的范围工具（可用时使用 `dsh-spec-pre-push-checks` 技能）或版本控制。不规定命令，也不打包脚本。 | 上游命令属于来源仓库；把结果而非工具陈述出来，要求即与领域无关；打包范围工具会发明目标不拥有的机制。 | 规定默认命令或加入打包的范围脚本。 |

**原样搬运上游文本。** 它失败是因为请求的受众与领域是软件工程，不是来源仓库：原样文本引入另一个项目的命令、路径、框架规则与策略，每一条对采用者都不成立。

**复用已部署的 `.agents/skills/dsh-code-review` 改编。** 它失败是因为部署副本不是设计来源；请求点名上游技能，每条搬用的约束都必须追溯到那个来源。复用更早的改编会让记录无法展示每个来源单元的处置。

**交付 change-scope 脚本。** 它失败是因为上游命令是来源仓库的工具；一旦陈述结果而不是工具，要求就与领域无关，打包范围脚本会发明目标不拥有的机制。

**把 manual checks 拆到 reference 文件。** 它失败是因为改编文本预期落在门禁预算内，且每次审查都需要整份检查项；渐进式披露只会增加检索步骤而不减少审查使用的上下文。

**用通用最佳实践清单替换事实来源。** 它失败是因为该机制是拿项目自己声明的标准来审查——通用建议无法告诉审查者这个项目决定了什么——而且评审将不再能引用拥有页面。

**把 dsh 专用检查保留为条件小节。** 它失败是因为用一个项目词汇写成的条件仍会把那套词汇带进通用技能；它们的通用属性被重绑定，框架名被消解（R8）。反向错误——条件化核心职责，仿佛每个项目的声明都很薄——由 R11 排除。

**把上游双语规则保持为强制。** 它失败是因为项目是否成对语言由它自己声明；目标让成对内容检查以项目政策为条件。

**在停止时保持候选不发布。** 它失败是因为工作目录与分支在评审验收前是可逆状态，而该验收正是把候选变成已交付技能的落地授权。

**保留全类目条件化。** 它失败是因为核心审查职责无条件、只有机制型要求条件化：条件化每个类目会让薄声明被读成可以跳过审查本身的许可。

**为清晰重命名小节标题。** 它失败是因为小节标题遵循上游，因此 `## Sources of truth`、`## Blocking requirements`、`## Manual checks` 与 `## Reporting findings` 保留原名。

**发布但不移除被取代的安装副本。** 它失败是因为新技能取代 `.agents/skills/dsh-code-review/`：安装副本与清单条目被移除，固定的上游基线保持不变。

**不带中文对侧地落地记录。** 它失败是因为 notes 树中 implemented 记录携带对侧，而最终评审正是写出对侧的时点（R5）；配对记录证明当前性，不是质量。

**保留 rc.3 措辞，把 alpha.2 差异记为偏离。** 它失败是因为本包是跟随上游的抽取：三处扩充是通用审查流程，在不点名来源仓库的情况下让检查更锐利，而没有任何理由支持一个偏离。

**把新增的 `dsh-session-projection` 引用作为“可用时”示例搬用。** 它失败是因为包不交付这样的兄弟技能，也没有等价手段；为永不交付的技能写“可用时”示例，等于点名采用者无法满足的依赖，因此该引用被消解（S12、R14），由保留与派生状态检查保留归属属性。

- 包在 `skills/dsh-spec-code-review/` 交付 `dsh-spec-code-review`，安装副本在 `.agents/skills/dsh-spec-code-review/`；被取代的上游同名安装副本与清单条目已消失，`AGENTS.md` 与根 `THIRD_PARTY_NOTICES.md` 点名该技能。
