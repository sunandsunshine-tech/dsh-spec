# Agent Note: Forging dsh-spec-find-simplifications from the upstream find-simplifications skill

Status: implemented

English | [中文](2026-10-28-forging-dsh-spec-find-simplifications.zh.md)

## Problem

The skill set has no skill that finds simplifications. A project can record decisions, forge skills and write prose, but an agent asked to remove dead, duplicated, speculative or unnecessarily maintained behavior has no procedure: it does not know which project documents state the constraints, which questions expose a removable obligation, how much evidence a candidate needs, which ownership and failure semantics must survive, when replacing infrastructure is a net reduction, and how a survey becomes a decision record. Upstream `dsh` carries exactly that procedure in `.agents/skills/dsh-find-simplifications/SKILL.md` and its `references/historical-patterns.md`, but it is written for DeepSeek Harness: it names that repository's documents, packages, protected designs, note corpus and check commands. Copying it verbatim would carry another project's referents; leaving it out would drop a mechanism the pattern names.

## Decision

The package ships `dsh-spec-find-simplifications` as an adaptation of the upstream `dsh-find-simplifications` skill for the software-engineering domain. The landed directory holds `SKILL.md`, `references/historical-patterns.md` and `THIRD_PARTY_NOTICES`; the skill is mirrored into `.agents/skills/`, and the superseded upstream-named installed copy is removed. `SKILL.md` keeps the upstream section names and the mechanism each section carries — establish scope and constraints; the six discovery questions; reachability and trade-off proof; ownership and failure semantics; infrastructure replacement for a net reduction; record, consolidate and validate — adapted as the disposition table records. The reference keeps the seven calibration patterns as product-neutral archetypes. The frontmatter carries the name, the generalized description with Chinese trigger keywords (R8), and a license field naming the skill-root notices.

- Delivery and language: English delivery with Chinese trigger keywords; the review drafts are Chinese `.zh.md` files with their `.i18n.yaml` records, and the landed sources are English-only (R8, R12).
- No bundled script, no package source, no tests and no runtime dependency; `rg` is the first search tool, with the project's own tool as the fallback (R5, R11).
- A revision of the shipped procedure is edited in place: no forge work directory, no `publish` step and no new review drafts; the procedure, its installed copy and this record change together, and the full repository suite is its acceptance (R20).

## Alternatives considered

**Port the source verbatim.** It lost because a verbatim port reads as another project's instructions: the documents it names, the package tree it searches, the protected adapters and the note corpus do not exist in a general project, and an adopter cannot follow a referent it does not have.

**Dissolve the calibration reference and keep only SKILL.md.** It lost because the reference is part of the source mechanism: a candidate whose value an unused-symbol search does not settle is exactly where the recorded patterns calibrate the decision, and dropping the file would drop that part of the procedure.

**Bind the forged skill to this repository's own paths** (`AGENTS.md`, `.agents/dsh-spec-agent-notes`, `.agents/dsh-spec-translate-docs/terminology.md`). It lost because the skill is delivered to adopting projects, not to this repository: the project's own declaration is the referent, and a fixed repository path would be another project's referent in a different clothes.

**Name the sibling skills as hard references.** It lost because a hard reference makes the skill depend on a mechanism the adopter may not install; the parenthetical example keeps the alignment without the dependency (R4).

**Keep the siblings unnamed.** It lost because the set ships the prose, notes and check-selection siblings, and a generic rule with an example-form name reads the same to an adopter with or without the sibling (R4).

**Ship a scanning script.** It lost because the source ships none, the decisions are judgment rather than exact commands, and a script would invent a mechanism the source does not have while creating a maintenance surface the request does not ask for.

**Carry the source's protected LLM adapters and persistence seam.** It lost because those are source-product facts; a general project has no such twins, and inventing protected designs would be worse than asking the project, its records or the user which designs are protected.

**Keep the archived-note links in the calibration reference.** They lost because they point into a corpus a general project does not have, the skill gate rejects links that escape the skill, and the link target is not the lesson; the product-neutral archetype is.

**Keep the source product's role names in the archetypes.** It lost because the target requires product-neutral wording: it keeps the scenario, deletion inventory, retained obligation and failure mode that calibrate, and replaces only the role names (R6).

**Add acceptance criteria, a scoring scale or a checklist.** It lost because the source says the text is guidance rather than a checklist, the request forbids extending a mechanism the source does not have, and a score would manufacture false precision for a judgment task.

**Keep the record proposed.** It lost because the notes contract moves a shipped decision to `implemented/`.

**Publish without removing the superseded installed copy.** It lost because the new skill replaces `.agents/skills/dsh-find-simplifications/`: two installed copies would compete, and the manifest would advertise the old one; the installed copy and its manifest entry are removed, and the pinned upstream baseline is untouched.

**Carry the alpha.2 delta verbatim.** It lost because two of its referents — the Agent Notes corpus and the defensive-patterns ownership-rule link — are source-repository facts; generalising them keeps the rules and removes the referents (R15, R18).

**Skip the alpha.2 delta as source-specific.** It lost because the delta's rules are product-neutral once those two referents are adapted; skipping them would leave the landed skill behind its pinned source, contrary to R9.

**Re-forge into a work directory and publish over the shipped copy.** It lost because the revision changes five lines of the same procedure; the in-place edit keeps the record, the installed copy and the pair aligned without duplicating the forge work directory and publish machinery (R20).

- The set ships `dsh-spec-find-simplifications` at `skills/dsh-spec-find-simplifications/` and its installed copy at `.agents/skills/dsh-spec-find-simplifications/`; the old upstream-named installed copy and its manifest entry are gone.
- The skill is prose-only: the six upstream stages and seven calibration patterns are carried as recorded rulings (R1–R20), with three target-side fallbacks — the no-declaration read (R2), the no-`rg` search tool (R11) and the no-declared-check gap report (R13).
- The procedure carries five additional constraints in place (R15–R19) and its installed copy matches it (R20).
- **Costs and limits.** A project without a declaration gets less protection (R2); a project declaring no checks gets a gap report rather than a proof (R13); the skill's output quality is prose-only and not machine-checked (A18 unverified); the ownership comparison binds to whatever ownership conventions the project declares (R18); the product-neutral archetypes trade source-product specificity for domain fit; example-form sibling names can be read as requirements by an executor that skips the parentheses; the trigger description overlaps other analysis skills a project may install.
