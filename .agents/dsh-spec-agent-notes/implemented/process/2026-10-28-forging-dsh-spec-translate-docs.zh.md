# Agent Note: 将 dsh-spec-translate-docs 锻造为自包含的翻译机制

Status: implemented

[English](2026-10-28-forging-dsh-spec-translate-docs.md) | 中文

## 问题

只抽取上游 `dsh-translate-docs` 的工作流映射的锻造，会把配对记录、语言切换行、一致性检查与术语纪律留给一个本包并不交付的「采用者的配对机制」。新采用者安装该技能后，拿到的指引会止步于一个它并不拥有的机制；既有配对文档的日常维护不会归该技能负责；而这份交付物会成为本包中唯一不自包含的技能。

把上游的项目内部布局当成设计边界是误读。上游把 `gen-translation-brief` 与 `verify-translation-pairing` 留在其仓库的 `scripts/` 里，把配对约定、翻译规则与术语纪律留在 `docs/i18n/` 里，但这些脚本、约定与 SKILL.md 是一个内聚的机制；这些文件之所以位于 SKILL.md 之外，只是因为该机制仅服务于那个仓库。本次锻造的目标是整套机制，将它抽取并泛化。

本技能的设计裁决：

- 机制是自包含的：技能随附脚本，机械地检查配对并生成其记录；
- 脚本只以上游为依据——本仓库的 manager 移植是历史遗留物，本次锻造将取代它，它不是来源；
- 调用边界只在正文中陈述；description 不携带点名用户的规则；
- 一个技能；采用者声明范围内与已经配对的文档自动维护；其他新增配对需要用户同意；
- 源语言默认为英文，对侧语言由采用者决定，并在声明或对话中指明；多种语言由声明或指令给出；
- 术语表位于 `.agents/dsh-spec-translate-docs/terminology.md`，缺失时从模板初始化；
- 一条约束取代两条路径的正文：除非采用者的声明覆盖了某份未配对文件，或用户明确要求，否则不要为它创建配对；
- 没有单独的采用者声明文件：采用者在自己的声明中声明，agent 把事实传给脚本，脚本从不读取项目配置。

## 决策

`dsh-spec-translate-docs` 是上游双语文档机制的自包含抽取：一个技能，其 SKILL.md 是工作流映射，`references/` 承载配对约定、翻译规则与文风样例约定，随附的 `scripts/translate-pair.mjs` 是机械的那一半——配对列举、检查、记录、区域比较、最小更新简报、机械拼接与术语模板初始化。范围级检查与评审汇报只把 `dsh-spec-pre-push-checks` 与 `dsh-spec-code-review` 作为可用性限定的示例点名；项目自己的检查与评审约定仍是约束规则。

- 交付语言是英文；评审语言是中文，由于评审语言与交付语言不同，description 追加中文触发语言。
- 技能从 `skills/dsh-spec-translate-docs/` 与 `.agents/skills/` 下的安装镜像发布；术语表位于 `.agents/dsh-spec-translate-docs/terminology.md`；旧的已安装 `dsh-translate-docs` 副本与 `scripts/dsh-spec-manager/` 引擎已移除（R70、R71）。

### 自动维护与调用规则

自动维护规则建立在一条约束上：

- 既有配对作为任何触及任一侧的编辑的一部分被维护——带上对侧文件、重新记录它，并在同一个变更中检查该配对；
- 采用者声明纳入范围的文档会作为日常维护为每个声明目标配对，走该配对需要的路径（已存在时走更新路径，不存在时走整篇文档路径）；
- 不要为声明之外的未配对文档创建配对，也不要添加声明未点名的目标，除非用户明确要求；用户请求在那里支配；
- 较重的单次工作——翻译声明未覆盖的文档，或声明未点名的语料——只在用户显式调用该技能或要求时运行。

这就是「声明即授权」的读法：是声明，而非单独的调用，授权对其范围进行日常维护；显式调用支配范围之外的工作。

| R1 | 技能交付自己的配对机制：记录、切换行与检查归技能所有，不归采用者。 | 直接用户裁决 |

| R28 | 冻结／生成区域使用技能自己的整行标记对，区分大小写、列 0、没有其他空白：`^<!-- (BEGIN\|END) GENERATED ([A-Za-z0-9][A-Za-z0-9._-]*) -->$`。扫描在围栏代码块之外的行上进行：围栏内的标记形状行在任何地方都是普通代码，包括区域内的围栏标记示例。标记行必须在其他块之间独立成块（区域整体周围是空行或文档边界）；区域内容可以紧贴其 BEGIN/END 标记，因此正常的 BEGIN/body/END 生成器输出是良构的。嵌套 BEGIN、没有 BEGIN 的 END、slug 不匹配、未闭合的 BEGIN、同一文件中的重复 slug、不完全符合语法的标记形状行、列表／表格／段落内的标记，以及区域内容中任何围栏之外的标记形状行都是违规；区域内容除此之外是任意 Markdown。 | 生成文档是真实的语料需求；标记格式是我们的，因为旧标记兼容性被明确放弃 |

| R28b | 区域比较是有序且惰性的：两侧的区域列表必须只在配对文档链接归一化之后拥有相同 slug 与相同文本；不匹配时点名 slug 并以「重新生成两侧」使检查失败。`brief` 把区域排除在漂移、差异与单元之外；当两侧当前区域一致时，它把重新生成的区域视为已对齐（把当前区域代入上次确认基线）并报告无需简报；当两侧当前内容不一致时，点名简报以退出码 2 结束并给出重新生成消息，而不带参数的简报以退出码 2 中止并点名配对。单侧漂移时 `check` 失败、`list` 报告该配对。`--apply` 的区域交集守卫是防御性的，在文档化流程中不可达（单侧不匹配先被捕获，已对齐的重新生成被排除），因此它不是计数的用例。只有生成器编辑区域；技能从不编辑。 | 区域重新生成不得要求记录或翻译，而半生成的配对必须保持可见 |
| R29 | 切换行按结构定位，而不是按版面位置：剥掉 frontmatter，找到 H1，扫描其顶层段落到下一个标题为止，寻找标签、分隔符与链接都匹配规范切换行的段落；至多一个段落可以匹配。位置自由，因此格式强制的 `Status:` 段落可以位于其前。零匹配报告期望的行；两个匹配报告两个行号。只有匹配段落的链接不受签名与 locale 检查约束。目标是相对对侧路径，或 pathname 以该仓库相对对侧路径结尾的绝对 URL。行内代码引用不匹配。规范标签是源标签，然后是按语言代码顺序的每个目标标签；R46 定义未声明目标的标签如何派生。生成源只豁免它自己一侧的切换行。 | 笔记格式把元数据段落放在最前，而版面位置不是语义 |

## 考虑过的替代方案

**保留采用者拥有的配对机制。** 它落败，因为新采用者没有机制可提供，因此技能会止步于缺失的记录与检查，也不会拥有请求要求的日常维护。

**复用本仓库的 `scripts/dsh-spec-manager` 移植作为脚本来源。** 它落败，因为那个引擎是历史遗留物而不是来源，把它当作来源会把移植的 dsh-spec 专用形状留在一个必须追溯至上游的技能里。

**只复用 schema 格式并写一个新引擎。** 它落败，因为机械的那一半——结构签名、小节记录、简报粒度、链接 locale——正是上游已经实现的部分；从头编写它会是第二个没有出处的实现。

**两个技能：一个自动维护者，一个显式调用的扩展工作流。** 它落败，因为结构是一个技能；边界是声明加正文中的一条约束，而不是第二个包。

**通过 frontmatter 字段或 `metadata` 键控制调用。** 它落败，因为 Agent Skills frontmatter 是封闭集合，这些字段是 Claude Code 的扩展，dsh 与 Codex 不从 `metadata` 读取调用控制，而禁用模型调用会把技能从目录中移除，这与自动维护相矛盾。

**在术语表旁放一份持久化的范围／配置文件。** 它落败，因为采用者在自己的声明中声明，agent 传递事实，而没有脚本读取的文件会变成第二个真源。

**一份带按语言列的术语文件。** 它落败，因为表的译法列属于一个目标语言，一份有多个对侧文件的源文件需要每个术语多张表，而文件将不得不为每种声明语言增加列；每个目标一份文件保持抽取出的表的列形状，并按目标选择文件。

**原样交付 dsh 的文风样例与流水线提示词。** 它们落败，因为样本文本属于项目，流水线提示词是流水线资产。技能交付文风样例约定与提炼出的语言中立原则（R35），翻译规则为其余部分点名项目的声明。

**在 v1 中支持任意纯文本格式。** 它落败，因为随附的记录、结构签名与简报单元模型都是文档类别概念；v1 交付 Markdown 类别，其他类别等待声明的模型。

**不写评审草稿就构建交接。** 它落败，因为中文评审草稿就是机制自己的证明，且配对在交接前接受检查。

## 后果

- **门禁不证明语料完整性。** 没有对侧文件的声明文档就不是配对；创建由声明、轻量路径与评审拥有。这是为按文件目标集与稳定门禁付出的明确代价。
- **聚合记录每个目标一行目标签名。** 只为某个目标记录的源编辑会让其他签名绑定旧源并刻意失去同步；检查会捕获它，但工作流必须在同一个变更中更新每个既有目标。对同一源文件的并发编辑应串行。
- **退役是批量操作。** 移除对侧文件需要移除其切换行链接，然后 write --all；点名的 write 从不丢弃目标。对侧文件已消失的条目在批量写入之前被报告为不完整。
- **按文件的源语言依赖记录与对侧标签。** 不带 --source-lang 的第一份记录回退到 en；法文源文件必须提供该旗标一次。混合源语言按源文件创建，而不是由一次批量写入创建。
- **轻量路径依赖 agent 的纪律。** 其条件是正文；越界的工作 agent 会得到红色检查，但可能产出比简报路径更差的最小编辑。分诊告诉它在不确定时切换。
- **区域锚点是小节级的。** 在同一撰写小节内移动的区域不会被捕获；两侧就错误位置达成一致会被视为协同变更。第一个标题之前的区域锚点为 0。
- **外壳 A 比先前的 slug 语法更宽松。** 当标记行匹配上游形状的外壳时被接受，包括 slug 中的标点与可选的 BEGIN 尾注；更严格的围栏、独立成块与重复规则仍然适用。
- **基于存在性的链接谓词会在新增配对时翻转。** 新增对侧文件会改变指向它的链接的归一化；受影响的既有配对必须在同一个变更中重记录。
- **迁移是一次性的聚合重记录。** 选中的活跃语料被重记录一次；不存在 v1 记录兼容层，也没有按目标的记录读取器。归档、冻结与 vendored 目录树不被选中。
- **项目声明是创建意图的唯一来源。** 脚本从不读取它；agent 传入 --select/--skip、目标、术语与生成 glob。忘记声明旗标的 CI 运行检查更少的配对，而不是错误的语料。
- **隐藏与 vendored 目录树是采用者布局。** 遍历进入隐藏目录，只剪掉默认树；宽泛声明必须对冻结或 vendored 目录树使用 --skip。
- **翻译质量不被机制验证。** 检查证明配对一致，而不是行文读起来好；翻译质量未测量。
- **仓库之前的配对机制已移除。** 遗留 manager 引擎与旧的安装副本已移除（R71）。
