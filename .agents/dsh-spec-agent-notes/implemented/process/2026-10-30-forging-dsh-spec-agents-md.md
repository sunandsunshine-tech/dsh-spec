# Agent Note: Forging dsh-spec-agents-md from the AGENTS.md format

Status: implemented

English | [中文](2026-10-30-forging-dsh-spec-agents-md.zh.md)

## Problem

The set carries skills for shaping a prompt, for durable prose, for decision records and for the mechanics of a change, but nothing owns a repository's `AGENTS.md` — the standing-instructions file that a coding agent reads before it works. The format at <https://agents.md> states what the file is for, where it lives and how nested files win, and it leaves open the questions an agent faces when writing one: which of a project's practices belong in this file rather than in the README, the documentation or a decision record; which content stays inline and which becomes a pointer or link; how an inline instruction is composed; how the root file and nested files divide scope; and when a line must change. The format's content guidance is a menu of popular sections and the onboarding guidance, "anything you'd tell a new teammate belongs here too"; it states no pointer, inline-form, size or update rule. The existing skills do not cover this artifact: the prompt skill shapes context for a prompt, and the prose skill edits durable text, but neither decides what an `AGENTS.md` carries, where a fact's home is, or how the file's scope and staleness are governed. An agent writing an `AGENTS.md` today either copies the format page's example, putting content in the file that the README or a linked document owns, or writes a pointer with no rule behind it. The set needs the artifact-specific judgment, stated without repeating the craft the existing skills already own.

## Decision

`dsh-spec-agents-md` ships from `skills/dsh-spec-agents-md/` as one prose `SKILL.md`, plus a skill-root `THIRD_PARTY_NOTICES` for its adapted source; its installed copy at `.agents/skills/dsh-spec-agents-md/` mirrors it byte for byte; it has no bundled script, no reference file and no `compatibility` field. Its body answers five questions a writer or reviewer of the file must decide: what belongs in `AGENTS.md`; when content stays inline and when it becomes a pointer or link; how an inline instruction is composed; how root and nested files divide scope and resolve precedence; and how the file is kept current. It is generic — it names no repository, path, tool or process of this set — and it defers prose wording and prompt shape to the existing skills as optional references, requirement first, in the form `.agents/dsh-spec-agents-md/forging.md` requires.

- Delivery language is English; the review language is Chinese, and the description carries Chinese additional trigger language.
- This record keeps its own `.zh.md` and `.i18n.yaml` companions.

### Source absences and derived rulings

The site states no rule for the pointer-versus-inline choice, the composition and linking of an inline instruction, the belonging and exclusion tests, the loading model that would settle how an ancestor file and a nested file combine (it says only that the nearest file is read and the closest wins), the cross-agent writing practice, the storage location for detail extracted from the file, or an update workflow. The no-schema rule is not a derived ruling: the format states that freedom itself (no required fields, any headings, the popular sections as choices) and it is carried as U11. The request requires those answers, so each is recorded as a derived ruling, marked as such in the skill's own word where the skill states it, and kept out of the disposition rows' "carried" basis. No derived ruling is presented as a source statement.

## Alternatives considered

**Carry the format page as a checklist or template.** The page's sections could be reproduced as a required outline. Rejected: the format says any headings and no required fields, so a template would impose a structure the format does not, and the request forbids preset sections. The skill states the freedom and the acceptance evidence instead.

**Write a fixed content matrix** (always project overview, always commands, always security). Rejected for the same reason: the site calls those sections popular choices, and a project without a security surface or a special deployment would carry empty or invented sections. The onboarding guidance and the exclusion list replace the matrix.

**Treat the format's guidance as rules.** The statements "anything you'd tell a new teammate belongs" and the popular-section list could be reproduced as the file's required content. Rejected: they are guidance and a menu, not a prohibition or a schema; the skill keeps them as the starting point and records the narrower belonging test and the exclusions as derived rulings.

**Bundle a script that checks links, nesting and emptiness.** Rejected: whether content belongs, is a pointer or is current are judgments; the only mechanical requirement — a relative link resolves — belongs to a project's own documentation gate, and a bundled checker would add a runtime and maintenance surface without deciding the skill's questions. Recorded as T1.

**Split into two skills**, one for selection and one for scope and updates. Rejected: the five questions are one coherent unit that a single task encounters together, and splitting them would force two loads, overlap their triggers and create conflicting instructions at the boundary.

**Ship a reference file of worked cases.** Rejected: the body's rules and acceptance evidence are complete for the five questions, and cases would restate the same rules at an extra load and an extra translation; a contested placement is decided by the rules, not by a larger corpus of examples.

**Carry the ecosystem list and the tool-configuration answers.** Rejected: the list is descriptive and dated, and the configuration answers are product-specific; neither changes what a project writes.

**Use this repository's own `AGENTS.md` as the model.** Rejected by the request and by the source: the format's own page is the authority, and modelling on one repository's file would put that repository's rules into a generic skill.

**Rely on the existing prompt and prose skills and add no new skill.** Rejected: the prompt skill shapes context for a prompt and the prose skill edits durable text; neither owns what an `AGENTS.md` carries, where a fact's home is, or how the file's scope and staleness are governed. The new skill supplies the artifact-specific judgment and references the two for craft.

**Derive the content rules from OpenAI Codex's `AGENTS.md` documentation or another product's docs.** Rejected by the request: the format page is the authority, and product documentation would import a product's vocabulary into a general skill.

**Record as implemented now.** Rejected during forging: nothing had landed and the human review had not run, so the record stated a proposal and moved with the landing.

## Consequences

**What it bought.** The set now has an owner for `AGENTS.md` content: the five questions have a stated answer, the pointer and extraction-home rules keep the file and its linked detail from becoming a second documentation system, and prose and prompt craft stay with the skills that already own them. The acceptance conditions were met before landing: the maintainer accepted the revised submission; the landed tree passes the skill gate, the repository suite, the formatting check, the notes check, the record pairing, the installed-copy comparison and the DCO check; the skill answers the five questions from <https://agents.md>; it repeats neither the prompt-shape rules of `dsh-spec-agent-experience` nor the editorial rules of `dsh-spec-prose-standard`; it contains no repository-specific path, rule or flow; and its provenance notice and Chinese pair are complete.

**What it gave up.** The format states no belonging, pointer, inline-form, loading-model, storage or update rule, so D1–D7 are the drafter's reading of its purpose; the maintainer's acceptance is the evidence that the reading matches intent, not a source confirmation. The default extraction home is `.agents/dsh-spec-agents-md/`, chosen to avoid collisions with a project's other directories and a default only, so changing it costs a directory rename and one link edit; it can become a second documentation store if a project ignores the bound. The scope fallback restates a repository-wide rule in a subtree where the client may load the ancestor, and a client that always loads it makes the repetition unnecessary. The trigger behaviour and the skill's effect on an executor's decisions remain unverified, the rules are not exercised on a live project's `AGENTS.md` (including the default extraction home and its commit requirement), and the duplication guard is the boundary references plus review. The landing touched shared files — the root `THIRD_PARTY_NOTICES.md` and the installed copies — only after acceptance, so a rejected review would have left them unchanged.
