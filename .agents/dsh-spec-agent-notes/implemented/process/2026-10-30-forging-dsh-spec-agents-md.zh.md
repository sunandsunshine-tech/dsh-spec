# Agent Note: 从 AGENTS.md 格式锻造 dsh-spec-agents-md

Status: implemented

[English](2026-10-30-forging-dsh-spec-agents-md.md) | 中文

## 问题

本技能集合已带技能，分别用于塑造提示词、持久行文、决策记录与变更机制，但没有任何技能负责仓库的 `AGENTS.md`——编码 agent 开工前读取的常驻指令（standing orders）文件。<https://agents.md> 上的格式说明了该文件的用途、所在位置以及嵌套文件如何胜出，却没有回答 agent 撰写它时面对的问题：项目的哪些做法应写入本文件，而不是 README、文档或决策记录；哪些内容保持内联、哪些成为指针或链接；一条内联指令如何构成；根文件与嵌套文件如何划分范围；以及一行何时必须改动。该格式的内容指导是一份流行小节菜单，再加一句入职引导语“你会告诉新同事的内容也都属于这里”；它没有陈述任何指针、内联形式、篇幅或更新规则。现有技能不覆盖这个产物：提示词技能为一条提示词塑造上下文，行文技能编辑持久文本，但两者都不决定 `AGENTS.md` 承载什么、一条事实归到哪里，也不决定文件的覆盖范围与过时如何被治理。今天写 `AGENTS.md` 的 agent 要么照抄格式页的例子，把 README 或某份被链接文档拥有的内容写进文件；要么写一个背后没有规则支撑的指针。本技能集合需要针对该产物的判断，陈述它时不重复现有技能已经拥有的手艺。

## 决策

`dsh-spec-agents-md` 从 `skills/dsh-spec-agents-md/` 交付：一份纯散文的 `SKILL.md`，外加技能根目录的一份 `THIRD_PARTY_NOTICES`，用来承载其改编来源；其安装副本 `.agents/skills/dsh-spec-agents-md/` 与之逐字节一致；它不随附脚本，没有 reference 文件，也没有 `compatibility` 字段。正文回答这份文件的撰写者或评审人必须裁决的五个问题：`AGENTS.md` 里应当放什么；内容何时保持内联、何时成为指针或链接；一条内联指令如何构成；根文件与嵌套文件如何划分范围并裁决优先级；以及文件如何保持最新。它是通用的——不点名本技能集合的任何仓库、路径、工具或流程——并把行文措辞与提示词形态以可选引用的方式交给现有技能，要求在前，形式遵循 `.agents/dsh-spec-agents-md/forging.md` 的规定。

- 交付语言为英文；评审语言为中文，description 携带中文附加触发语言。
- 本记录保留自己的 `.zh.md` 与 `.i18n.yaml` 伴随文件。

### 来源缺失与派生裁定

对于指针与内联的取舍、内联指令的构成与链接、归属与排除判定、会裁决祖先文件与嵌套文件如何组合的加载模型（页面只说读取最近文件、最近者胜出）、跨 agent 的书写实践、从文件中抽出的细节的存放位置以及更新工作流，网站都没有陈述规则。无 schema 规则不是派生裁定：格式本身陈述了这份自由（没有必需字段、标题任意、流行小节只是选项），并作为 U11 承载。请求要求这些答案，因此每条都记为派生裁定，在技能自行陈述之处用技能自己的措辞标注为派生，并且不进入处置行中“承载”的依据。没有任何派生裁定被呈现为来源陈述。

### 描述

该技能的 frontmatter description，逐字如下（776 个字符，低于规范的 1024 字符上限）：

> Use when writing, reviewing, or updating an AGENTS.md file — the standing instructions a repository gives coding agents — including when migrating an existing agent-instruction file to that name, to decide which content belongs in it, which content becomes a pointer or link to its owning document, how inline instructions are written, and how scope and updates are settled. Not for writing README or documentation prose, not for general prompt engineering, not for another agent-instruction format's own content, and not for applying an existing AGENTS.md during a code review. 用于编写、评审或更新 AGENTS.md——仓库给编码 agent 的常驻指令，包括把已有的 agent 指令文件迁移为该名称：决定哪些内容应写入、哪些应抽成指向拥有该内容的文档的指针或链接、内联指令怎么写，以及适用范围与更新边界如何裁决。不用于撰写 README 或其他文档行文，不用于通用提示词工程，不用于其他 agent 指令格式的内容，也不用于在代码评审中执行既有 AGENTS.md。

英文句子是交付语言，承载该技能裁决的五项决定、迁移情形，以及被排除的相邻任务：行文写作、提示词工程、其他 agent 指令格式的内容，以及在代码评审中应用既有指令。中文句子是附加触发语言。

### 要求锚点

每一条处置行都锚定它承载的要求，被锻造技能的每项要求，都在可获得的最精确层级上有对应的锚点。技能门禁是名称与目录、frontmatter 形态、大小预算与链接规则的机械锚点：`node skills/dsh-spec-skill-forge/scripts/verify-skill-spec.mjs .agents/dsh-spec-skill-forge/dsh-spec-agents-md`。§ Deciding a draft 是内容、放置与更新要求的判断锚点，§ 来源缺失与派生裁定把每条派生规则锚定到它的依据；独立评审为每条处置行与每条派生裁定各记录一个结论。仓库的形态测试与 `skills/dsh-spec-agents-md/` 到 `.agents/skills/dsh-spec-agents-md/` 的目录比较，是安装副本的机械锚点。记录门禁与翻译配对门禁是本记录及其伴随文件的机械锚点。技能的触发行为及其对执行者决策的影响在这里没有精确锚点，在后果（Consequences）一节记为未验证。

## 备选方案

**把格式页当作清单或模板搬用。** 页面的小节可以复制成一份必需的提纲。不予采纳：格式规定标题任意、没有必需字段，因此模板会强加一种格式并未规定的结构，而请求禁止预设小节。技能改为陈述这份自由与验收证据。

**写一份固定的内容矩阵**（永远是项目概览、永远是命令、永远是安全）。同样不予采纳：网站称这些小节为流行选择，而没有安全面或特殊部署的项目会携带空小节或编造的小节。入职引导与排除清单取代了矩阵。

**把格式的指导当作规则。** “你会告诉新同事的内容都属于”这句陈述与流行小节清单，可以被复制成文件的必需内容。不予采纳：它们是指导与菜单，不是禁令或 schema；技能把它们保留为起点，并把更窄的归属判定与排除项记为派生裁定。

**随附一个检查链接、嵌套与空标题的脚本。** 不予采纳：内容是否应写入、是否为指针、是否为最新，都靠判断；唯一机械的要求——相对链接能解析——属于项目自己的文档门禁，随附检查器会增加运行时与维护面，却不能裁决技能要问的问题。记为 T1。

**拆成两个技能**，一个管选择，一个管范围与更新。不予采纳：五个问题是同一个任务会一起遇到的连贯单元，拆分会迫使两次加载、触发面重叠，并在边界处制造互相冲突的指令。

**交付一个实例案例的 reference 文件。** 不予采纳：正文的规则与验收证据对五个问题已经完整，案例会在额外加载与额外翻译之上重述同样的规则；有争议的放置由规则裁决，而不是由更大的示例语料裁决。

**搬用生态系统清单与工具配置答案。** 不予采纳：清单是描述性的、标注日期的，配置答案是产品专用的；两者都不改变一个项目写什么。

**用本仓库自己的 `AGENTS.md` 作为范本。** 请求与来源都不予采纳：格式自己的页面才是权威，以一个仓库的文件为范本，会把那个仓库的规则塞进一个通用技能。

**依靠现有的提示词与行文技能，不新增技能。** 不予采纳：提示词技能为一条提示词塑造上下文，行文技能编辑持久文本；两者都不拥有 `AGENTS.md` 承载什么、一条事实归到哪里，也不拥有文件的覆盖范围与过时如何被治理。新技能提供针对该产物的判断，并为手艺引用那两者。

**从 OpenAI Codex 的 `AGENTS.md` 文档或其他产品的文档派生内容规则。** 请求不予采纳：格式页才是权威，产品文档会把产品的词汇带进一个通用技能。

**现在就记为已实现。** 锻造期间不予采纳：什么都还没落地，人工评审也还没运行，因此本记录陈述的是一份提案，并随落地一起移动。

## 后果

**换来了什么。** 本技能集合现在有了 `AGENTS.md` 内容的负责者：五个问题有了明确陈述的答案，指针规则与抽取内容存放规则让该文件及其链接的细节不会变成第二套文档系统，而行文与提示词手艺仍留在已经拥有它们的技能里。验收条件在落地前就已满足：仓库维护者接受了修订后的送审稿；落地后的树通过技能门禁、仓库套件、格式检查、笔记检查、记录配对、安装副本比较与 DCO 检查；技能回答了 <https://agents.md> 提出的五个问题；它既不重复 `dsh-spec-agent-experience` 的提示词形态规则，也不重复 `dsh-spec-prose-standard` 的编辑规则；它不含任何仓库专用的路径、规则或流程；其出处通知与中文配对都完整。

**放弃了什么。** 格式没有陈述归属、指针、内联形式、加载模型、存放或更新规则，因此 D1–D7 是起草者对其目的的解读；仓库维护者的接受是该解读符合意图的证据，而不是来源的确认。默认的抽取内容存放位置是 `.agents/dsh-spec-agents-md/`，选择它是为避免与项目的其他目录发生命名空间冲突；它只是默认值，改动它只需重命名目录并修改一处链接，项目若无视这条界限，它可能变成第二个文档存储。范围兜底在客户端可能加载祖先文件的子树里重述仓库级规则，而总是加载祖先文件的客户端使这种重复变得不必要。触发行为与技能对执行者决策的影响仍未验证，这些规则也没有在真实项目的 `AGENTS.md` 上演练过（包括默认的抽取内容存放位置及其提交要求），防重复的防线是边界引用加评审。落地只在验收之后触及共享文件——根 `THIRD_PARTY_NOTICES.md` 与各安装副本——因此被否决的评审原本会让它们保持原样。
