# Agent Note: 锻造记录陈述当前事实

Status: implemented

[English](2026-11-02-forging-records-state-current-facts.md) | 中文

## 问题

锻造技能把记录写成了流水账：记录契约列出设置、读取页面、检查运行与评审结论，并要求锻造者“记录冲突及其解决方式”。于是记录在设计之外还带着轮次编号、会话事实与验收叙述，后一轮又叠加一层，而不是替换前一层。同一设计出现多种措辞，读者无法判断哪一句仍然成立。笔记契约已经要求 implemented 笔记陈述已落地的决策并就地改写陈旧事实；锻造技能自己的记录规则没有这样做。

## 决策

锻造记录陈述当前设计，而不是锻造过程史。它的事实是：目标；读取的来源修订（仓库、修订与读取日期）；生效的设置；处置表；每一条裁定；当前的需求锚点与验证证据；读取的页面及其日期；未验证项及其原因；风险与回滚点；以及发布授权状态。

每一轮更新本次变更所改动的事实，并删除不再成立的事实。记录不得追加轮次、评审往来、草稿序号、带日期的修订叙述或前后对比；被替换的决策写成当前决策，被取代的事实删除。过程由版本控制与会话承载。`skills/dsh-spec-skill-forge/SKILL.md` 的 § Record 与 § Verification（**Complete**）承载该规则。锻造技能自身的记录在这次变更中去掉了过程叙述；上述事实是每条记录下次更新时的目标，记录从未承载的事实不虚构补写。

## 备选方案

- **保留过程日志。** 它会重复 Git 与提交信息已经承载的变更历史，第二份记录会与设计漂移。
- **在记录旁保留单独的过程日志。** 它会恢复锻造记录规则所排除的第二状态库。
- **只改写未来的记录、保留既有记录。** implemented 笔记是当前状态文档；陈旧记录仍会错误，而且会被后来者当作先例复制。

## 后果

- 锻造记录读起来是设计的当前状态，每一句话都可以信任。
- 既有锻造记录去掉轮次、会话与验收叙述；决策、备选方案与证据保留。其 `.zh.md` 与 `.i18n.yaml` 伴随文件随源改写并重录。
- 该规则是行文与判断：没有脚本裁决记录是否陈述当前事实；由评审执行。
