# Agent Note: 委派是能力选择，不是技能依赖

Status: implemented

[English](2026-11-17-delegation-is-a-capability-choice-not-a-skill-dependency.md) | 中文

## 问题

两个交付技能把 subagent 写成整篇文档翻译和宽泛简化调查的唯一路径。harness 并不保证每个采用者都提供 subagent、并行执行或隔离上下文。把其中任一机制写成必需，就会把一个可选的执行能力变成安装前提，并阻止合法任务完成。反过来完全删除隔离要求也是错误：独立生成或审查可以是质量边界，静默丢掉它会得到自信但无效的结果。

## 决策

技能陈述所需结果以及需要保留的隔离或覆盖性质。subagent、并行执行和隔离上下文是可选机制，不是安装要求。宿主提供适用机制时，技能可以使用；没有时，使用仍能保留该性质的等价路径：有界顺序处理、干净上下文交接、分阶段独立审查或其他可验证方式。如果没有任何等价路径能保留必需的质量边界，就停止并交接，明确缺少的能力、已完成工作和剩余工作；不得把静默降质的结果当作完成。

本笔记拥有技能必需结果的可移植性。[委派交给 harness 与提示词](2026-09-23-delegation-follows-the-harness-and-the-prompt.zh.md) 继续拥有仓库级规则：技能不规定载体阶梯。带明确回退的能力偏好不是载体选择协议。

评估场景作为开发资产位于 `tests/skill-evals/`。执行 eval 时，把它们暂存到临时技能副本中的官方 `evals/` 路径。交付的 `skills/` 树及其 `.agents/skills/` 安装镜像都不包含 eval 清单或夹具输入。

Eval 覆盖按可证伪行为选择，而不是按技能数量机械补齐。若真实提示能够证伪一项核心自然语言行为，且确定性检查无法裁决，就增加开发侧场景。能力分支同时覆盖两个 profile。机械契约继续使用单元或集成测试，模型 eval 在归属行为变化时运行，不进入例行 CI。

## 验证

2026-11-18 的六次干净上下文 agent 运行针对开发侧场景语料验证了能力 profile。

| 场景 | 观察证据 |
|---|---|
| 无隔离的翻译局部更新 | 对侧文件直接更新，`translate-pair write` 与 `check` 均退出 0，没有使用 subagent |
| 所有独立机制都不可用时的整篇翻译 | 没有改动任何配对文件，交接明确给出源、目标语言、已完成工作、待完成工作、缺失机制和下一命令 |
| 有隔离上下文的整篇翻译 | 一个隔离 agent 生成完整对侧文件，父上下文的 `translate-pair check` 退出 0 |
| 无隔离但证据可分离的简化调查 | 运行时与文档在不同阶段调查，各自保留消费方证据与被否决替代方案 |
| 必须隔离领域证据的简化调查 | 保留运行时证据，并对未验证的模块可达性交接可恢复的下一步 |
| 有隔离上下文的简化调查 | 三个干净上下文分别调查运行时、文档和测试，合并结果保留每个领域的证据 |

[能力场景测试](../../../../tests/skill-scenarios.test.ts) 验证场景语料、包含关系与临时暂存。[仓库形状测试](../../../../tests/repository-shape.test.ts) 拒绝分发树中的 `evals/` 目录。语料门禁还会把 `tests/skill-evals/**` 从翻译发现中排除，因此仓库检查仍只报告维护中的 39 对文件。

## 备选方案

- **保留强制 subagent 路径。** 这会破坏独立安装，并把宿主能力缺口变成任务内容失败。
- **删除所有 subagent 提及。** 这会丢掉可用的隔离上下文路径，并在宿主提供隔离能力时削弱独立审查。
- **新增中央“何时使用 subagent”阶梯。** 这会复活既有委派决定撤销的、依赖部署形态的协议。
- **把所有当前上下文内的执行视为等价。** 这会允许静默降质和虚假完成。
- **要求项目声明可用能力。** 这会增加配置负担，并违背“缺少项目声明是有效状态”的规则。
- **要求用兄弟技能作为回退。** 这会把安装依赖换一个名字重新建立。
- **把 eval 语料放在每个技能内分发。** 这会让每个采用者安装本仓库的开发提示与夹具。临时暂存既保留官方 eval 布局，又不改变交付技能。

## 后果

- 没有 subagent 的宿主可以通过可验证路径完成局部任务，或对需要隔离的任务得到明确交接。
- 有能力的宿主保留隔离上下文偏好，但不规定 subagent 数量、深度或工具名。
- 两个受影响技能在仅用于开发的场景语料中携带能力缺失和能力可用的场景，执行 eval 时才暂存。
- 分发与安装仍只包含运行时技能资源。
- Eval 覆盖与非机械行为的风险保持比例。其他技能只在自身可证伪行为变化时增加场景，而不是为了让每个技能都携带 eval 目录。
- 锻造流程要求依赖能力的技能记录能力可用与能力缺失两类结论。
