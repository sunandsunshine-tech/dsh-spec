# Agent Note: 兄弟技能引用只点名机制，不搬运实现

Status: implemented

[English](2026-11-17-sibling-references-name-a-mechanism-not-its-implementation.md) | 中文

## 问题

技能可以独立安装，因此兄弟技能名只是可选示例，不是依赖。部分引用还携带了兄弟技能的精确章节、记录位置、调用策略或输出细节。把兄弟技能替换为项目内的同类机制后，指令本身就会改变，示例因此把行为倾向到某一种实现。

## 决策

技能只有在完整陈述通用要求之后，才能把另一个技能作为可选示例点名。括号只包含可用性和技能名，并使用两种既定形式之一。兄弟技能的章节、路径、命令、参数、记录格式、输出位置、内部顺序和调用策略仍属于该技能。项目替换为同类机制后，要求必须仍然成立。

description 与 compatibility 不点名兄弟技能。`scripts/verify-sibling-references.ts` 检查这些元数据以及入口和参考文档的可见文本；`scripts/verify-corpus.ts` 将它作为语料门禁运行。

## 备选方案

- **删除所有兄弟技能名。** 这会失去可发现性，也不能阻止其余行文继续泄露实现。
- **允许括号内携带简短目的。** 这曾让部分引用更易读，但目的会带出兄弟技能的事实，并使可选示例看起来像约定的一部分。
- **只依赖评审。** 语义泄露仍需评审，但缺少稳定的机械检查曾让多种具体形式持续漂移。
- **把本仓库策略放进随包的技能规范门禁。** 该规范门禁服务所有 Agent Skill 采用者；兄弟引用策略属于本仓库的语料门禁。

## 后果

- 谨慎的引用仍可发现，安装不同技能子集的采用者仍能遵循通用要求。
- 门禁能拦下未限定名称、括号细节和元数据中的兄弟技能名；跨句流程泄露和“notes companion shape”这类隐式别名仍由评审发现。
- 本决策部分取代 [锻造 dsh-spec-code-review](2026-10-28-forging-dsh-spec-code-review.zh.md) 中的 R12；该记录回链本决策并陈述当前规则。
- 技能入口与安装副本在同一变更中修改。
