# Agent Note: 技能默认值无需项目指令也能完成

Status: implemented

[English](2026-11-17-skill-defaults-complete-without-project-instructions.md) | 中文

## 问题

在使用位置声明默认值，能让该值紧邻使用它的行为。一个技能即使还会读取项目的常驻指令（standing instructions），仍可能让没有指令的状态含糊不清：执行者可能把沉默视为缺少配置、让用户选择默认值、新增 `AGENTS.md` 来记录默认值，或再建一张默认值表。这些应对方式会让临时项目依赖它并不需要的配置，并重新引入就地声明本可避免的漂移。

当有效调用未指定某个默认值、且现有项目指令未作规定时，有六个技能会依据该具体默认值选择行为。它们是 `dsh-spec-agent-notes`、`dsh-spec-translate-docs`、`dsh-spec-pr-description`、`dsh-spec-prose-standard`、`dsh-spec-merging-stacked-prs` 和 `dsh-spec-skill-forge`。它们的具体值早已位于各自的使用位置，但共享的执行规则并非如此。

当一个技能为一项有界工作激活另一个技能时，默认值还需要组合边界。把所有已安装技能的默认值当作一个全局集合，会让无关值跨任务泄漏，并重新形成对可选技能的依赖。完全忽略被激活技能的默认值，又会迫使调用方复制兄弟技能的使用处取值。

## 决策

具体默认值仍保留在各自现有的使用位置。没有集中的默认值表。

每个带默认值的技能都携带一个 `## Defaults` 段落，并表达同一项约定。默认值是技能在自己使用处声明的值或策略。当有效调用未指定该选择、且现有项目指令未作规定时，默认值生效。用户轮次或显式调用参数提供一次性值。持久覆盖在现有项目指令中陈述，只能读取，不能重写或复制。缺少项目指令是有效状态，不应让用户选择默认值，也不应只为选择默认值而新增指令文件。该约定不豁免单独要求的输入、授权或停止条件。

同一项约定允许默认值沿真实技能激活组合。A 可以为一项有界工作激活项目内可用的 B。B 随后在该部分内按自己的顺序解析未指定选择，因此 B 的项目指令可以覆盖 B 的默认值，A 显式传入的值在 B 中属于显式输入。被激活的默认值不能解析 A 的无关选择，不能覆盖 A 的显式值，也不能让 B 成为必需。没有真实激活时，仅仅安装或作为示例点名不贡献默认值。被委托的调用只携带被委托的步骤以及调用方适用的授权和范围，B 的默认值不能授予授权或扩大该范围。A → B → C 在每条激活边上遵循同一规则。

这是 [#87](https://github.com/sunandsunshine-tech/dsh-spec/issues/87) 的使能基础，不是该 issue 的实现。#87 仍拥有 Agent Notes 的双语默认阶梯、Translate Docs 的文档所有者授权来源、目标语言可解析性、翻译失败语义和 `.agents/skills` 内容排除。本记录只说明被激活兄弟技能为何能在不成为依赖、不获得额外授权时贡献默认值。

该规则不移动也不重复任何具体值。笔记根仍位于笔记位置约定中，翻译目标与数据根仍位于配对约定中，变更描述的结构与语言阶梯仍位于该技能中，行文模式与文风指引仍位于各自的使用位置，堆叠合并的回退方案仍位于合并流程中，锻造技能的语言与记录默认值仍位于锻造技能使用它们的位置。

技能锻造的完成条件现在要求：未来每个声明默认值的锻造技能，在有效调用未指定该选择且项目指令未作规定时解析该默认值，同时仍执行单独要求的输入与授权，并满足锻造技能的 `## Defaults` 一节，包括被激活技能的组合规则。这样，该规则成为未来技能验收的一部分，而不只是现有技能恰好遵循的一项惯例。

随附脚本仍由参数驱动。它们不解析项目指令，不写入 `AGENTS.md`，也不把项目指令复制到仓库；agent 读取现有的持久覆盖，并把其中的事实作为调用参数传入。

## 曾考虑的替代方案

**创建一张集中的默认值表。** 它能让每个值都在一个地方可发现，但这张表会与使用各值的行为竞争，并在某一使用位置改变时发生漂移。本决策让每个值继续保持就地，只把共享的覆盖行为安放在每个可独立安装的技能中。

**要求 `AGENTS.md` 在技能运行前声明默认值。** 它会让选定的值变得明确，但缺少该文件并不是错误，临时项目也不需要为了使用工具而取得常驻指令。当有效调用未指定该选择、且现有指令未作规定时，默认值仍然生效。

**只把共享规则放在锻造技能中。** 未来的锻造技能会继承它，但现有的带默认值技能仍会处于含糊状态，也无法按相同条件工作。每个可独立安装的技能都需要在自己的正文中携带这项约定。

**让脚本读取 `AGENTS.md`。** 它会把覆盖的发现集中到代码中，但每个脚本都会多出一个指令解析器，并依赖一种文件格式。agent 读取现有项目指令，把得到的参数传入；脚本仍对显式输入保持确定性。

**合并所有已安装技能的默认值。** 它会让相邻技能在没有激活边时也看似可组合。翻译目标等无关值可能仅因技能被安装，就改变 PR 描述或合并行为。

**把被激活兄弟技能的默认值复制到调用方或项目指令。** 这会让值出现第二个归属方，并与兄弟技能使用处漂移。调用方必须选择该值时传入显式输入，否则由兄弟技能在被委托步骤内解析自身默认值。

**把激活当作授权。** 它会让任何调用技能仅凭调用就扩大兄弟技能的写入范围。激活只携带调用方已有的范围和授权，兄弟技能仍执行自身授权与停止条件。

## 后果

- 一个没有 `AGENTS.md` 的项目，无需先创建项目配置，就能初始化笔记、选择默认翻译目标、写入变更描述、应用默认行文模式、落地堆叠 PR（Pull Request），或锻造技能。
- 六个相互独立的技能有意携带同一段简短段落。每个安装仍保持自包含；`tests/skill-defaults.test.ts` 中的内容约定会检出共享约定段落缺失或重复，并防止任何具体值进入共享段落。
- 一次性覆盖不会重写项目指令。持久覆盖仍留在已经拥有它的项目文档中；命令把其路径或值作为参数接收，不会创建第二份副本。
- 被激活的兄弟默认值可以改善隐式组合而不建立全局默认注册表。收益只出现在调用方真实调用兄弟技能时，兄弟技能仍保持可选。
- 该规则为 #87 等后续联动技能工作提供基础，同时保留各技能的授权边界。它本身不选择双语笔记对，也不新增 Translate Docs 的授权来源。
- 这份清单不包含 `dsh-spec-agents-md`，其默认目录位置仅在获得授权的 AGENTS 写入任务开始后才适用；也不包含 pre-push 报告的 `HEAD` 等参数默认值：两者都不会依据缺失的项目指令选择 agent 行为。
- [锻造决策记录](2026-10-27-forging-dsh-spec-skill-forge.zh.md) 拥有未来技能验收条款，[翻译决策记录](2026-10-28-forging-dsh-spec-translate-docs.zh.md) 拥有翻译默认值当前的放置位置。两者都受本记录部分约束，并继续有效。
- 行文与锻造规则作为内容约定接受检查，而不是由可重复的 agent 行为 harness 执行。干净上下文演练覆盖了持久覆盖发现和被激活兄弟默认值，脚本的无指令路径已有 fixture（测试前置数据）覆盖；在这些路径之外执行行文约定时，仍依靠评审背书，而非机械证明。
