# Agent Note：技能选择只有一个详细归属地

Status: implemented

[English](2026-11-20-skill-selection-has-one-detailed-home.md) | 中文

## 问题

采用方需要依据安装条件、推荐配套技能、常用组合和跳过规则来选择技能子集。根 README 如果承载这些细节，就会变成一套与包的快速入口争夺职责的目录。把材料放回每个技能旁的 README，又会重建技能集合已经移除的分散介绍。

## 决策

根 README 继续承担采用入口。它列出通用起始组、映射五个按需分组、概括来源，并链接到 `docs/choosing-skills.md`。

该指南是各组职责、推荐配套技能及其作用、常用组合、项目级安装流程、能力要求和跳过规则的唯一详细归属地。它维护为英文与中文配对文档。

通用组作为一个整体安装。组内五项技能共同覆盖日常 agent 工作中反复出现的提示词、常驻指令、决策、持久性文字和翻译职责；因此 `dsh-spec-translate-docs` 不以项目已经维护配对文档为安装条件。这是「避免安装项目尚未使用技能」规则的有意例外；为了一个覆盖常见协作文档的小型共同基线，项目接受相应更新负担。推荐配套技能仍是可选补充，每个技能保有自己的触发、边界和完成路径。

## 曾考虑的替代方案

**在每个技能旁恢复 README。** 这样每个技能都有本地页面，却把同一次比较分散到整个目录，并为每个技能目录增加一组需要维护的配对。

**把完整目录留在根 README。** 这样不需要第二份文档，却把安装条件和配套矩阵塞进项目的第一印象，并与快速入口重复。

**为每个采用者分组创建一页详细文档。** 每页可以更短，却为一个选择决定制造五个需要协调的归属地，新增技能时还要同时修改多页。

**把推荐配套变成依赖。** 每个工作流可以只有一条安装命令，却阻止独立采用，并让可选机制成为无关任务的失败条件。

**把通用组缩减为项目已经使用的能力。** 这样首次安装更小，却要求采用方预判哪些日常指令和文档工作将会出现，并漏掉那些让 `AGENTS.md` 指令和决策记录保持可读的配套技能。

## 后果

- 新采用者从一份简洁 README 和一个通用安装命令开始。
- 分组安装会在第一个失败的技能处停止，但不会在调用方 shell 中启用 fail-fast 模式。
- 专项技能从唯一一份双语详细指南中选择，而不是从冗长目录中推断。
- 通用组安装时不需要逐个判断技能是否适用，专项技能仍可选用。
- 普通评审请求安装 `dsh-spec-pr-description`；只有项目使用 GitHub 官方 stacked PR 工作流时，才加入 `dsh-spec-merging-stacked-prs`。
- 新增或移动技能时，需要同步更新 README 的分组表以及指南中的分组、来源和配套技能说明。
- 采用方文档门禁会检查五组技能划分、README 安装代码块与通用组的一致性、固定的通用组成员、专项组按需安装、普通 PR 与 GitHub 官方 stacked PR 的推荐边界、本地链接以及中英指南结构。
- [整套技能不在每个技能旁放 README](2026-09-21-the-skill-set-is-introduced-once.zh.md)继续维护这条决定，并在此链接当前的总览与细节分工。
