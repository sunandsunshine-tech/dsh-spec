# Agent Note: 实质工作从提案开始

Status: implemented

[English](2026-11-25-substantial-work-starts-as-a-proposal.md) | 中文

## Problem

issue 可以说明还剩哪些工作，却不适合保留设计理由、替代方案、验收条件与风险。单独的 work record 只会再增加一个状态存储。缺少清晰分工时，agent 要么把设计埋进 issue 评论，要么把尚未合入的 draft 当作有效指导。

## 决策

实质未来工作从 proposed Agent Note 开始。Agent Note 拥有问题、设计、替代方案、验收条件与风险。项目的执行跟踪器拥有依赖、状态、已完成与待办证据以及下一个检查点；双方互相链接，而不是复制完整设计。

只存在于工作树、Draft 变更或未合入分支中的提案不计入有效清单。提案一经保留在目标分支的 `proposed/` 下，就会在那里可被发现，并可指导实现。实现缺失或仅完成一部分时，提案保持 proposed；到完整检查点时，当每一项已获认可的验收条件都已交付并验证，该 Agent Note 作为拥有者移动到 `implemented/`。

不存在单独的 work-record 产物；没有任何重复的常驻指令（standing instructions）资产重述本工作流。现有[移除 work record 的决定](2026-09-18-drop-the-work-record.zh.md)继续拥有该约束及其经测量的重新引入条件；本记录分配设计与执行角色以及完整／部分检查点规则。

跟踪：#133。

## Alternatives considered

**把完整设计、替代方案和状态都放进 issue。** 这避免额外文件，却把易变执行视图与持久理由混在一起，并失去 Agent Note 生命周期和双语单元。

**在没有新证据的情况下重新引入 work-record 文件。** 它提供一个查看状态的位置，却复制 issue tracker 和提案验收条件，并要求每次变更维护另一个状态源。移除决定只有在满足其经测量的接续条件后，才允许重新引入。

**把分支上的 Draft Agent Note 当作有效指导。** 这避免合并，却让未提交清单取决于后续会话碰巧看到哪个分支。

## 后果

- 每项实质未来变更都有一个提案负责设计、一个执行跟踪器负责状态与证据。提案与跟踪器条目互相链接；issue 评论可以说明进展，但不会成为第二个设计权威。
- 提案只有在保留到目标分支上后，才进入有效清单。分支本地的草稿不能让实现取决于后续会话碰巧看到哪个分支。
- 生命周期迁移在同一变更中改写状态、骨架、完整单元与入站链接。部分工作保持 proposed，并记录其剩余且已获认可的范围。
- 小型变更可能承担不必要的 Agent Note 开销；现有“持久决策理由”触发条件仍决定是否需要记录。如果实现未经检查点就落地，issue 与提案可能漂移，而被放弃的提案必须按 Agent Note 生命周期否决或删除。
