# Agent Note: 草稿 PR 在 head 就绪前跳过 CI

Status: implemented

[English](2026-11-27-draft-ci-skips-until-ready.md) | 中文

## 问题

在草稿 PR（Pull Request）的每次中间推送中运行完整的 GitHub 检查套件，会消耗远程 runner，并让评审人等待将被后续提交取代的结果。若把缺失或已被取代的结果当作通过证据，反而会掩盖门禁本应发现的那些远程失败。

## 决策

向草稿 PR 推送的中间提交默认在提交消息中携带 `[skip ci]`。`[skip ci]` 不是通过结果：被跳过的工作流没有在该 head 上运行，不能提供完整的远程检查证据，也不得被引作证据。

只有在确切的草稿 head 当前需要远程 CI 作为证据时，才移除 `[skip ci]`。在将 PR 标记为就绪之前，推送一个不带 `[skip ci]` 的新 head，并要求完整检查套件在那个确切的 head 上成功。

已知失败、CI 工作流或配置变更，以及无法在本地复现的集成边界，都需要一次真实的远程运行。它们不会被跳过、延后，也不会被当作已覆盖。

本仓库的 GitHub 操作规则位于 [`CONTRIBUTING.md`](../../../../CONTRIBUTING.md#draft-pull-requests) 和根目录 [`AGENTS.md`](../../../../AGENTS.md)。它属于本仓库的 GitHub 工作流，不进入随包交付的 pre-push 技能。

## 曾考虑的替代方案

**每次草稿推送都运行完整 CI。** 这会提供即时的远程反馈，但在评审人等待期间，大部分结果都会被取代，远程容量也会被消耗。

**在合并前只把本地检查用作证据。** 本地检查能发现仓库回归，但无法确立 GitHub 工作流配置或远程集成行为。

**在就绪 head 上保留 `[skip ci]`。** 被跳过的 head 没有完整的远程检查结果，因此将其标记为就绪会声称一项并未发生的检查。

**在已知失败或集成边界上依赖本地检查。** 本地套件通过并不能确立远程失败或工作流边界；这些需要真实检查。

**把规则放进随包交付的 pre-push 技能。** 本包服务于 GitHub 草稿 PR 之外的项目，因此把 GitHub 专用跳过规则放在那里会约束无关的采用者。

## 后果

- 草稿 PR 的中间推送无需等待将被下一次提交取代的完整远程套件。
- 被跳过的 head 保持明确的未评估状态，而不会被描述为通过。
- 就绪 head 不携带 `[skip ci]`，并且针对其确切提交拥有完整的远程检查证据。
- 已知失败、工作流变更和集成边界无法藏在跳过之后。
