# Agent Note: 人类语言跟随当前用户的偏好

Status: implemented

[English](2026-11-27-human-language-follows-current-user-preference.md) | 中文

## 问题

提交主题规则把约定的 `type(scope)` 标记与面向人的摘要分开，却没有说明由谁选择该摘要或其他 Git 与 GitHub 文字使用哪种语言。仓库历史、账户归属以及最近的 pull request 序列都不是当前用户语言偏好的证据；若用它们来选择语言，就会把偶然的上下文变成策略。

## 决策

人类可读的 Git 与 GitHub 文字可使用中文或英文。提交主题中面向人的部分、提交消息正文，以及 pull request 标题和正文，都应使用当前用户偏好的语言。

`type(scope)`、固定的 pull request 标题标记和结构标题、代码标识符、命令、API、路径和机器可读字段，都应保留为仓库要求的形式或英文形式。无论人类可读文字使用哪种语言，工具与评审人都依赖这些形式。

账户归属不能确立语言偏好。PR 作者、issue 作者、历史比例、最近的 pull request 以及优先级阶梯都不能决定当前用户使用哪种语言；当前用户的偏好决定。

[squash 提交主题由非合并提交数量决定](2026-11-26-squash-subjects-follow-the-non-merge-commit-count.zh.md)仍对主题来源、跟踪器后缀处理和 DCO trailer 具有权威性。本记录以当前用户的偏好取代那篇记录关于语言的结论，同时使其主题和 trailer 规则继续有效。

## 曾考虑的替代方案

**要求人类可读文字使用中文。** 这会把某一时期的仓库做法规定为强制规则，并剥夺当前用户选择英文的能力。

**要求人类可读文字使用英文。** 这会拒绝一种同样有效的用户偏好，并在需要英文的机器可读形式之外强制使用英文。

**根据账户归属或历史推断语言。** PR 作者、issue 作者、先前的提交或最近的 pull request 序列，都不能确立当前用户偏好什么。

**对 issue、领域和近期改动使用优先级阶梯。** 额外证据不能取代当前用户的选择，还会让一项简单的偏好看起来像语言检测算法。

**翻译每个固定字段和标题。** 机器可读字段和共享结构需要稳定形式，供工具与评审使用，因此只有人类可读文字跟随用户偏好。

## 后果

- 贡献者可以按照当前用户的偏好，在人类可读的 Git 与 GitHub 文字中使用中文或英文。
- 约定标记、固定结构标题、代码形式、路径和机器可读字段在不同语言下都保持稳定。
- 账户归属和历史模式不会被当作语言偏好的证据。
- 没有自动门禁评判人类可读文字使用哪种语言。
