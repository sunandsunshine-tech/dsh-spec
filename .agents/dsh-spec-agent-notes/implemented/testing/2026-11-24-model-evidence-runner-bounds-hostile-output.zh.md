# Agent Note: 模型证据运行器将模型输出视为不可信内容

Status: implemented

[English](2026-11-24-model-evidence-runner-bounds-hostile-output.md) | 中文

## Problem

模型证据运行器让模型控制的文本和进程可以访问项目命名空间。允许的 catalog 字符串中嵌入的凭据可能跨入该命名空间，模型创建稀疏或稠密文件的速度也可能快过宿主机的检查速度。因此，仅靠 stdio 字节上限，无法约束最终响应、保留的产物、Git 检查或哈希计算。

## Decision

凭据类查询名称会忽略大小写和分隔符差异进行归一化。`authkey`、`authkeyid`、`clientsecret` 和 `subscriptionkey` 等复合键名一律采用失败即拒绝的策略。catalog 字符串中的每个候选 URL 都会按绝对 HTTP(S) URL 校验，并且既不得包含 userinfo，也不得包含凭据类查询参数。格式错误和不支持的 URL 形式都会失败，不会依据解析器消息文本进行路由。

模型可写目录都是设有上限的 tmpfs 挂载：工作区 512 MiB，Codex home 64 MiB，响应目录 8 MiB，home 目录 128 MiB，临时文件 512 MiB。Codex 启动前，包装器会把一份只读种子复制到工作区和 Codex home。受信任的 Git 目录和已安装技能仍作为只读叠加层。

包装器持有一个仅支持单次连接的 Unix socket，上报模型的退出状态，终止其 PID 命名空间中的剩余进程，并在宿主机通过 `/proc/<child-pid>/root` 复制工作区和响应目录期间持续等待。宿主机的结果目录不会挂载到模型命名空间中。模型以非零状态退出时，会跳过最终响应和产物处理。

最终响应上限为 2 MiB。每个产物上限为 16 MiB；文件至多 256 个，总量至多 64 MiB。在读取、复制或保留文件之前，系统都会检查其逻辑大小，因此也会拒绝 tmpfs 块配额未计入的稀疏文件。哈希计算通过 64 KiB 缓冲区流式进行，并受独立的字节上限约束。

## Verification

`tests/runner-safety.test.ts` 覆盖凭据名称、内嵌及格式错误的 catalog URL、精确的最终响应上限与产物上限、流式哈希的内存占用、有界目录树复制、生成的 tmpfs 参数、真实的 bwrap 工作区配额、真实的模型运行器成功路径，以及一个会创建超限输出并失败的模型。`tests/skill-scenarios.test.ts` 验证历史证据辅助程序会忽略所有继承来的 `GIT_*` 变量，并验证 PR #121 证据仍绑定到其记录的修订，而不会被描述为当前行为。

## Alternatives considered

**直接绑定宿主机上的工作区、Codex home 和响应目录。** 这会保留旧数据流，但在任何运行后检查执行之前，稀疏文件就可能超出宿主机文件系统容量。

**仅依赖 tmpfs 配额。** tmpfs 限制已分配的块，并允许稀疏文件的逻辑大小远超配额，因此仍需进行宿主机侧的逻辑大小检查。

**按消息文本对 URL 解析错误分类。** 解析器文本不是稳定的安全判别依据；无论抛出的错误文本是什么，格式错误和不支持的 URL 都必须失败。

**在判断文件是否符合限制之前，先读取并计算完整文件的哈希。** 这一判断会消耗它本应约束的资源。大小检查先于分配，哈希按固定大小的块流式计算。

**为收集结果而挂载宿主机结果目录。** 模型可能直接写入保留结果的区域。将结果目录留在命名空间之外，并通过一条退出后的私有控制路径进行复制，可以保留一个有界的结果收集点。

## Consequences

- 模型分配的资源不能超过所声明的工作区、home、响应和临时文件配额。
- 符合块配额但超出逻辑输出上限的稀疏文件，会在 Git 或产物处理之前失败。
- 模型即使没有失败，只要生成了超出上限的最终响应或产物，宿主机仍会在保留这些输出之前将其拒绝。
- 运行器依赖 `bubblewrap --size` 以及 Linux 的 `/proc` 命名空间视图。
- 证据语料仍需评审人评级；这些资源保证不会使模型 trace 成为执行证明。
