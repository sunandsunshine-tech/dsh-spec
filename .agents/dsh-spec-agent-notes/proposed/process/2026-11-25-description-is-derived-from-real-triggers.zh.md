# Agent Note: description 从真实触发条件派生

Status: proposed

[English](2026-11-25-description-is-derived-from-real-triggers.md) | 中文

## Problem

技能 description 在技能正文之前加载，是模型决定是否读取该技能时唯一可见的目录文本。列出有吸引力的关键词、重复一个开放式模板，或宣传正文没有提供的行为，会造成误报，并掩盖该技能真正服务的时刻。

## Proposal

锻造或重构出的 description 从四项事实派生：

- 技能的实际角色；
- 应触发它的任务时刻和对象；
- 它排除的相邻场景；
- 从上游来源保留的任务族。

description 保留这些来源任务族，但不复制上游产品名称或不受支持承诺。它不使用固定的开放式枚举句式（例如“覆盖 A、B、C 等”）来填满目录预算。字符上限是约束，不是目标，也不是增加主题的理由。

触发验收同时使用应加载技能的正例和不应的近失例。这一组必须区分边界，而不是只证明宽泛的性能或评审语言会引起选中。

跟踪：#132。

## Alternatives considered

**在目录上限内把 description 写得越长越好。** 它能在加载前暴露更多词，但新增名词往往制造误报，却没有让实际角色更清楚。

**复制上游 description，只替换产品名称。** 它保留来源，却携带产品专属表述，并可能声称通用化正文已不支持的触发条件。

**为每个技能使用一个固定模板。** 它让评审形式统一，却迫使无关技能套入关键词清单，鼓励复制目录文案，而不是如实陈述角色。

## Acceptance criteria

- description 用正文自身的术语陈述角色、正向触发边界和重要排除范围。
- 每个保留的来源任务族都有对应当前能力，或记录了被排除的理由。
- 除非已加载技能提供该行为，否则不宣传它。
- 变更 description 时记录正例和近失例触发评估。
- description 保持仓库目录预算，且只使用 BMP 字符。

## Risks

- 小型触发集可能过拟合一种措辞，漏掉另一种自然请求。
- 复合技能可能拥有真实但较宽的角色，其边界比单源移植更难表述。
- 通过触发评估只证明选定示例，不代表通用路由准确率；评审仍需检查措辞是否与正文一致。
