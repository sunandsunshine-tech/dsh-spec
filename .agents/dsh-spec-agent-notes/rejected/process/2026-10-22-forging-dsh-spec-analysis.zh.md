# Agent Note: 把 dsh-spec-analysis 锻造成四产物对象分析方法

Status: rejected — abstract meta-method prompts do not converge stably; concrete prompts win until the method can be formally checked

[English](2026-10-22-forging-dsh-spec-analysis.md) | 中文

## Problem

本仓库随附技能锻造与 agent team 工作流，却没有一套分析并重构复杂对象的可复用方法。一次设计对话推导出该方法，但最初的几次锻造在三个方面不符合锻造技能：只陈述步骤，没有可断言的产物；抽出一份由多个步骤共享的 reference，而步骤的完成判断依赖它；把自我分析单独呈现，而分析本身已经包含它。驾驶员的审查给出四产物叙述并修正了抽取方式。本记录覆盖最终的锻造。

## Proposal

把 `dsh-spec-analysis` 锻造成恰好产出四件产物的 Skill：对象定义、带归属断言的要素、重组方式（关系与规则及其判断断言）、评判标准。正文保留层与步骤顺序；六个 SOP 步骤各自阅读一份 reference，其中承载该步的内容、完成判断、检查方法、失败恢复与产物格式。工作记录保存框定、情形、裁定与断言证据，它不是第五件产物。技能不带 script。

锻造采用采用者默认值：工作草稿用交付语言（英语），description 带中文触发；审查草稿用采用者语言（中文），带英文触发；记录为本 Agent Note；落地目标是 `skills/dsh-spec-analysis/`。来源是题为「Agent编排本质与组合」的共享对话；本记录引用它，被锻造的技能不引用。与本文相关的内容已直接内联在这里，因此记录不依赖链接：

- 锻造是一种元方法，而不是一组写作步骤：先定义对象是什么，识别它的 Docs、SOP、Script，处置它的约束，重组它，断言结果，再按结果修正。
- 可迁移的序列是：理解对象、识别要素、分析并处置、重组、断言、修正。把对象换掉（技能、工作流或任何可结构化对象），序列仍然成立；迁移的是元方法，不是某个领域的具体流程。
- 稳定性改变契约：稳定的交付物可以预先定义结构，而动态对象只固定方法，把每一次具体安排留给情境。
- 四件产物、对象范围以及精度和抽取方面的修正由驱动者给出；它们属于本记录自己的裁定，不是对话的主张。

### Collection

- **Docs。** 来自对话：分析、本质、定义、要素、归属、关系、规则、重组与评判的定义；驾驶员第二次审查的四产物叙述；第三次审查的范围、格式、精度与干净测试要求；第四次审查的自我分析与抽取修正。来自仓库：notes 契约、Agent Skills 规范、锻造技能的组成规则。
- **SOP。** 六步方法：框定、定义、分解、推导关系与规则、建立标准、组装并断言。上游提供步骤，驾驶员提供四件产物与输出纪律。
- **Script。** 无。方法的工作是判断，产物没有通用 schema，因此没有确定性检查器；适用锻造技能的「无 Script 时跳过并记录」分支。
- **未收集的线索。** 对话早期的编排部分服务于姊妹工作流锻造，不是本技能；工作流标准背后的闭环文献未被查阅；Agent Skills 规范只用于触发约定。它们都不能再改变本技能的设计。

### Deconstruction units

- **U1，对话第 62 条与驾驶员第二次审查。** 分析方法的序列：识别本质与对象解决什么，推导定义，把它分解为要素，分析并处置约束，重组，断言，并在结果要求时循环。目的：可断言的分析产物，而不是散文。覆盖 C1–C5。
- **U2，对话第 62 条与驾驶员第一次审查。** 方法是独立的元技能，不是工作流技能的一部分；工作流技能可以在意图阶段使用它；分析深度随所服务的决策调整。目的：两个技能保持独立，深度成比例。覆盖 C6–C8。
- **U3，驾驶员第三次审查。** 对象范围是所有可结构化、可断言化的事物；行文遵守仓库格式；精度达到锻造技能的级别，并用一个分析「技能」对象的干净测试来验证。目的：通用、精确、经过验证的方法。覆盖 C9–C10 与 C12。
- **U4，驾驶员第四次审查。** 自我分析不得单独呈现；抽取必须遵守锻造技能的 resource 规则。目的：不泄露抽象，不拆出必需的 reference。覆盖 C11–C12。
- **U5，仓库声明与锻造默认值。** 记录是 Agent Note；交付英语、审查中文、附加触发中文；script 只用于确定性工作；四产物及其记录的落位。覆盖 C13–C16。

### Verification

`node skills/dsh-spec-skill-forge/script/verify-skill-spec.mjs .agents/dsh-spec-skill-forge/draft/dsh-spec-analysis --strict-budget --name-max 64 --description-max 1024 --compatibility-max 500 --max-lines 500 --max-tokens 5000 --cjk-tokens-per-char 0.6 --other-tokens-per-char 0.3` → 10 项检查，0 失败，85 行，约 2,614 tokens；严格预算通过。六份步骤 reference 在正文中被点名，每步读一份，且只有一层深度。

锻造符合性，直接检查：正文带有触发（description）、技能定义与边界、全局释义、全局准则、SOP 步骤与成果断言，没有空层或多余层；每一步需要的材料在该步自己的 reference 中；字段表只有一个归属（其步骤 reference），正文不重复；格式用列表与表格承载条件与分支；记录遵守 `AGENTS.md` 与 notes 契约；语言遵守交付/审查/附加触发的规则；不声称 script。

驾驶员要求的干净测试用只加载工作草稿的新 agent 运行了两次。两份报告发现同样的缺陷，本稿已修复：`clause` 与 `part` 已定义；框定与裁定留在工作记录中，不再作为产物；深度改变细节，不改变数量；字段表只有一个归属；归属是结构性的，质量属于标准；无法查阅的规范被标为未验证；独立的自我分析表面被移除。两个 agent 对技能对象推导出的模型（选择面、指令正文、按需资源）在这些要素上与锻造技能对同一对象的模型一致；锻造技能的 Docs/SOP/Script 组成与处置机制是刻意的差异，在这里按驾驶员的四产物叙述被解除。

对正文与六份 reference 的格式审计报告：表格外没有分号串联，表格列数一致，没有行尾空白。外部触发质量、冷启动与代表性任务效用仍未验证，因为本环境没有为技能的目标受众安装该技能的 harness。

Note 门禁也通过：`translation-pair check` 报告两条锻造记录一致，`notes check --all` 报告 26 条记录结构一致，`md-links check` 解析四份记录文件。

### Review and landing

四次审查修正塑造了这次锻造。第一次提高精度并缩短名称。第二次给出四产物叙述。第三次放宽对象范围、要求格式规则并要求干净测试验证。第四次要求移除自我分析表面，并让抽取遵守锻造技能的 resource 规则。审查草稿在 `.agents/dsh-spec-skill-forge/review/dsh-spec-analysis/`，中文正文加英文触发，六份步骤 reference 也投影成中文。它提交给驾驶员，等待接受、修改或否决。落地把工作草稿复制到 `skills/dsh-spec-analysis/`，只删除本技能的草稿与审查目录，并把本 note 移到 `implemented/`。

## Alternatives considered

**抽出一份由多个步骤共享的产物 reference。** 它落败，因为步骤完成判断需要的 reference 不是可选的；锻造的 resource 规则要求步骤的内容随步骤移动，所以现在每一步有自己的 reference。

**把自我分析作为第五件产物与示范模型单独呈现。** 它落败，因为分析本身已包含自我分析；单独一节会泄露抽象，并加入四产物所禁止的产物。

**保留例子清单式的对象范围。** 它落败，因为驾驶员的范围是所有可结构化、可断言化的事物；清单现在只作说明，不作限制。

**保留分号串联的句子。** 它落败，因为仓库格式规则要求条件、分支与流程用列表或表格。

**把干净测试报告当作可选验证。** 它落败，因为它们暴露了定义、框定、深度与字段表缺陷，而这些正是锻造的精度检查会漏掉的。

**携带锻造技能的 Docs/SOP/Script 分类作为要素模型。** 它落败，因为驾驶员从定义推导要素，而不是从通用分类。

**每次调用都规定完整仪式。** 它落败，因为深度跟随所服务的决策。

**附带结构检查脚本。** 它落败，因为定义、归属条件或评判标准没有通用 schema。

## Acceptance criteria

- 工作草稿以给定参数通过 `verify-skill-spec.mjs` 的严格预算。
- 审查草稿把正文与六份 reference 转写为中文且不引入新概念，驾驶员接受它。
- 落地后 `skills/dsh-spec-analysis/` 等于被接受的工作草稿，本 note 位于 `implemented/`。
- 正文只保留层与步骤顺序；每一步读自己的 reference；没有 reference 被某步的完成判断所需要却住在别处。
- description 在任何可结构化对象的分析时触发，在结构已定的局部修改时不触发。

## Risks

- 宽泛的对象范围可能让普通阅读或摘要任务误触发；description 的「分析与重构」条件与「不用于局部修改」一行降低风险，但触发质量尚未验证。
- 定义先行的纪律要求高；弱模型可能满足于描述。失败模式与等价断言针对这一风险，但不能消除它。
- 六份步骤 reference 是六次可能的加载；正文只给顺序与断言，不给字段表。这是预算路由的有意代价。
- 没有脚本检查产物；过宽的定义或缺失的归属条件只能由第 6 步发现。
- 落地会把一个新的通用技能带入一个其他已交付技能都可追溯到上游的包；本记录是这次刻意偏离的痕迹，审查是否决它的时点。
