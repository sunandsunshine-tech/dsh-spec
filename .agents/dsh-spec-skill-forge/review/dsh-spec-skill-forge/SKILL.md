# 技能锻造

## 指导原则

将任何对 AI 的期望转化为精准可判定的锚点：明确要什么（正向边界），明确不要什么（负向边界），并给出如何验证（判定条件）。方案的效力取决于锚点的精准度——无论是自然语言锚点，还是机械执行锚点。

## 工具

- `scripts/forge.mjs` —— 创建工作草稿、投影评审草稿并落地工作草稿。它的 `--help` 列出各命令与选项。
- `scripts/verify-skill-spec.mjs` —— 机械门禁。它的 `--help` 列出各项限制与选项；它逐项报告检查结果。

两者都从本技能的根目录运行。

## 界限

按 Agent Skills 最佳实践及其链接的内容撰写被锻造的技能。记录每个读过的页面及其阅读日期；某页读不到时，改读它对应的[离线回退](references/offline-skill-authoring.md)，并记录哪一页不可读。离线回退是一份提炼过的快照，不是第二权威；只要能读到在线原文，就以在线原文为准。


### 停止

只对未经授权覆盖或删除既有技能，以及环境禁止或无法撤销的操作，停下来等待。其余一切都记入记录的裁定：不提问、不确认、不展示草稿，也不等待其他任何东西。停下时，报告阻塞、已尝试的裁定和可逆的选项。

### 意图

从请求和声明中确定：名称、目标、边界、交付物、模式、位置和语言；目标受众及其领域；以及其环境的运行时、工具与约束。新建模式：从构想或上游素材提炼，并把请求中的要求作为来源。迭代模式：读取当前技能和既有记录；记录缺失即按新建处理，并记录下来。

从来源推出触发词汇与它排除的邻近任务。

确定被锻造的技能是否需要脚本：存在哪些确定性工作，目标环境提供哪些运行时和工具，采用环境能否构建并运行它，以及开发运行时与目标运行时不同时的测试路径。运行时或工具缺失是一次错误退出和一条记录在案的裁定，而不是停止。

### 来源

来源中的每条要求、禁止、条件或固定选择都是一条源约束。逐条列出，并标明其位置。把先陈述一种工作方式、随后给出具体指令的段落解构为一个单元，提取其中的步骤、决策规则、角色与结构；仅有具体规则并不构成一个段落。按目的合并重复项，同时保留每个位置。

只收集会改变设计的材料；新材料不再改变任何东西时就停止。没有上游时，请求中的要求就是来源。请求与声明都无法确认的事实成为一条裁定，即最贴合目的、改动最少且可逆的决定，并记录下来，而不是臆造。

### 处置

每个单元取第一个适用的处置：

| 处置 | 适用时机 | 动作 |
|---|---|---|
| Keep | 原文措辞与含义成立 | 带入，只调整语言与版面 |
| Adapt | 指称对象存在，只有取值不同（路径、命令、参数、上限、名称） | 用目标取值实例化 |
| Re-bind | 没有指称对象，或名称不同 | 抽象到目的，找到等价手段，再具体化为可执行形态 |
| Dissolve | 以上都不成立 | 不带入；记录目标事实、它的检查，以及接替它的东西 |

每个单元一行：源位置、处置、目标位置和依据（目标领域的事实、技能的目的、上游文本或一条裁定）。一次变更要说明保留的部分和迫使它变更的事实；一次 Dissolve 要说明接替它的检查。覆盖：每条约束各有一个单元和一个归属处；一个被解构的单元覆盖其段落陈述的每条约束；处置之间不重复、不冲突。

不要断言某项技能已安装；把含糊的示例变成一条裁定。例如：固定路径变为 Adapt；目标环境缺少的工具变为 Re-bind；指称对象已消失的规则变为 Dissolve，并记录接替它的检查。

### 脚本转换

命令能精确判定的要求变成带参数与安全默认值的脚本。只有判断才能判定的要求保持为正文，点名权威并记录一个结论；两者都不存在时，把该项记为未验证。

### 评审

评审语言与交付语言不同，或采用方要求一份只读副本时，需要评审草稿。工作草稿是唯一的权威；评审草稿是它的投影：概念与名称保持对齐，不引入新概念，也不逐字转写。

投影的出处位于 frontmatter 的 metadata 中，归脚本所有：只改正文，绝不动戳记。工作草稿发生变化时，投影被标为 stale，现有译文保留到该文件重新翻译并被接受为止。落地会拒绝缺失、过期或不匹配的投影，除非记录载明豁免理由与复查条件。两种语言相同时，投影是原样副本或不存在；落地不要求存在投影。

最终评审提交评审草稿，等待采用方接受、修改或拒绝它。

## 核验

每条要求都在可用的最精确层级上带有核验锚点；没有锚点的要求只是正文。两个执行者从同一个锚点得到同一个决定，这个锚点才算精确；决定是否保留一个锚点的是精确性，而不是锚点的数量或脚本承担的比例。

| 锚点 | 做法 | 证据 |
|---|---|---|
| 机械 | 由命令判定。 | 命令与输出 |
| 判断 | 由点名的指南或参考文件判定；每项给出一个结论。 | 每项一个结论 |
| 未验证 | 该项没有精确检查。 | 该项与原因 |

运行门禁，确保文件缺失或链接失效会导致失败；用它的严格预算让正文超限同样失败（它的 `--help` 点名该选项）。

**完成**：每条源约束都有一行处置并有其归属处；被锻造技能的每条要求都带有一个锚点；门禁按所用参数通过；每个判断项都有结论；每个未验证项都带有原因；需要评审时评审投影已被接受；记录载有证据、已读页面和裁定。

**失败**：修复后重跑；不得把失败或未运行的检查声称为通过。正文超限：把内容转到 `references/` 并重跑。无法解决的缺口：记录一条裁定。

## 记录

写到采用方的声明或既有决策记录机制指定的位置；否则写到脚本使用的锻造目录下的 `record/<name>.md`。遵循既有机制；没有机制时，记录目标、模式、设置、处置表、检查结果、评审结论、未验证项、风险和回滚点。每个决定一经确定就写入；发生冲突时记录冲突与解决方式。记录放在被锻造技能目录之外。只有一份记录：没有第二套状态存储或过程日志。

## 默认值

| 设置 | 默认值 |
|---|---|
| 交付语言 | 英语 |
| 评审语言 | 采用方的语言；没有采用方时，用请求的语言 |
| 附加触发语言 | 评审语言；与交付语言相同时，另选一种或省略 |
