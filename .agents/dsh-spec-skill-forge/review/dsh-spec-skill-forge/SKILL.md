# 技能锻造

技能锻造从请求、项目上下文或上游参考出发，创建或改写 Agent Skill。它把 Docs、SOP 和 Script 组成一个完整技能，按规范检查，形成落地产物并记录决定。它交付被锻造技能目录。安装、加载、运行或使用被锻造技能不在本技能范围内。

## 全局释义

- **驾驶员**：指挥 agent 的人。
- **采用者**：使用本技能的人，通常是驾驶员。
- **采用环境**：采用者的项目、决策记录机制、记录、语言与工具。
- **目标受众**：使用被锻造技能的人或 agent。
- **目标受众的领域**：被锻造技能服务领域的名称、惯例和术语含义。
- **目标受众的环境**：被锻造技能需要的运行时、工具和约束。
- **声明位置**：采用者或目标受众的 `AGENTS.md` 或其引用的文件。采用者的声明位置给出设置，目标受众的声明位置给出自定义值。
- **交付语言**：被锻造技能正文使用的语言。
- **审查语言**：审查草稿正文使用的语言。
- **附加触发语言**：落地产物 description 中除交付语言外的关键触发词。
- **决策记录机制**：项目已有的决策记录形式，例如笔记树、ADR 集合或决策日志。
- **Docs**：定义、事实、约束、schema、模板和参考资料。
- **SOP**：技能定义、步骤、决策规则、完成判断和失败恢复。
- **Script**：只应由代码完成的确定性工作。
- **三要素**：Docs、SOP 和 Script。
- **上游参考**：提供三要素的材料或现有技能。
- **源约束**：上游中限制被锻造技能的要求、禁止或条件。
- **处置**：对源约束的决定。
- **被锻造技能**：本次锻造产出的技能。
- **锻造目录**：记录、工作草稿和审查草稿的父目录。
- **工作草稿**：交付语言工作副本。
- **审查草稿**：审查语言副本。
- **落地产物**：最终放到被锻造技能目录的完整技能。
- **归属处**：一个定义、规则或事实被写下的唯一位置。
- **SSOT**：单一来源。
- **无歧义**：每个术语、概念和决策点只有一种解释。
- **记录**：决策依据、检查结果和交付信息的存放位置。
- **结构检查器**：目标项目提供的结构检查工具。
- **裁定**：请求或声明位置无法决定时，采用最贴合目的、改变最少且可撤销的决定，并记录。
- **硬红线**：无法在不改变环境或不动用不可逆操作的情况下继续的条件。
- **规范**：Agent Skills 规范。

## 全局准则

### 交互

除硬红线和最终审查外，锻造不提问、不确认、不展示草稿或 diff、不等待。决定只作为裁定写入记录。硬红线只有这些：

- 未经授权覆盖或删除已有技能。
- 需要修改采用者或目标受众的声明位置。
- 采用环境不允许的文件、网络或 Git 操作。
- 采用环境缺少 Script 所需的运行时或工具。
- 源目的与目标领域红线冲突。

遇到硬红线时停止，给出阻塞、已尝试的裁定和可逆选项，等驾驶员决定。其余决定作为裁定写入记录。最终审查提交审查草稿，等待接受、修改或拒绝。

### 语言

工作草稿和落地产物用交付语言，审查草稿用审查语言。

工作草稿和落地产物的 description 以交付语言为主，以附加触发语言为关键词。审查草稿相反，以审查语言为主，以交付语言为关键词。语言不同时对调，相同时审查草稿只使用审查语言。

审查草稿把工作草稿转写为审查语言。保持概念和名称对应，不引入新概念，选词符合审查语言和领域。不逐字转写。

默认值：

| 语言 | 默认值 |
|---|---|
| 交付语言 | 英语 |
| 审查语言 | 采用者语言。没有采用者时用请求的语言 |
| 附加触发语言 | 审查语言。与交付语言相同时另选或省略 |

### 锻造目录

采用者没有指定时，锻造目录是项目根目录下的 `.agents/dsh-spec-skill-forge/`。不可写时用裁定另选并记录。

### 记录

记录位置按序取：

1. 采用者的声明位置或项目已有决策记录机制指定的位置。
2. 锻造目录下的 `record/<名称>.md`。已存在时用裁定另选并记录。
3. 锻造目录不可写时，用裁定另选并记录。

按项目已有决策记录机制组织。包含目标、模式、设置、处置、检查结果、审查结论、未验证项、风险和回滚点。没有机制时用这些作标题。

每个决定确定时写入。与先前决定冲突时记录冲突和解决方式。记录不放进被锻造技能目录。只使用一份记录，不建立第二套状态、轮次文档或过程日志。

### 草稿

工作草稿是交付语言副本。它可在循环中修改，不写入最终路径，不展示。它放在锻造目录下的 `draft/<名称>/`。审查草稿放在 `review/<名称>/`，使用审查语言。结构检查和技能规范断言只对工作草稿执行。审查草稿是语言投影，不再判断。

审查草稿只在以下都成立时存在：

- 结构检查通过。
- 技能规范断言满足。
- 需要审查。

工作草稿更新时重新生成或更新审查草稿。以下任一情况移除审查草稿：

- 结构检查或技能规范断言未通过。
- 不需要审查。

自主循环中不更新审查草稿。

### 资源与归属

步骤需要的资源放在步骤内或紧邻处。整个技能需要的资源放到对应归属处：定义进全局释义，规则进全局准则，成果判断进成果断言。

只有真正可选、不参与任何步骤完成判断、能按需加载且内聚的材料才挂引用。其他材料不拆分，因为它必然随技能加载，拆分只增加引用成本。

Script 可在任何需要确定性的位置调用，不限 SOP 步骤。

### SSOT（单一来源）

写到归属处。同一内容不在两个位置重复定义或说明。归属处按内容确定：

| 内容 | 归属处 |
|---|---|
| 技能规则与步骤 | 技能正文 |
| 记录内容 | 记录 |
| 领域事实 | 记录保存工作材料 |
| 术语 | 被锻造技能在定义处定义 |
| 环境与运行时 | `compatibility` 或脚本头 |
| 默认值 | 技能 |
| 自定义值 | 目标受众的声明位置 |

每条规则只有一个权威文本。第二个权威文本即违规。

### 无歧义

每个术语一个含义，每个概念一个名称，每个决策点一种解释。日常词有多个含义时，在定义处写明并只消歧一次。有意保留的自由度说明执行者能决定什么、依据是什么。

### 格式与描述

以下是默认格式。采用者的声明位置可以覆盖。

并列词用顿号。条件、分支和流程写成列表或表格，不压进一句。结构化内容优先用表格。层内行文形式不限。标题和布局跟随内容，不用模板，也不照抄上游格式。

description 是触发条件。说明做什么、何时使用，用日常词，包含任务关键词和语言规则要求的附加触发词。

## SOP 步骤

1. 意图识别。读 `references/1-intent.md`。
2. 三要素采集分析与处置。读 `references/2-analyze-and-dispose.md`。
3. 重组技能。读 `references/3-recomposition.md`。

每个步骤的内容、完成判断、检查方法和失败恢复在对应 reference 中。它们随步骤移动。

## 成果断言

被锻造技能必须满足：

- 全局准则。
- 全部 SOP 步骤的断言。
- [Agent Skills 规范](https://agentskills.io/specification)。
- [Agent Skills 最佳实践](https://agentskills.io/skill-creation/best-practices)。

可机械判断的检查优先用 `script/verify-skill-spec.mjs`，支持项见 `--help`。脚本不支持的检查，编写临时脚本判断。非机械判断的部分直接判断。检查参数从 Agent Skills 规范和最佳实践中取。

token 估算默认值：

| 语言 | token 估算 |
|---|---|
| 中文 | 0.6 tokens/字符 |
| 英文 | 0.3 tokens/字符 |

正文超过预算时，按顺序调整：

1. 先按不损失精度的措辞压缩。
2. 再按“资源与归属”判断抽取：只有真正可选、能按需加载且内聚的材料才挂引用。
3. 最后把全部 SOP 步骤整体抽取到 `references/<步骤>.md`，正文保留步骤顺序和每步引用，断言和依赖随步骤移动。如果某一步之前已抽取过部分内容，先把那部分内联回该步骤，再整体抽取。只有该步骤自身仍超预算时，才保留其拆分。
4. 每次调整后重新运行结构检查器。成果断言改动了技能时，按本技能的 SOP 重新走一遍。

**完成**：被锻造技能满足全局准则、全部 SOP 步骤的断言、Agent Skills 规范和最佳实践。可机械判断的检查通过正式或临时脚本，非机械判断直接给出结论。

**检查**：机械检查由正式或临时脚本执行并记录输出，参数按当前规范传入。非机械判断直接给出结论。没有未运行的通过。

**失败**：按上面的顺序压缩、抽取或路由，然后重新走一遍。仍无法满足时用裁定并记录。
