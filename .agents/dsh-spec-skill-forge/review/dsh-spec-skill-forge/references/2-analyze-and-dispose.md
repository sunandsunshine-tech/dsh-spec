# 2. 三要素采集分析与处置

1. **锚定**
   - 受众与领域：目标受众、领域、名称惯例和术语含义。列出要求的工具、目录、约束和缺少的条件。上游面向其他领域或状态时，列出每处差异，由处置决定。
   - 环境：运行时、工具和约束。写进 `compatibility`，有 Script 时也写进脚本头。
   - 声明位置：目标受众是否有声明位置。有则读取自定义值，无则使用技能默认值。
   - 术语：为正文使用的每个术语确定指称、领域含义和归属处。不能消歧时用裁定并记录。
2. **采集**：从请求、项目上下文或上游采集 Docs、SOP 和 Script。只保留会改变设计的内容。新增材料不再改变设计时停止。记录未采集的线索和预期价值。
3. **源约束**：无论措辞，每条“必须、不得、只能”都是源约束。列出每条及其位置。按目的合并重复项，保留全部位置。没有上游时使用请求要求。处置依赖的事实无法确认时，用裁定并记录，不编造。
4. **解构**：寻找上游中比整体更小、陈述一种工作方式、并被多条具体指令遵循的段落。一个段落一个单元。提取步骤、决策规则、角色和结构。一组具体规则不构成段落。没有这种段落时，每条约束逐条处置。
5. **处置**：对未被解构单元覆盖的每条源约束，按顺序取第一个成立的方式。
   - **保留**：约束按原措辞和原意成立。原样携带，只调整语言和排版。
   - **适配**：指称存在，只有取值不同，例如路径、命令、参数、限制或名称。用目标取值实例化。默认值留在技能，自定义值来自目标声明位置。
   - **重新绑定**：没有该指称或名称不同。抽象到目的，在该领域找等价手段，再具体化为可执行表达。
   - **消解**：以上都不成立。不携带，记录目标事实、如何检查以及由什么承担职责。
   - 约束表每行一个单元，列上游位置、处置、位置和依据。依据是目标领域或环境事实、技能目的、上游文本或裁定。解构单元也记录目的和覆盖的约束。改变约束的处置说明保留的部分、目的和迫使改变的事实。消解说明如何检查。
6. **覆盖**：每个解构单元覆盖其段落陈述的全部约束。其余单元各覆盖一条。每条约束恰好被一个单元覆盖。
7. **诚实**：不断言目标受众安装了哪些技能。需要说明职责时，给出职责和尝试顺序。示例以“例如”引入。示例含义不明时用裁定并记录。

**完成**：三要素已识别，每条源约束有处置、位置和依据，没有无归属内容。

**检查**：后续重组需要的材料都已定位，覆盖规则成立，没有重复或冲突的处置。

**失败**：补齐处置、缩小范围、记录缺口或解决冲突。无法决定时用裁定并记录。
