# 3. 重组技能

## 3.1 重组

### 技能结构

被锻造技能的技能结构由以下层组成。没有内容的可选层省略，不保留空标题。

| 层 | 内容 |
|---|---|
| 触发条件 | 元数据：何时加载、作用于什么 |
| 技能定义与边界 | 要完成什么、不做什么、交付什么 |
| 全局释义（可选） | 术语、概念和定义的唯一含义，用于无歧义和唯一指称 |
| 全局准则（可选） | 每一步执行前、执行中、执行后都适用的规则。不描述具体步骤，也不替代步骤的完成判断 |
| SOP 步骤 | 带所需 Docs 和 Script 的步骤，有完成判断、检查方法和失败恢复。资源落位按全局准则 |
| 成果断言（可选） | 全部步骤完成后对最终成果的断言。不中途执行，不复述全局准则或步骤断言，只判断过程无法判断的成果 |

SOP 步骤可以嵌套。每一层遵守同一结构：自己的任务、所需 Docs 和 Script、完成判断、检查方法和失败恢复。子步骤使用下一级编号，父步骤的完成判断覆盖子步骤。层内行文形式不限。格式按“格式与描述”或采用者规则。

### 生成主体，先完全内联

从处置后的三要素分析出触发条件、技能定义与边界、全部 SOP 步骤及其内容。每一步写完成判断、检查方法和失败恢复。所需 Docs 和 Script 放在步骤内或紧邻处。先不抽全局层。

### 抽取全局层

按无歧义和 SSOT，从完全内联的 SOP 中抽取：

| 抽取内容 | 去向 |
|---|---|
| 术语和概念定义 | 全局释义，可选 |
| 环绕每一步的规则 | 全局准则，可选 |
| 全部步骤完成后才能判断的成果 | 成果断言，可选 |

抽取后，原位置只保留引用或使用，不重复定义。步骤所需 Docs 和 Script 留在步骤处。

### 整理

按技能结构整理。可选层有内容才存在。每步所需 Docs 和 Script 已落位，并有完成判断、检查方法和失败恢复。全局释义不重复 SOP，SOP 不重复全局释义，Script 不重新解释方法。按 SSOT 和无歧义整理。写 description，包含任务关键词和附加触发词，然后写术语名称和格式。

**完成**：技能正文已生成并完全内联，全局层已抽取，技能结构已整理。

**检查**：全局层来自完全内联的 SOP，每步依赖已落位，技能结构齐全，SSOT 和无歧义成立。

**失败**：补齐正文、全局层、依赖或整理。无法解决时用裁定并记录。

## 3.2 完成 Script

只在确定性工作确实需要代码时加入 Script。没有 Script 时跳过本子步骤并记录。

有 Script 时，按采用环境编写、改造或移植。从目标受众环境确定运行时，写进脚本头和 `compatibility`，探测采用环境的开发和测试工具。缺少运行时或工具属于硬红线。停止，给出阻塞、已尝试的裁定和可逆选项，等驾驶员决定，补完环境后再完成 Script。

开发运行时与脚本运行时不同时，记录如何在脚本运行时上测试。不能测试则标未验证。

Script 声明依赖、输入、输出和退出码。非交互，用 `--help` 说明接口，结构化数据走 stdout，诊断走 stderr。在脚本运行时上测试并记录输出。可重试处保持幂等，破坏性操作提供 `--dry-run`。写文件、网络或 Git 时用裁定决定并记录。放进 `script/`，不引入安装步骤，记录 stack、依赖和运行时缺失时的行为。

**完成**：无 Script 时明确跳过。有 Script 时接口、测试或未验证状态、调用位置和硬红线记录完成。

**检查**：运行时、依赖、输入输出、退出码、测试或未验证状态和调用位置成立，Script 不替代方法判断。

**失败**：补齐环境、接口或测试。环境缺失时按硬红线停止，不冒充完成。

本步骤（重组技能）的完成判断：

**完成**：3.1 与 3.2 都完成。

**检查**：两个子步骤的完成和检查都成立，两个产物形成同一个被锻造技能。

**失败**：按失败子步骤的失败处理。无法解决时用裁定并记录。
