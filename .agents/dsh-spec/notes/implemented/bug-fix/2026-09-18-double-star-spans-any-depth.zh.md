# Agent Note: `**/` 跨越任意深度，`*` 只停留在单个路径段内

Status: implemented

[English](2026-09-18-double-star-spans-any-depth.md) | 中文

## 问题

有一个匹配器决定某个范围条目是否覆盖某条路径，它把 `*` 和 `**` 当成了同一个运算符：「单个路径段内的任意字符」。于是 `**/README.md` 只匹配两段路径，更深的一律不匹配，因此再深一层的 README 落到了每一个点名它的范围之外——文档范围和双语配对范围读到的文档集合都小于其条目所描述的集合。

没有任何门禁报告这件事。本技能集合的每道门禁都只校验它找到的文件，没有一道声称应该有多少个文件，因此一个悄悄只保留了一部分路径的范围，会基于这部分算出一份绿色的报告。一个没有期望值的计数不是证据。

## 决策

**以 `/` 结尾的范围条目覆盖任意位置的该目录，含 `*` 的条目是 glob，其余条目是一条精确路径。** 在 glob 中，`**/` 跨越任意数量的目录，单个 `*` 只停留在单个路径段内。

**读取某个范围的门禁报告它排除在外的内容，并按排除它的规则分组。** 配对门禁点名每一条排除规则并统计其下的文件，因为一个突然覆盖得少得多的范围，最先显露在门禁拒绝读取的集合的大小上。笔记门禁保留空语料护栏：一次什么都没找到的运行失败。

## 考虑过的替代方案

**显式列出范围覆盖的文件。** 没有可能写错的模式，文档集合也能在一处读完。它输掉是因为这份清单是目录树的第二份副本：每新增一篇文档都得加进去，而漏掉一条恰恰会以 glob 出错的方式隐身。

**从目录树推导范围，再把条目与它比对。** 模式与文档集合就不可能不一致。它输掉是因为范围条目是一项决定，而不是一次推导：一份被有意排除的文档是靠声明排除的，而一个自行推断集合的匹配器表达不了这种排除。

**修好匹配器，什么都不报告。** 这是移除缺陷的最小改动。它输掉是因为同一类错误会在下一次由模式决定成员时回来，而排除报告是把「范围变窄」变成可见事实的唯一信号。

## 后果

范围条目点名一个读者能对着目录树核对的模式，而每次运行都报告排除结果，使文档集合的大小成为输出的一部分，而不是某个人必须事先知道的数字。

代价是配对报告更长：每次运行都会打印被排除的文件及其规则。这份输出正是重点——一道门禁不读的那些文件，恰恰是「有意排除」与「匹配器缺陷」看起来完全一样的地方。
