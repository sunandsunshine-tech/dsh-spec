# Agent Note: 初始化器不覆盖不是它写入的文件

Status: implemented

[English](2026-09-18-never-overwrite-a-file-the-initializer-did-not-create.md) | 中文

## 问题

初始化器的约定是「只写缺失的东西」，这条约定的价值在于维护者可以随时重跑这个工具。`scripts/init-agents-md.ts` 在每一处写入上都遵守了它，只有一处例外：安装项目文档约定的那段代码在复制模板前没有测试目标是否存在。在一个已经有该文件的仓库里重跑，它就把仓库自己的约定换成了原始模板。

本集合的每道门禁都校验一棵树的形态，没有一道会执行写树的那个工具。在空目录上做一次 dry run，看到的是约定被创建——正是这段代码为之而写的情况——因此在工具内部，第一次运行和随后一次运行看起来完全一样。语料中没有任何东西能区分这两者，而被覆盖掉的正是仓库投入最多工作维护的那个文件。

## 决策

**初始化器不覆盖任何不是它写入的内容。** 它规划的每一条路径都先测试是否存在，已存在就记录为保留，模板与目录都一样。新增在一组既有写入旁边的写入从它们那里继承这条规则：周围的写入就是规范，不读它们的新代码块继承不到其中任何一条。

**初始化器写项目的 agent 指令、Agent Note 树，以及文本属于集合的两个文档路径。** 被删掉的那段代码安装的约定属于文档机制，而该机制已删除；留下的是常设指令、笔记约定、分类目录、笔记模版，以及术语表的空壳。

## 考虑过的替代方案

**信任第二次运行是有意的。** 重跑初始化器的维护者想必是想让它执行。它输掉是因为这个工具也是更新路径的一部分：一个项目取用集合的新修订并重跑初始化器，这是常规情况，而正是这种情况会毁掉手写内容。

**为每条规划路径记一个哈希，只改写仍然匹配的那些。** 这是一条更强的规则，而且能抓到被上游变更过的模板所改写的文件。它输掉是因为它把这个工具变成合并器：只要项目没有动过那个文件，它就会被改写成集合的文本，而集合并不拥有项目的指令文件。

**不提供模板，让每个项目自己写。** 少一个问题，也没有东西可覆盖。它输掉是因为文件格式正是门禁执行的约定：一个自创笔记布局的项目会在它读不到的门禁上失败，因此模板保留下来，作为工具不会收回的起点。

## 后果

初始化器可以安全重跑，它的报告区分写入的内容与保持原样的内容，因此维护者能看出这次运行属于哪种情况。这条规则管的是创建期：项目自己写的文件永远不会被 `init` 触碰。

上游的模板变更现在会抵达项目，走的是另一个持有不同授权的操作：[机制文本用覆盖的方式更新](../process/2026-09-21-the-mechanism-text-is-updated-by-overwrite.zh.md)会重写集合拥有的文档，并保留其中属于项目的内容——术语表的行，以及标记小节之外的常设指令。

## 相关

这条规则对每道门禁都不可见。这里没有任何东西会在一个已初始化的仓库上执行初始化器，因此这条护栏靠阅读代码保持，而未来新增的一处没有它的写入会由评审发现，而不是被某条命令抓到。
