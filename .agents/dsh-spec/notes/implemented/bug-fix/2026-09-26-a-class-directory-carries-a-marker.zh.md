# Agent Note: 类目录靠一个标记文件随行

Status: implemented

[English](2026-09-26-a-class-directory-carries-a-marker.md) | 中文

## Problem

归档门禁要求六个类目录齐备。Git 携带的是文件而不是目录,所以一个还没有东西归档进去的类目录,只存在于创建它的那棵工作树里,任何一次克隆都没有它。

[空归档无法交付它的类别目录](../../archived/bug-fix/2026-09-21-an-empty-archive-cannot-ship-its-kind-directories.md) 用产物数量给这条要求上了膛:归档为空时不要求,非空时才要求。本仓库的归档在 2026-09-22 第一篇笔记归档时就不再为空,那道守卫随即向一棵只可能携带一个类目录的树索要六个。每一次全新克隆都过不了 `check --all`:

```
verify-archived-agent-notes: archive rules violated:
  archived/feature/: required kind directory is missing
  archived/bug-fix/: required kind directory is missing
  archived/simplification/: required kind directory is missing
  archived/architecture/: required kind directory is missing
  archived/testing/: required kind directory is missing
```

那道守卫治好了它被写出来时的状态,却弄坏了它上膛之后进入的状态——而后者是每一个归档过一篇笔记的项目都会进入的状态。本地工作树是绿的,因为初始化器在这棵树上建过那六个目录、也没有人删过它们;同一次修订在 CI 上是红的,因为克隆只带走 Git 记下的东西。

## Decision

**六个类目录无条件齐备,每个目录带一个标记文件。** `AGENT_NOTE_CLASS_PLACEHOLDER`(`.gitkeep`)写进每一个归档类目录——初始化器建树时写,已存在的项目手工补——于是那个目录成了 Git 会携带的文件,而不是会被丢掉的空目录。归档门禁把同名文件读作目录标记,而不是冻结产物,所以它既不进产物表,也不进只增不改的封存。

**产物数量那道守卫删除。** 这条要求就是 dsh 自己那个无条件循环;让它在归档类目不足六个的项目里可满足的是标记文件。本包对 dsh 的偏离因此缩成一条规则——类目录里名为 `.gitkeep` 的文件是标记而不是产物——取代了原先那道「把 dsh 的规则换成另一条规则」的守卫。

**未知类目规则不变。** `archived/` 下不在闭集里的目录无论归档里有什么都是错误,而这条规则正是抓住把类名拼成 `bugfix/` 的那条。

## Alternatives considered

**保留守卫,接受失败。** 改动最小。它输在:它让每一个归档过一类的项目的全新克隆都长期是红的,包括本仓库;而一个过不了的门禁不是门禁。

**删掉六目录要求,有哪个类目录算哪个。** 要求随内容走,空归档和部分归档都不会失败。它输在:类目录是「一篇笔记的类目能一眼对着闭集核对」的凭据——目录不在,说明该类没用上;目录被删,什么也说明不了;而且本包会停止陈述一条 dsh 在陈述、归档契约也已经公示的规则。

**只在产物读取处豁免标记文件。** 一处豁免而不是两处。它输在:封存是从读取处填出的产物表派生的,一次跳过同时覆盖两者;第二处豁免是够不到的代码。

**让 `sync` 模式在克隆后补建缺失目录。** 六个名字,那条命令本来就知道。它输在:它把失败搬走而不是消除——聚合在有人跑 manager 之前一直是红的,而承诺是克隆下来就能直接跑 `--all`。它还把门禁要求的目录,挂在一个契约是「同步本包拥有的文本」的模式下。

**给标记换个名字,或往每个空类目录放一篇笔记产物。** 前者只是外观。后者不成立:类目录里放的是归档三件套,凭空造一篇会作为没人做过的决定进入封存与清单。

## Required verification

本仓库的临时克隆——它带着标记文件、不带别的空目录——过聚合:`dsh-spec.ts check --all --root .` 报 `check notes-archived: ok`。同一棵树里删掉一个类目录,该目录被报为缺失,证明这条规则是上了膛而不是被删掉了。只放着标记文件的目录不报任何未封存产物。初始化器对一个空项目运行后,写出六个类目录,每个都含那个标记。

## Consequences

**换来了什么。** 聚合只凭修订本身就能是绿的,在本仓库和在每一个采用这套机制的项目里都是如此,不需要前置命令,也不取决归档恰好用到了哪些类目。本包陈述的规则现在就是 dsh 的规则,两份副本之间的差别只剩一个读取处会跳过的文件名。

**代价是什么。** 多了六个标记文件,它们的唯一职责是对付 Git 对目录的处理;每个文件自带说明,因为门禁把类目录里的其他文件都读作冻结产物。一个项目若在目录还空着时删掉标记,下一次克隆就会丢掉那个目录、并在那里过不了门禁——那处失败很响,且点名是哪個目录,而这正是这条规则想要的结果。
