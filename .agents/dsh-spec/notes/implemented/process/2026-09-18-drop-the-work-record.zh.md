# Agent Note: 去掉工作记录

Status: implemented

[English](2026-09-18-drop-the-work-record.md) | 中文

## 问题

本仓库曾经新增 `.agents/dsh-spec/work.md` 来承载"在飞的工作"，理由是提案与 git 都不说明会话停在哪里。而源项目没有这样的工件，却可靠地迭代——这是更好的证据：这套模式自己的答案是，`proposed` 笔记陈述设计与验收标准，提交陈述已交付之物，笔记树陈述未决之事，而这些已经足够。

那条记录还让每次变更都付出代价：一份必须保持最新的文件、契约里的一个层级及紧邻它的一行参数、一条常驻指令、组成地图里的一节，以及一篇解释它的笔记。

## 决策

**`work.md` 及其承载它的每一个面都被删除**：层级表两侧的该层级、要求更新它的常驻指令、组成地图中的那一节，以及文档表中的那一行。这些面已随文档机制本身一并消失（[四个机制，而非十二个](2026-09-18-four-mechanisms-instead-of-twelve.zh.md)），而引入该工件的记录已按合并规则并入本笔记，其英文、中文与伴随文件一并删除。

**接续来自已经存在的东西。** 会话从仓库恢复：笔记树陈述决定了什么、还有什么仍是提案，聚合检查报告哪些已不再成立，`git log` 陈述交付了什么。工作记录本会说"第 6 步，共 15 步"的地方，现在由提案的验收标准说明还剩什么，而闭合每一步的提交说明它满足了哪一条标准。

## 曾考虑的替代方案

**保留一份只追加的工作日志。** 无需重写，且追加起来很容易。它落选是因为它会变成与 git 漂移的第二份历史，而且每一条在它所描述的工作完成后仍然留着——正是 slop 清单要移除的实现状态叙述。

**保留它并系统化进集合。** 这套模式可以发布该工件，让每个采用项目都获得同样的接续能力。它落选是因为维护者的检验标准就是源项目：它不需要，那么发布一个就等于让集合主张一条它自己的源头已经否证的需求。

**只为本仓库保留。** 它本来就是这么划界的，在本仓库之外不花代价。它落选是因为代价的大头恰恰就在这里——一个层级、一条常驻指令、一节地图，全都是为本仓库而存在。

**用每份提案里的一节来替代它。** 不新增工件，而提案本就是设计的权威。它落选是因为提案在转为 implemented 时会被重写，而决策记录里的进度标注，正是 slop 清单要移除的东西。

## 后果

恢复一个被中断的目标，现在意味着读各提案的验收标准、聚合检查，以及最近几次提交。这是几条命令而不是一个文件，而这也是源项目付出的代价。

记录做过、而别处无法替代的只有两件事：在一台全新机器上恢复克隆的命令，以及一句"下一步是哪一步"。前者在 `AGENTS.md` 的 Commands 一节和根 `README.md` 里；后者可被推导——这正是"没有它也能可靠迭代"的含义。

## 重新引入

**只有在没有它就无法可靠接续时才重新引入。** 条件是被测量到的代价，而不是偏好：出现两次以上会话各自把下一步推导错，或一次交接丢失了工作。证据应是那些提交，而不是论证。

## 缺失核验

没有任何东西引用该工件：`.agents/`、`docs/` 或 `skills/` 下没有任何文件提到 `work.md`，也没有任何层级认领它。`grep -rn 'work\.md' AGENTS.md docs skills .agents/dsh-spec` 无输出。
