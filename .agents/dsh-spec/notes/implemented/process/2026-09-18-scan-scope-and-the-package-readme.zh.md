# Agent Note: 扫描范围、内联的理由，以及一份包 README

Status: implemented

[English](2026-09-18-scan-scope-and-the-package-readme.md) | 中文

## 问题

在这里运行初始化器，一次暴露了四件事。

扫描把 `submodules/dsh/` 里的十二个子树指令文件计了进来，而且只要依赖树里恰好有这类文件，它还会继续计——因为它只是遍历目录，对项目自己的忽略范围一无所知。项目自己的 `.gitignore` 就是"什么属于它"的陈述；无视这份陈述的扫描，会把另一个归属者的文件报告成维护者的。

已部署的 Agent Note 契约指向三份只存在于技能集合源项目里的决策记录，于是三条规则——统一格式、没有索引、冻结归档——把它们存在的理由留在了读者打不开的仓库里。

初始化器的工作流从未要求 agent 在写入之前提问。它的步骤是清点、收集、应用，然后才说"与维护者一起替换每个占位符"——于是在模式为 `attended` 的项目里，维护者的回答变成对已完成工作的更正。

该包的 README 是在没有打开它所发布的文档标准的情况下写的。它在向维护者解释自己，而不是向安装这个包的人解释；而它从未读过的声音规则明确写着，这些规则"对包 README 尤其具有强制力"。

## 决策

**扫描尊重项目的忽略范围。** 它以 git 对树的视角——已跟踪加上未跟踪、减去被忽略的——作为"属于这个项目"的文件集合，因此被忽略的路径永不被读取，子模块的内容也永不进入。没有 git 时退回按目录名跳过。git *没有*忽略的依赖树，若同时持有自己的 manifest 和 lockfile，仍会被跳过；而每一次拒绝都会连同理由打印出来，好让维护者能够核查这个判断，而不是信任它。

**三条理由被内联进契约。** 规则与其原因现在同处 `.agents/dsh-spec/notes/README.md`，用技能集合自己的措辞，而不再指向另一个仓库里的笔记。规则本已转移过来，缺的只是它们的依据。

**工作流在写入之前先提问。** `dsh-spec-init.md` 在"收集事实"与"应用"之间新增了一步：在 `attended` 下，展示清点结果与问题并等待；在 `unattended` 下，应用文件支持的部分，把其余记成提案。先应用、后汇报被明确点名为两种模式都不是。

**包 README 遵循它所发布的标准。** 它以读者能做什么开篇，而不是这个包是什么；它说明让副本被共享的安装方式，以及这套模式收取的代价；并给出第一条能产出结果的命令。那句写给维护者的话已经删掉。

## 曾考虑的替代方案

**保留遍历，把 `submodules/` 加进跳过清单。** 一个字符串，本仓库的报告就干净了。它落选是因为 `submodules/` 是本项目的事实：下一个项目的依赖树叫别的名字，而扫描会以完全相同的方式把它的指令报告成维护者的。

**直接解析 `.gitignore`。** 不依赖 git，而且范围在扫描自己的源码里可见。它落选是因为忽略语义——取反、锚定、仅目录模式、嵌套文件之间的优先级——是一份有参考实现的规范，而部分重新实现会朝着"扫描过多"的方向静默失败。

**把理由留在上游并链接到技能集合。** 这三条规则属于模式，所以它们的推理可以放在 `references/` 里、由契约引用。它落选是因为一份项目每写一条笔记都要读的契约，不该为了知道格式为何如此而要求打开第二份文档；而这些规则足够短，各自的原因只有两句话。

**只补上缺失的步骤，不说明错误行为是什么。** 一句"先提问"读起来像风格建议。点明失败——迟到的回答会变成更正——才是让 agent 照做的原因。

## 后果

初始化器现在在本仓库报告一棵被跳过的树：`submodules/dsh`，连同被跳过的理由。读到这一行的维护者可以不同意它，而这正是重点。

扫描依赖 git 存在且根目录位于工作树内。不在工作树内时，回退是旧的按目录名遍历，因此忽略范围只在它存在的地方被尊重。

契约多了三句话，少了三处指向本仓库读者打不开的文件的指引。笔记契约及其中文对侧仍与技能集合模板逐字节一致，因此下一次模板变更无需任何调和就能到达本仓库。

README 现在是一份受双语门禁约束的配对文档，这意味着编辑它要为对侧付出一次编辑和一次重新记录，而它的长度由换行规则而非个人口味决定。
