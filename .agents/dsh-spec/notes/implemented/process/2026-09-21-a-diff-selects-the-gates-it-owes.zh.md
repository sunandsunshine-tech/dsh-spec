# Agent Note: 一次改动只跑它该跑的门禁

Status: implemented

[English](2026-09-21-a-diff-selects-the-gates-it-owes.md) | 中文

**部分被 [门禁只读调度器交给它的范围](2026-09-21-a-gate-reads-the-scope-it-is-handed.zh.md) 取代。** 下面的决定仍然拥有这个行为——一次改动只欠它该跑的检查,限定范围的运行永远不能替代聚合——它的范围键也保留了下来。改变的是选区在何处计算:入口现在按每道 check 的记录把范围交给它,check 只读交给它的东西,于是键与选区种类合为一道门禁一条记录,而 `tracked` 随凭据扫描一起消失。

## 问题

本技能集合的每道检查都只能按名称调用,于是一个只改了一条笔记的人,得先知道存在三道笔记门禁、知道配对门禁也会读这条笔记、还知道三道 Markdown 门禁同样会读它——否则就跑聚合检查,然后等着那些根本看不见这次改动的门禁跑完。pre-push 技能把这份对应关系写成了散文,而那是"每道门禁读什么"的第二份陈述,门禁范围一变它就开始漂移。

## 决策

manifest 里每道已记录的门禁现在都要声明一条**范围记录**:它为什么表面作答——`notes`、`notes-archived`、`markdown` 或 `pairs`——以及范围如何交给它,断言关于整棵树时为 `root`,只读交给它的文件时为 `files`。入口经由本来拥有这些路径的模块解析键:`notes-root.ts` 管笔记树,`md-scope.ts` 管散文门禁所读的 Markdown,`i18n-scope.ts` 管配对范围。随后 `dsh-spec.ts check --base <ref>` 把落在各键内的路径交给对应主语,只跑这次改动欠下的检查,并把每一个被跳过的主语连同原因打印出来。

用键而不是路径字面量,是为了让每条路径只有一个归属者:manifest 说明一道门禁对哪块*面*负责,引擎说明那块面在哪里。集合外的键一律拒绝——无法解析的范围会被读成"这里没有属于该门禁的东西",从而悄悄丢掉检查;已记录的门禁若完全没有条目也拒绝,这样记录不会只写一半。

`check --all` 仍是整树形式,`check --base <ref>` 是在自己的输出里说明这一点的子集;子集永远不能替代推送前的文件扫描。

## 曾考虑的替代方案

**继续把对应关系写成 pre-push 里的散文。** 今天能用,也不需要写代码。它落选,是因为散文无法被执行:门禁范围变了而那句话没变时,没有任何东西会失败,而那句话恰恰是贡献者会去读、而不去跑检查的东西。

**让每道门禁自己报告它读哪些路径。** 这是最忠实的版本——门禁自己回答。它落选,是因为这意味着每道门禁都要长出一个范围上报模式,分发器还要解释四种不同的回答;而由拥有路径的模块解析一个键,说的是同一件事,且只有一个归属者。

**在 manifest 里为每道门禁记录字面 glob。** 评审时最直观,没有间接层。它落选,是因为它把每条路径的第二份副本放进第二个地方,而这个包已经为"一条路径两处字面量"付过两次代价。

**不打印被跳过的门禁。** 输出会更短。它落选,是因为一次不说明自己漏了什么的限定运行,与一次通过的聚合检查无法区分——而这正是整份记录要防的失败。

## 后果

- 改引擎只会跑凭据扫描;改一条笔记会跑读笔记树、配对与 Markdown 的那四道检查;每次运行都会打印它跳过了哪些。
- manifest 现在承载四条事实;新增一道门禁意味着在同一次改动里记录它的名称、范围与脚本。
- 代价是多了一份要与门禁清单保持同步的记录。只写一半的情况由拒绝覆盖,而封闭的键集合让一个拼写错误无法悄悄缩小运行范围。
- 验证:`dsh-spec.ts check --all --root .` 报告两道整树检查;`dsh-spec.ts check --base HEAD --root .` 对每个主语打印一行 —— `check <subject>: ok`、`FAIL` 或 `skipped — <reason>` —— 干净树上打印四条跳过。
