# Agent Note: 初始化以空表发布词汇表

Status: implemented

[English](2026-09-21-initialization-releases-the-vocabulary-table-empty.md) | 中文

## 问题

配对约定告诉项目 `docs/terminology.md` 是每一对双语文档共同遵守的词汇表，翻译简报生成器没有这个文件就拒绝运行，但没有任何东西创建它：采用本技能集合的项目必须先自行发明这张表的形状、各列含义与加行规则，然后才能翻译任何东西。而「一行由维护者决定」这条规则此前随配对约定一起发布——那是一份机制文档，却在描述某个项目自己拥有的文件的项目流程，编辑这张表的人根本遇不到它。

## 决策

`install` 向 `docs/` 写入两个路径：`terminology.md` 来自一份带有各列含义、使用规则与一张空表的模版；`AGENTS.md` 则载明管束这张表的常设指令——一行约束每一对文档的两侧、增删或修改一行须由维护者在对话中提出、以及这张表自身不声明配对。没有任何开关可以跳过它们:采用技能集合的项目就一并接受这张表与它旁边的指令;不翻译的项目带着同一张没有行的表,而不是换一种布局。两者一旦存在都不会被覆盖。

这张表刻意不带任何行发布。一行固定了配对两侧共同书写的用词，因此一行就是一个决定；一行从本技能集合抄来的示例，或由初始化器凭空写出的一行，都是没人做过的决定，而此后的每一次翻译都会遵循它。所以模版只带规则与列头，行由项目在维护者做出决定时填入。

规则随表一起搬家：`docs/AGENTS.md` 是项目自己的文件，与它所约束的产物同处一处；配对约定不再携带关于某个项目流程的条目。约定保留它自己拥有的东西——配对、记录、切换行、结构签名——只把这张表称为它读取的真源。

## 曾考虑的替代方案

**把本技能集合自己的表作为起点发布。** 这能让项目立刻拥有词汇，并展示填好的行长什么样。它落选，是因为那些行是本仓库的决定：照着它们翻译的人，遵循的是另一个项目的示例，而项目的头一件事反而变成审计自己从未决定过的行。

**把规则留在配对约定里。** 约定是翻译工作者在动一份配对之前会读的东西，因此无需新增文件就能触达每个项目。它落选，是因为需要这条规则的是编辑这张表的人，而那个人不在约定里；这条规则也属于从技能集合内部描述项目文件的写法，项目无法改动它。

**让初始化器写一行示例，并标明这是示例。** 这样既能展示表的形状，又不声称任何决定。它落选，是因为标明为示例的一行仍然可能被译者照用，而且这张表自己的规则说，不影响翻译的条目不属于本表——列头已经展示了形状。

## 后果

- 需要翻译的项目从第一次提交起就拥有正确的列与规则;不翻译的项目带着同一张没有行的表,而不是换一种布局。
- 词汇规则现在住在它所约束的表旁边，项目可以修改它，而随包发布的约定不再陈述某个项目的流程。
- 代价是采用过程多写两个路径、多两份需要与其所描述约定同步的模版,以及删除 `docs/AGENTS.md` 的项目会失去这条规则唯一的归属处。
- 验证：`dsh-spec.ts check --all --root .` 在本次改动留下的目录树上以 `run: 8 gate(s), 0 failed` 结束；向空仓库执行 `install` 会创建这两个路径，其中不再残留 `{gate-dir}`，`verify-md-links` 报告所有相对链接均可解析。
