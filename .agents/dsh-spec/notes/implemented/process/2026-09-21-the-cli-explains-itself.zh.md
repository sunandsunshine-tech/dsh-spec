# Agent Note: CLI 自己讲清楚用法,并说读者的语言

Status: implemented

[English](2026-09-21-the-cli-explains-itself.md) | 中文

## Problem

这套东西的全部机械流程现在都走同一个入口——`install`、`upgrade`、`uninstall`、`status`,六道检查,以及变更范围的分派——而它的用法文本只有 `--help` 打印的一行主语清单。读者想查一个旗标、范围语法、退出码或示例,没有地方可看:主语表在 `manager-lifecycle.md` 里重复了一份,而"这种改动欠哪些检查"的映射是某个随包工作流技能里的散文,不是 CLI 自己讲出来的事实。

由此有两件事。加载这套技能的 agent 没有一页可以读,来学会驱动这套东西的工具;而任何手写在 CLI 旁边的长文档都会与它漂移——同一个事实放在两处,正是本仓库已经付过两次代价的失败。

帮助还只有英文,而这里每一份给人读的文档都是双语的。

## Decision

**帮助变成一个真正的界面。** `--help` 打印命令行工具该有的形状:用法行、管理类主语、带操作各检查类主语、旗标、退出码,以及指向逐主语帮助的一行。`dsh-spec.ts <主语> --help` 打印该主语的操作、范围形式、旗标与一个示例。

**帮助双语,而且只有帮助双语。** 语言优先取 `--help zh|en`,其次是 `DSH_SPEC_LANG`,再是 `LC_ALL`、`LC_MESSAGES`、`LANG`;值里的语言部分以 `zh` 开头选中文,其余选英文。各检查的报告保持英文:它们是提交信息或笔记引用的证据,功能套件也在断言它们的文本。

**长文档与帮助是同一份数据。** `references/cli.md` 由 `--help --markdown` 渲染,并由一条功能测试断言提交的文件等于渲染结果,于是帮助与参考不可能各走各的。它是英文,与它旁边其它参考一致;中文读者运行 `--help zh`。

**一个事实一个所有者。** `manager-lifecycle.md` 保留部署模型、manifest 与边界,用法部分改为链接到 `cli.md` 而不重复主语表;`SKILL.md` 把 `cli.md` 列为第一条参考。

**操作名长什么样是另一个决定。** 这条笔记拥有的是帮助这个界面——它从哪里渲染、说哪种语言、怎么被测试。帮助打印给读者的是文法:动作是子命令,旗标是修饰语,命令默认读的是便宜的那个范围,除非某个旗标把它放宽。那套文法由[动作是子命令](../../proposed/process/2026-09-21-actions-are-subcommands.zh.md)决定,它部分取代了这条笔记的"主语加旗标"写法;两条笔记保持互相链接。

## Required verification

- `--help` 以 0 退出并点名每一个主语;`--help zh` 输出中文,`--help en` 输出英文。
- `DSH_SPEC_LANG=zh --help` 是中文;`LC_ALL=en_US.UTF-8` 覆盖 `LANG=zh_CN.UTF-8`;`--help en` 覆盖 `DSH_SPEC_LANG=zh`。
- `--help de` 以 2 退出并列出可接受的值。
- 每个主语都能回答 `--help`,点名它的操作、范围形式与一个示例。
- `references/cli.md` 等于 `--help en --markdown`;任一侧单独变动,套件即失败。
- 没有任何检查报告改变语言。

## Risks

- 双语帮助让需要保持真实的文本翻倍。漂移测试只覆盖英文参考;中文帮助由套件的语言用例覆盖,断言各主语摘要存在且为中文。
- 帮助文本一旦转述主语,就可能在该主语新增旗标时过期。套件断言每个已记录的主语都有帮助,所以新主语在被描述之前会失败。
- 如果语言开关连检查报告一起切换,每一处被引用的验证都会取决于读者的环境;这正是开关止步于帮助的原因。

## Alternatives considered

**手写 `cli.md`,再测"每个主语都出现在里面"。** 这是常见做法,文档也能比帮助屏写得多。它落选是因为先漂移的正是细节:CLI 里改名的旗标仍能通过覆盖测试,而两份文档恰好在读者看的地方开始互相矛盾。

**连检查报告一起本地化。** 全篇一种语言,一次决定。它落选是因为检查报告是证据——提交信息引用它,笔记记录某道门禁打印了什么——而且那会把套件里的英文断言改成结构化断言,换不来读者要求的东西。

**在 `--help zh` 之外再加 `--lang zh`。** 同一件事两种说法,而 `--help` 本来就得读语言才能打印自己。它落选于本集合处处适用的同一条规则:一个所有者,一种写法。

**主语表继续留在 `manager-lifecycle.md`。** 那里已经写好了。它落选是因为用法事实将有两个所有者,而读者先找到哪一个纯属偶然。

## Consequences

这套东西多出一页回答"我该怎么驱动它"的内容,从 agent 加载的技能可以到达,而且它是 CLI 自己的输出,不是对它的描述。`--help` 成为人人在终端里读的短形式,`cli.md` 成为可检索的长形式,两者由入口里同一张表渲染。代价是帮助数据从此成为需要维护的面:没有帮助的主语会让套件失败,语言开关的两个取值都被用例走过。
