# Agent Note: 机制文本用覆盖的方式更新

Status: implemented

[English](2026-09-21-the-mechanism-text-is-updated-by-overwrite.md) | 中文

## 问题

`install` 只写一次机制文件,此后不再触碰,这保护了项目的改动,却也把项目初始化时所处的修订冻结下来。本仓库自己的目录树就展示了代价:它的笔记约定已经与技能集合交付的模版相差 26 行,两个 `AGENTS.md` 也有差异,而树里没有任何东西能说明一份副本是否过期。门禁无法执行一份每个项目文本都不同的约定,评审者读到的某个项目的约定,可能是技能集合早已不再交付的规则。

产生这一状态的那条规则本身是对的,并且保留:初始化器必须可以安全重跑,所以安装仍然只写缺失的东西。缺的是另一个持有不同授权的操作——更新文本属于技能集合的文件,同时不拿走属于项目的内容。

## 决策

`install` 与 `upgrade` 以初始化器的 `sync` 模式收尾,该模式也可以单独运行:初始化器默认试运行,`--write` 才落盘。它只重写**文本**属于技能集合的文件,更新到刚安装的修订:

| 文件 | 合并方式 |
|---|---|
| 笔记约定(`notes/README.md`)与三个笔记用的 `AGENTS.md`、`docs/AGENTS.md`、`.rgignore` | 整份替换 |
| `docs/terminology.md` | 替换表头,保留项目自己的行 |
| 根 `AGENTS.md` | 只替换被标记的 `dsh-spec:agent-notes` 小节 |

有两样属于项目的东西在构造上就能存活。术语表的一行是一个决定,因此行会在新表头之下原样保留;标记小节之外的常设指令是项目自己写的文字。笔记相关文件只在笔记树存在时才同步,所以删掉它的项目不会又被补回来;那份清单之外的东西一概不读不写。每一条被重写的路径都会报告出来,试运行时只报告不落盘。

希望自己目录树上有不同规则的项目,应把规则写进笔记、写进 sync 不管理的文件——而不是去改约定正文,因为下一次 sync 会把它替换掉。

## 曾考虑的替代方案

**只报告差异,让项目自己改。** 加一行 `status` 列出有差异的文件是只读的,而且有意改过约定的项目能保住自己的文本。它落选,是因为技能集合的承诺就是"机制只有一份":一个项目在暗中执行技能集合已经删掉的规则,正是抽取存在的意义所要防止的漂移,而报告被无视的次数不会少于被执行的次数。

**全量替换,连常设指令与术语表一起。** 规则最简单,也能让每个项目完全一致。它落选,是因为它会毁掉决定:术语表的行属于维护者,根 `AGENTS.md` 承载项目自己的指令。一个删掉"它本应记录的决定"的机制不叫一致,叫破坏。

**给每个受管区域加标记,原地编辑。** 这把常设指令的规则推广到所有文件,也能扛住重新排版。它落选,是因为它要求在人读的文档里引入一套标记约定,而约定本身足够短,整份替换比对着标记看 diff 更容易评审。

## 后果

- 每个项目的笔记约定、文档指令与搜索排除都是它所运行修订的文本,因此门禁执行的是同一份约定,评审者读到的也是同一份约定。
- 项目对这些文档所做的自己的改动会被覆盖。这正是要点,也是 sync 逐条报告被重写路径、而不是笼统说一句"已是最新"的原因。
- 术语表的行与标记小节之外的常设指令需要项目自己照看,因为 sync 会保留它们,而没有别的东西守着它们。
- 验证:在一个探针项目里,约定被加过一行、术语表被加过一行、`AGENTS.md` 的开头已填写,执行 `sync --write` 得到 `updated .agents/dsh-spec/notes/README.md`、`updated docs/terminology.md`,约定里新增的那行消失、术语行保留、开头原样;再跑一次时过期的标记小节被替换(`updated AGENTS.md`)。`dsh-spec.ts check --all --root .` 在探针项目与本仓库都以 `run: 7 gate(s), 0 failed` 结束。
