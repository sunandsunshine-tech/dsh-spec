# Agent Note: 写笔记的触发条件跟着 dsh 收窄

Status: implemented

[English](2026-09-21-the-note-trigger-follows-dsh.md) | 中文

## 问题

本集合交付的约定此前写的是:**每个非平凡变更**都必须新增或更新一份 Agent Note,而"非平凡"是一张清单——行为、架构、跨文件共享的约定、流程或工具、测试策略、磁盘/线缆/配置格式,或任何维护者可能重新审视的决定。

dsh 在 `dsh-v0.1.6-alpha.2`(本集合现在钉住的发布)里把它收窄了:笔记只写给**代码、测试与现有文档都解释不了的、具有长期价值的决策理由**,机械性或局部编辑豁免。从旧钉住到这次发布之间,机制里别的东西没有动:没有门禁脚本、没有笔记说明文件、没有搜索排除。

## 决策

收窄后的文本只搬到 dsh 改动的那一处:笔记约定模版及其中文对侧。随后 `sync` 会把它写进每个项目的副本,本仓库自己也算在内。

**集合里别的一律不动。** dsh 没有动自己的常设指令——它的根 `AGENTS.md` 仍然写着"非平凡变更必须带笔记"——所以 `init` 注入项目 `AGENTS.md` 的那一小节保持这条规则,manager README 的概述也保持。我们跟源项目保持同一状态,**包括它的约定与常设指令之间那处不一致**:要不要消解它,是 dsh 的事,不是我们的。

## 曾考虑的替代方案

**把收窄也搬到常设指令。** 这样更整齐:agent 每次会话读到的句子,与它写笔记时对照的约定,说的是同一件事。它落选,是因为那不叫对齐:源项目没有改它的 `AGENTS.md`,而一套自行消解上游矛盾的集合,等于悄悄立了一条源项目从未做过的规则,下一次重新抽取会把它当成一处没人要求的差异。这个方案先被实现过,后按维护者的指示回退。

**保留宽触发条件,记成一次偏离。** 会有更多决定被写下来,本仓库自己的历史也证明这个习惯抓得住东西。它落选,是因为触发条件属于笔记机制本身:一套交付的触发条件与 dsh 的不同,世界上就同时存在两份同名约定。

**等一个稳定版再跟。** 基线会动得更少。它落选的理由与当初定基线的理由相同:笔记机制有自己的节奏,而改动了它的 alpha 恰恰是最值得跟的那个发布。

## 后果

- 每个项目的笔记约定都等于我们所钉修订上 dsh 的约定,`sync` 让它保持如此。
- 我们自己以及每个采用者的规则,仍与 dsh 的常设指令一样宽:非平凡变更照旧应当带一份笔记。收窄后的约定管的是"这份笔记该为什么而写"。
- 这里约定与常设指令确实不一致,与源项目一模一样。这条笔记把这处不一致记下来而不是抹平,下一个读者因此知道它被看见过。
- 验证:`dsh-spec.ts all --check --root .` 以 `run: 7 gate(s), 0 failed` 结束;约定的"何时需要写一份"一节与 `submodules/dsh/.agents/notes/README.md` 携带同一条规则,只是把它的 `same PR` 换成了我们的 `same change`;向空项目 `install` 注入的常设指令与本次改动之前完全相同。
