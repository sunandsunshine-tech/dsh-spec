# Agent Note: 两侧各按自己的语感写,并按读者能跟上的次序排

Status: implemented

[English](2026-09-22-each-side-is-written-in-its-own-idiom.md) | 中文

## Problem

一对双语文档,是两份文本承载同一个意思;而把它们绑在一起的那道门禁读的是结构:标题层级、列表形状、代码块、链接目标。它读不了句子。于是一对文档可以通过全部检查,而读者真正用的那一侧根本读不下去——因为那一侧是照着另一侧一句一句搬过来的。

本仓库在自己的笔记上就栽过这一次。某一篇中文侧的第一稿,留着英文的句子骨架:"in the same breath"被直译成"在同一次呼吸里","would survive"被安在"积累的内容"上而搭配不成立,"the expensive direction"和"buy insurance"原样搬成了中文读者不用的比喻,整段还跟着英文的从句堆破折号。结构检查全过。母语读者第一行就卡住了。

第二种失败没有借来的句子。一段文字可以由一句句真话组成,读者却什么也拿不走,因为次序里没有线:一个点在这儿,一句插话在那儿,第一点的理由隔了三段才出现。维护者对这样一份报告说过:读完一段,上一段就被顶出去了。结构照样全过——配对门禁读的是标题,门禁读的是命令。

**同一条规则也管 agent 说出来的话。** 回话和文档是在同一个条件下被读的:用哪门语言写的,就由谁一次读完。

## Decision

**按那门语言的说法写,并排成读者能跟上的次序。** 两条要求,一个读者:

1. **那门语言自己的语感。** 句子骨架来自另一门语言的,就从意思重写:该调序的调序,该拆句的拆句,该丢的比喻丢掉,用那门语言本来就会用的说法。术语另有一套规矩,归术语表管——刻意的共用词表住在那儿。
2. **能带住人的次序。** 先说要什么、结论是什么,再按因果与逻辑给出支撑它的那一串;每一句都由前面几句建立起来,或者明确标出它是新的前提;该在一起的在一起,相邻段落不互相矛盾。次序不是修饰:读者记不住第一段却要读第二段,等于什么都没得到。

**一份文本用哪门语言,不是这条规则的问题。** 成对文档的两侧由契约定;本仓库与技能集合自己的文本是英文,因为读它的是 agent;回话用提问时那门语言。语言定了,这条规则才开始。

这条规则随技能集合发布:在规范目录里是 `prose.idiom`,项目不必读到这篇记录就能用它。

## Alternatives considered

**忠实翻译,一句对一句。** 落选:一对文档的单位是意思,不是句子。对源语语序的"忠实"正是问题本身——读者得先把它翻回去才看得懂,而第二语言的存在本来就是为了省掉这道工序。

**按论文的写法来:先背景,再推理,最后给答案。** 落选:维护者读东西是为了做决定;答案放在最后,等于要求他把整篇端在手里等它出现。那一串理由仍按因果排,只是结论放在能用的地方。

**让配对门禁去抓。** 做不到:门禁比的是结构签名,而一个照搬语序的句子,标题、列表、链接和原文一模一样。这条规矩只能落在写第二侧的那个人身上。

**交给一位会说这门语言的评审者。** 作为退路保留,绝不当作规则:评审确实能抓到——这次就是这么发现的——但一条只活在评审眼里的规则,会在每一次改动里被重新发现一遍;而能最省力修好它的,是写的人。

## Consequences

- 说出来的那一侧与文档受同一条规则约束,所以次序是在落第一句之前定下的,不是写着写着才碰上的。
- 第二侧花的时间和第一侧一样多。一对文档是两篇写作,不是一篇加一份副本。
- 结构对齐仍然是机械的,所以门禁的价值不变:即使两侧都读得通,它照样能抓到跑掉的链接或列表。
- 母语读者说一句"这读着像机翻",或者读者读完第二段丢了第一段,都是关于散文的证据,该当成缺陷报出来,而不是当作口味之争。
