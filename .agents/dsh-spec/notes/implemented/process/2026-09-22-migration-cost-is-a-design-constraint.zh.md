# Agent Note: 迁移成本是一项设计约束

Status: implemented

[English](2026-09-22-migration-cost-is-a-design-constraint.md) | 中文

## Problem

一个会往别人树里写东西的包,在同一次呼吸里决定两件事:这个功能怎么工作,以及它在一个会长期持有它的项目里留下什么设计。第一件在这里判断 —— 对着代码、测试和本仓库自己的需要;第二件在那里判断 —— 对着一个已经改了自己那份副本几个月的项目:它在我们的小节旁边加了自己的小节,在块里换了措辞,把一条路径写进了自己的 `AGENTS.md`,从自己的笔记里链过来。改名的代价在这里是一次 diff,在那里是一次损坏;而这种不对称只会变大:一个项目时它是一次对话,一百个项目时它是一次迁移。

本仓库是用最普通的方式学到这种不对称的。一个功能的文件先放在 `docs/`,同一次会话里挪到 `.agents/dsh-spec/`;而促成这次挪动的讨论还问了另一个问题:如果当初选的是单个文件会怎样 —— 日后的按分组拆分就得把那个文件变成目录,移动一条项目已经持有的路径。那次挪动之所以免费,只是因为还没有人采用过任何东西。当初那个选择背后的理由——「只有一个文档,所以不需要目录」——对结构是成立的,对迁移是盲的。

## Decision

**当两个设计在架构与规划上等价时,选那个采用者已经积累的内容能活下来的。** 一个能继续加文件的目录,胜过一个以后必须变成目录的文件;一种能继续加字段的格式,胜过一种以后必须被重写的格式;一个能留住的名称,胜过一个必须移动的名称;一份躺在它文档旁边的记录,胜过一份以后被改名的记录。这条规则说的是**可演进性**,不是路径:要回答的问题是,当这个设计变化时,采用者手里握着什么。

两个条件使它不至于变成"投机的许可证"。变化必须是**大概率**的,而这个概率要在改动里被论证,而不是被假定;能扛住它的那个设计必须现在几乎不花成本、并且不动架构与规划。如果这条规则买的是对"没人预期会发生的改变"的保险,那么更简单的设计胜出 —— 因为投机的结构在这里本身就是一种缺陷。如果概率或成本确实只能靠猜,那么这个决定属于维护者:去问。

## Alternatives considered

**现在选最简单的设计,以后再迁移。** 落选:迁移才是昂贵的方向。简单由我们付一次;迁移由每一个已经积累内容的项目付,而本仓库没有资格替它们定价。

**到处为可选性买单。** 落选:这是同一枚硬币的另一面。在需要出现之前就造出通用设计,正是[四个机制,而非十二个](2026-09-18-four-mechanisms-instead-of-twelve.zh.md)删掉的东西;而一个没人需要的抽象,比一个目录更难移除。

**让每个改动自己临场决定。** 落选:第一个设计就是这么选出来的 —— 局部成立、对采用者盲;而这个答案应当能在一次会话里得到,不必每次重新推导。

**把每个这类决定都变成与维护者的讨论。** 作为默认落选、作为退路保留:当概率或成本无法由证据论证时,它是对的;当可以论证时,它太慢。

## Consequences

- 有些改动会带上一个目录、一次间接、或者比当下所需稍多的命名。这就是代价,而且改动要把它说出来,而不是留给人去发现。
- 「大概率」可能是错的。缓解办法是把这个判断写下来并论证,好让后来的读者看见当初假设了什么,并纠正它。
- 这条规则不凌驾于其他边界之上:一个会让这个包假定某一种生态的设计,或者一道会在空语料上通过的门禁,仍然拒绝。
