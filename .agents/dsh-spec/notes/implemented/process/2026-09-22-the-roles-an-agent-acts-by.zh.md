# Agent Note: agent 按什么角色行事

Status: implemented

[English](2026-09-22-the-roles-an-agent-acts-by.md) | 中文

## Problem

委派成了主线的全部工作内容,却没有任何文档说清这份工作是什么。一次会话里,活可以放在三个载体上——主线自己、后台任务、`subagent`;一批单元要同时跑,只有两种形态——`workflow`,或者并行 `subagent` 调用。而关于委派的唯一规则,管的是结果值多少:[被委派的结果是主张,不是证据](2026-09-20-three-rules-from-a-memory-pipeline.zh.md)把验收交给提交的人。这条只管委派的尾巴,前面一概没说:谁可以派活、一份 brief 欠持有者什么、持有者欠回什么、一批活什么时候有负责人、两个 agent 可以同时写哪些路径。

这个缺口在规则的第一版草稿里就现了形。写成行为——「对话留在主线,把等待交出去」——它对所有人都是建议,对谁都不是自己的规则:agent 手里没有一个位置可以对照,于是整条读完,一条也不落实。

## Decision

**brief 第一行写明持有者按什么身份行事。** 派活的 brief 以 `Role: subagent` 开头;没有任何人给过角色行的 agent 就是主线,即那个跟提问的人对话的 agent。身份是"坐在哪儿"这个事实,不是一段要靠自己去认出来的描述。

**没有谈成规划之前,主线不发生委派。** 规划是跟提问的人一起定下单元、载体与成本的地方:每个单元是什么、由哪个载体跑、复用哪个 agent、以及为什么没有更省的形状可用。委派是规划里记在账上的一笔成本,不是条件反射。

**主线让每一件活落在能装下它的最便宜载体上。** 交代加验收比自己做还贵的活,留在主线自己做。耗时的命令挂后台任务,不因此养一个 agent。自足且能被独立验证的单元交给一个 `subagent`;已经有 agent 握着相关上下文就复用它,那份上下文只会干扰判断时才开新的。

**一批活只有一个负责人。** 能同时跑的单元合成一个单元,交给一个 `subagent`:有 `workflow` 就用它,没有就并行 `subagent` 调用。这批活不从主线跑:fan-out 每完成一个单元就报一次,`workflow` 又会把调用它的线占满整段时间,两者都会把对话和工作切碎。单元里装着互不相干部件的 `subagent`,就是这些部件的 fan-out 负责人,汇报时要把它们的产物连同自己的结果一起带上来。

**持有者交回产物、输出和没能确定的事。** 交回给派它的人:产物路径、跑过的每条命令与它的原始输出、以及自己没能确定的事。一段叙述不是交回。

**一个路径只有一个写者。** brief 里的 `Scope` 是持有者唯一可写的路径集合,两个 agent 不会同时持有同一个路径的写权;fan-out 的负责人在开跑前按路径把单元切开。`Scope` 管的是交付树,不管草稿:草稿放在自己的临时目录里,两个单元不共用同一个。只要结论的单元不给写权。两个单元要写同一棵树,它们就不独立:串行跑,或者其中一个拿一个 `git worktree`。提交只有主线一个出口。

## Alternatives considered

**把规则写成行为,让每个 agent 自己套用。** 被这条规则的第一版草稿否掉了:行为没法跟位置对上,agent 判断不出一句话说的是不是自己。身份加它那一行可以对上,而写明身份的那份 brief 就点出了是哪一行。

**给工作区单独立一条规则。** 不立:写权是在规划挑载体的时候一起定的,fan-out 的负责人在开跑前按路径切分,两件事本来就一起读。单独立条等于把同一个决定写两遍。

**让主线持有 fan-out。** 不这么做:批次跑着的时候,提问的人就失去了对话,而回报还是每完成一个单元来一条。这两点正是 fan-out 要交给 agent 的原因。

**把 fan-out 负责人做成第三种身份。** 不立:等待是 `workflow` 的属性——它在前台跑——不是身份的属性。持有 fan-out 的 `subagent` 仍然是 `subagent`。

**看着像并行就派出去。** 不派:最贵的是交代,因为每个 agent 都从没有上下文开始;小到自己做更快的单元,交出去比做完还贵。同一个理由也让复用成为首选,只有当 agent 已有的上下文会干扰一件不相干的活时,才跳过复用。

## Consequences

- 主线始终保持可应答。维护者的新想法在活跑着的时候就能进来,要么改道正在跑的 agent,要么排进规划里等着。
- 成本成了跟维护者一起做的决定,而不是 agent 自己拿的主意:载体与复用都写在规划里,动工之前就定了。
- 被委派的结果有了固定形状——产物、产出它的那些命令、以及没能确定的事——然后由证据那条规则决定这个形状值多少。
- 这条规则没有门禁,也不可能有:一件活该不该派出去,树里看不出来。能机械化的部分已经被守住了——证据规则要求的验收,以及 brief 写明的 `Scope`。
- 接受三条代价。brief 的质量决定委派能到哪儿,因为 brief 就是 agent 开始时所拥有的全部上下文。fan-out 多一次转述:负责人要汇总各个单元报上来的东西。复用会把子 agent 早先的上下文一起带上,对相关的单元是优势,对不相干的单元是偏差。
