# Agent Note: 逐行门禁把标记区留作未读

Status: implemented

[English](2026-09-23-a-line-gate-leaves-a-marked-region-unread.md) | 中文

## Problem

逐行读源码的门禁看不见结构。`verify-md-link-syntax` 只要在一行里碰到批量改写留下的那两种形状就报,因为区分它们的那点信息——那对括号原本是不是链接——不在行里。于是一份有意原样保留某段文字的文件只剩两个坏选择:把冻结的文字改到门禁满意,或者让门禁一直红着,再教所有人忽略它。

整文件的情形已经有答案:冻结归档把封存的三件套移出语料,门禁根本读不到它。可这个答案救不了**活文档里的某一段**——它周围是有人写的、会变的、必须被读的正文。

这套机制上游有,而在抽取时丢了。dsh 的 `findReferenceViolations` 接受一个可选的 `excludedRange` 选择器,它的 `historical-schema-region.ts` 就靠它把一页历史格式文档里生成的 schema 摘录留作未读。本模式的 `repo-files.ts` 当初按 `split` 抽,只留了 glob 展开,逐行扫描器与那个钩子都没过来。

## Decision

`findReferenceViolations` 连同它的 `excludedRange` 参数一起移植过来;标记名有唯一的家,也有可见的效果。

- `repo-files.ts` 导出 `ReferenceViolation` 与 `findReferenceViolations`;扫描器把源码读一次,向可选选择器要一个零基、右端开区间的范围,然后恰好跳过那几行。
- `excluded-region.ts` 拥有标记对的名字。文档在独立成行的位置写 `<!-- gate-exclude:start -->` 与 `<!-- gate-exclude:end -->`,选择器返回两标记之间那段。
- `verify-md-link-syntax` 传入该选择器,于是标记区在那里被留作未读,而不必每个逐行门禁各做一遍。
- 门禁在小结旁边打印它跳过的每个区域的文件与行范围。

两条规则把它框住。标记名只有一个字面量,就在那个模块里,所以谁在语料里 grep 一个拼法,就能找到全部标记区。而半套标记不构成区域:除非恰好一个开始、一个结束且顺序正确,选择器返回 undefined,门禁读整个文件。

这是冻结归档为整文件所做的事在文件内的那一半:封存的三件套按**路径**离开语料,标记区按**行范围**离开。归档是决策的历史该去的地方;标记则留给活文档必须原样保留的文字。

## Alternatives considered

- **不移植这套机制。** 移植来的扫描器在本仓库没有消费方,所以丢掉看着不花钱;其实不然:这套技能集合要发给那些文档会引用、会冻结文字的项目,而采用者加不了引擎里没有的钩子。
- **把标记名做成项目设置。** 用一份文件列标记名,项目就能自创拼法,于是按一个拼法 grep 的人找不到其余的;这是约定,不是偏好。
- **改成按路径跳过。** 「这个文件不读」已经由范围模块表达,而它表达不了「活文件处处都读、只有一段不读」。
- **静默跳过。** 悄悄少读的门禁比会失败的门禁更糟:那行绿是评审唯一拿得到的证据,它就不再是它说的意思了。

## Consequences

**换来了什么。** 文档可以原样保留某一段,既不必让门禁失败,也不必让它一直红着;机制住在扫描器所在的地方,而不是住在第一个需要它的门禁里。文字离开门禁视野的两种方式之间的关系,现在写在一处,而不必每遇到一次重新发现一次。

**代价是什么。** 那段文字不再被**任何**门禁读取,不只是引发这个机制的那一个;所以标一次就压掉了未来所有逐行检查,项目若标了一大段,等于悄悄缩小了自己的语料,而只有那行打印出来的跳过记录会说出来。另外这个标记在文件之外看不见,所以看一份「先红后绿」的 diff 的人只能信那行记录,而不能像范围清单那样直接看到排除。

**留给读者什么。** 标记名是这套集合记录的约定,没有门禁在守:一份写错拼法的文档会被完整读,唯一症状是那行跳过记录不出现。移植来的扫描器也是下一个逐行门禁该起步的地方,于是采用者新增一个门禁时直接拿到这个钩子,而不必再立第二套约定。
