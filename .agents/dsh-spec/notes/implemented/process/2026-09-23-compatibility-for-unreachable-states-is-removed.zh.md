# Agent Note: 到不了的状态,兼容就该删掉

Status: implemented

[English](2026-09-23-compatibility-for-unreachable-states-is-removed.md) | 中文

## Problem

引擎里带着四处迁就,迁就的是安装者到不了的状态。

- `notes-root.ts` 把笔记树解析在本集合自己的路径上,**或者**解析在它被抽取出来的那个无命名空间路径 `.agents/notes/` 上;两个导出函数返回"可能的根前缀"列表,让引擎其余部分去搜。
- `verify-agent-note-format.ts` 接受一条祖父注释代替 `## Alternatives considered`(仅限日期早于 `2026-07-05` 的笔记),并封禁两个已退休的债务标记;`agent-note-tree.ts` 为这个截止日期专门带着每篇笔记的日期。
- `verify-agent-note-classification.ts` 会把把笔记放在 `docs/rfc/` 或 `docs/rfcs/` 的仓库判为失败。
- `manager.ts` 有一条分支,处理"替换副本比 `--only-skill-set` 更老"的情形,由替换副本自带的 manifest 装上技能集合,因为那份副本无法被指定目标。

这四处谁都到不了。这套集合从未发布过——`v0.1.0` 的 release 还是草稿——而已经存在的那个 tag 本身就带命名空间路径、当前正文格式和那个旗标,所以即便有人把副本钉在那个 tag 上,也进不了这四种状态中的任何一种。它们其实是本仓库自己的历史:它被抽取出来的那个布局、它迁移过的正文格式、更早的 ADR 流程用过的文档树,以及抽取还在写的时候加上的那个旗标。

代价不是那几行。每一条都是**没有构造出一个不可能存在的项目就无法覆盖**的分支;其中两条还是没有任何门禁在守的规则:笔记日期只喂了祖父截止日期,而那个无命名空间布局是对一个项目只需回答一次的问题给出的第二个答案。

## Decision

四处全删,连同只为喂它们而存在的机械:笔记的 `date` 字段与它的两个构造点、那两个前缀列表函数,以及被删分支的最后几个读者(导入与变量)。某条集合仍然想要的规则若写在了关于其中之一的注释里,注释随代码一起改——`md-scope.ts` 那句"采用者可以改这些清单"的误导说法,在这次一并改正。

引擎现在对每个问题只给一个答案:笔记树就是 `.agents/dsh-spec/notes`,除非 `AGENT_NOTES_ROOT` 替换它;笔记正文永远带 `## Alternatives considered`;分类门禁只判它自己走的那棵树;`upgrade` 只有一条第二段路径,它 re-exec 已安装的那份副本。

留下的规则是:**兼容只为用户能进入的状态而带。** 只有本仓库到得了的状态不是兼容负担,而是它自己的历史,而历史住在 git log 里。

## Alternatives considered

- **留着,反正不贵。** 写起来不贵,读起来贵:读者得先想清楚两套布局、两种正文格式、两条升级路径里哪一条适用于自己,而没有门禁能告诉他答案。
- **留下"旧副本"那条分支作为面向未来的保险。** 这是四条里唯一有真实论据的:一个早于该旗标的 ref 会打断两段式升级。但旗标就在第一个 tag 里,所以那个 ref 得是本仓库已经删掉的分支;而五层堆叠不是猜未来那种分支的地方。
- **留到第一个 release 发布之后再删。** 那时"没有用户会处在那个状态"这句就可核而非假设了。代价是第一个 release 里就带上这四处迁就,而那正是让它们永久化的原因。
- **只删笔记布局那一处的回退。** 它是最大的一处,但另外三处性质相同;只删一处,读者反而要猜剩下几条里哪条在承重。

## Consequences

**换来了什么。** 笔记放哪、正文必须带什么、一次升级怎么收尾,这三个问题在代码里各自只有一个答案,而不是一串搜索顺序;而且四处删除里有三处删掉的是一条没有门禁在守的规则——于是契约与引擎对"存在几套布局、几种格式"这件事的说法终于一致。

**代价是什么。** 在这套集合存在**之前**就采用了这套模式的项目——笔记已经在 `.agents/notes/`,或者正文还是旧格式——必须先迁移才能跑这些门禁,而没有任何东西会报告它留下的那个布局:它看到的失败说的是"树不在",而不是"你需要搬一次"。那条旧副本分支对降级也是真实保护:将来若真有某个 ref 去掉 `--only-skill-set`,升级路径就得重建而不是复用。

**留给读者什么。** 这些删除无法从代码里还原,因为接受那些状态的代码已经不在了;git log 与这篇笔记就是它们曾被接受的记录。注册表写明还剩哪些与上游不同——笔记日期与"只有命名空间根"都是偏离,将来重新抽取时必须重新决定,而不能继承。
