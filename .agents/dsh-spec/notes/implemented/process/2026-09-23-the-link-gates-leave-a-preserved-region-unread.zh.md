# Agent Note: 链接门禁把保留区留作未读

Status: implemented

[English](2026-09-23-the-link-gates-leave-a-preserved-region-unread.md) | 中文

## Problem

逐行读源码的门禁看不见结构。`verify-md-link-syntax` 只要在一行里碰到批量改写留下的那两种形状就报,因为区分它们的那点信息——那对括号原本是不是链接——不在行里。于是一份有意原样保留某段文字的文件只剩两个坏选择:把冻结的文字改到门禁满意,或者让门禁一直红着,再教所有人忽略它。

整文件的情形已经有答案:冻结归档把封存的三件套移出语料,门禁根本读不到它。可这个答案救不了**活文档里的某一段**——它周围是有人写的、会变的、必须被读的正文。

这套机制上游有,而在抽取时丢了。dsh 的 `findReferenceViolations` 接受一个可选的 `excludedRange` 选择器,它的 `historical-schema-region.ts` 就靠它把一页历史格式文档里生成的 schema 摘录留作未读。本模式的 `repo-files.ts` 当初按 `split` 抽,只留了 glob 展开,逐行扫描器与那个钩子都没过来。

## Decision

`findReferenceViolations` 连同它的 `excludedRange` 参数一起移植过来,而**两个链接门禁**都接收保留区返回的那段范围。

- `repo-files.ts` 导出 `ReferenceViolation` 与 `findReferenceViolations`;扫描器把源码读一次,向可选选择器要一个零基、右端开区间的范围,然后恰好跳过那几行。
- `excluded-region.ts` 拥有标记对的名字。文档在独立成行的位置写 `<!-- preserved-region:start -->` 与 `<!-- preserved-region:end -->`,选择器返回两标记之间那段。
- 两个链接门禁都传入该选择器:`verify-md-links` 管它解析的目标与锚点,`verify-md-link-syntax` 管改写留下的那两种形状。对两者而言,保留区都是文档自己的文字,所以项目只需要一套约定,而不是每个门禁各一套。
- 保留区里定义的锚点仍然是有效目标,所以打上标记不会把它变成入站链接够不着的孤岛。标记取消的是对**这段文字自身链接**的评判,不是这段文字的存在。
- 每个门禁在小结旁边打印它跳过的每个区域的文件与行范围。

两条规则把它框住。标记名只有一个字面量,就在那个模块里,所以谁在语料里 grep 一个拼法,就能找到全部保留区。而半套标记不构成区域:除非恰好一个开始、一个结束且顺序正确,选择器返回 undefined,门禁读整个文件。

这是冻结归档为整文件所做的事在文件内的那一半:封存的三件套按**路径**离开语料,保留区按**行范围**离开。归档是决策的历史该去的地方;标记则留给活文档必须原样保留的文字。

## Alternatives considered

- **不移植这套机制。** 移植来的扫描器在本仓库没有消费方,所以丢掉看着不花钱;其实不然:这套技能集合要发给那些文档会引用、会冻结文字的项目,而采用者加不了引擎里没有的钩子。
- **只接进一个门禁,让解析链接那门继续读这段。** 这是第一版的做法,也贴合上游使用该选择器的方式。它落选,是因为这段文字是项目自己的东西:一段引文里的链接指向早已不存在的东西,恰恰是标记存在的理由;而解析门禁仍在它上面失败,就等于标记对这唯一要紧的场景无效。
- **按"它排除了什么"给标记起名。** `gate-exclude` 读起来是一句对**每个**门禁的承诺,而引擎兑现不了——门禁在读,直到它自己去要那个选择器。现在这个名字陈述的是意图,而尊重它的两个门禁写在标记定义的地方。
- **把标记名做成项目设置。** 用一份文件列标记名,项目就能自创拼法,于是按一个拼法 grep 的人找不到其余的;这是约定,不是偏好。
- **改成按路径跳过。** 「这个文件不读」已经由范围模块表达,而它表达不了「活文件处处都读、只有一段不读」。
- **静默跳过。** 悄悄少读的门禁比会失败的门禁更糟:那行绿是评审唯一拿得到的证据,它就不再是它说的意思了。

## Consequences

**换来了什么。** 文档可以原样保留某一段,既不必让链接门禁失败,也不必让它一直红着;文字离开门禁视野的两种方式写在一处:归档按**路径**放走整个文件,标记按**行范围**放走一段。保留区里的锚点对整个语料仍然可解析,所以打标记不会让它成为孤岛。

**代价是什么。** 标记只覆盖那两个链接门禁,别的门禁照读这段——因为选择器要靠门禁自己去要。后来新增的门禁会读整个文件,直到有人教它去要;这是安全的默认值,也意味着一个标记并不是"没有门禁会评判这里"的通用承诺。两个链接门禁都会打印自己跳过了什么,于是那行绿自己说明了它的覆盖范围,不必让读者去假设。

**留给读者什么。** 标记名是这套集合记录的约定,没有门禁在守:一份写错拼法的文档会被完整读,唯一症状是那行跳过记录不出现。这个名字描述的是**文字的状态**,而不是对门禁的效果,因为效果属于那些自己去要选择器的门禁。
