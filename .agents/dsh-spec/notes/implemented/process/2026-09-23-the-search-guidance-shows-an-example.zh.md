# Agent Note: 检索指引只讲排除,命令只作示例

Status: implemented

[English](2026-09-23-the-search-guidance-shows-an-example.md) | 中文

## Problem

召回探针这份参考里长出了两节讲怎么跑检索的文字:`## Running the batteries` 讲怎么调用工具、哪些路径必须点名叫上,`## Shell rendering` 讲在没有检索工具时用 `grep` 兜底、以及同一批模式在 `ripgrep` 下的写法。它们是这份参考被改成「工具中立」那一次留下的:命令换成了讲工具的散文,于是文件里多出一段关于检索行为的描述——而那本该属于读者手上已经有的那个工具。

代价不只是变长。这份参考真正耐久的部分是模式与排除清单;讲调用的散文横在读者和这两样东西之间,而它描述的工具,这个项目并不依赖,文件的主题也不是检索。手里有工具的读者什么也没学到;手里没有工具的读者拿到的是一个兜底写法,而不是唯一要紧的那个事实:哪些树不能读。

## Decision

参考讲清排除,并把命令当作模式的一种渲染,而不是操作指令。

- `## Exclusions` 点名 vendored、冻结、自引用与夹具这几类树,说明各自为什么出局;并写明 `.agents/` 属于语料而非排除项——Agent Note 正是这次清理找到漏网之鱼的地方。
- 属于模式而非工具的判断规则(完整短语、先校准、反语言面)放在开头的段落里,读者在任何命令之前先碰到它们。
- 每批探针就是一条命令行,排除清单在它上方只讲一次——读者看到一次检索长什么样,而不必读一份工具手册。`ripgrep` 不进 README 的前置条件表:示例里出现它,项目不要求它,参考也写明命令只是一种渲染。
- `dsh-prose-standard` 用紧凑写法讲 vendored 排除,去掉同一次改写在那里加的工具中立从句。

## Alternatives considered

- **保留工具中立那套散文。** 它正是这次要删掉的那两节的来源:讲工具的散文比它替代的那条命令更长,而且跑不起来。
- **把 `ripgrep` 定成依赖并写进前置条件。** 诚实,写起来也更省事;但那会让一份讲散文质量的参考依赖某一种检索实现,而前置条件表是给只需要 Node 与 Git 的安装者看的。
- **只留模式列表,命令全删。** 模式才是耐久的部分,所以损失不大;但示例是唯一告诉读者大小写与排除该怎么配合的东西,删了就都得自己重建。
- **留兜底、删示例。** 那会变成描述检索却不展示检索,正是这个决定要撤销的那种失法。

## Consequences

**换来了什么。** 参考先讲一次检索必须排除什么,再展示一种跑法,于是耐久的事实不必绕道工具行为就能拿到,而 README 的前置条件表仍然只列安装者需要的东西。

**代价是什么。** 环境里没有 `ripgrep` 的读者拿到的是一段贴不进去的示例;排除清单与模式仍然可用,参考也这么写了,但读者得自己映射一次。另一个代价是把示例当成规范:后来改这份参考的人可能因为命令看起来像干货,就往里加工具特有的行为——那两节被删掉的文字就是这么长出来的。

**留给读者什么。** 排除清单只讲一次,命令里一条都不重复,所以换一种检索实现时,清单要手工带过去。参考给的是排除用的 glob,而不是某个工具的开关写法;这个缺口是刻意的:开关在工具之间会变,树不会。
