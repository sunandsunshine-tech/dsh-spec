# Agent Note: 简化技能跟上游这次的改写

Status: implemented

[English](2026-09-23-the-simplifications-skill-follows-upstream.md) | 中文

## Problem

我们的 `dsh-find-simplifications` 改写自上游一份更早的文本:157 行,枚举什么算强候选——没有消费者的方法、彼此镜像的表示、投机性的通用性、手写的轮子——然后让读者逐个证明或否决。上游把它换成了一份短得多的指南:讲清范围,给出六个发现用的提问,再讲可达性、归属与失败语义、基础设施替换、以及记录与验证,并把所有实例搬进一个参考文件。

旧形状在这套集合发布出去的场景里有两个问题。它的判据是一份逐条打勾的清单,而不是一组要问的问题:一条判据都不沾的候选永远没人考虑,而沾上一条的就被当成已证明。它的语境也属于某一个项目:例子里点名的是那个仓库自己的子系统、它的两个提供方、它的包管理器;别的项目里的读者得先翻译一遍,那些话才有意义。

## Decision

采用上游的结构,并对它的文字套用本集合的抽取标准。

六节照搬:范围与约束;六个发现用的提问;可达性与取舍;归属与失败语义;只在净削减时才替换基础设施;记录、合并与验证。dsh 专属的锚点或泛化、或删掉:它要读的文档路径改成"项目自己关于架构、防御模式与测试留下什么";它的笔记链接改成这套集合的笔记契约;它的子系统清单改成"项目自己的子系统";它的包管理器与文档命令改成项目的聚合检查与它自己的门禁;它的两条产品约束删掉,因为"两个提供方是刻意的"是一个产品的决定,不是关于简化的规则。

实例住在 `references/historical-patterns.md` 里,每条模式分三层:判断、它权衡了哪些因素、什么条件会推翻它、以及它出自哪些案例。六个发现用的提问只抽象地陈述主题,自己不携带任何实例——原先待在提问里的每处例证,都下沉到了它所属的那条模式。上游的引用不带:那些笔记并不随这套集合安装,指向它们的链接是没人能跟的指针;案例是重述的源项目自己的材料,由采用它的项目换成自己的。在这里解析得到的三个指针照留,因为每个都指向这套集合发布的技能:散文标准、推送前检查、以及拥有替代处置的归档工作流。

## Alternatives considered

- **留着 157 行那版,把新提问补进去。** 那样一份文档里会同时存在两套组织同一主题的方式,读者还得自己判断眼前这个候选归哪一半管。
- **照搬新文本,连路径一起。** 那就会发布一批采用者项目里并不存在的文件引用,而读者学到的第一件事是:这个技能是给别人写的。
- **搬新文本但不带模式参考。** 六个提问于是成了整个技能,而它们需要的校准——不可达的特性长什么样、为什么包变少不算证明——就没了。
- **留着参考文件里的引用,接受死链。** 冻结的笔记不能修,那条链接会永远坏着,而这里没有任何门禁会去检查一个没被安装的笔记。

## Consequences

**换来了什么。** 这个技能问的是读者能用在"并非为它而写"的项目上的问题,而它的可用知识分两层:六个提问陈述判断,下面的参考文件为每条判断补上它权衡过哪些因素、什么条件会推翻它、以及它出自哪些案例——于是一条判据都不沾的候选也仍然够得着,读者也能拿判断去和它的案例对照,而不是相信一条光秃秃的规则。

**代价是什么。** 参考文件不带引用:教训出自哪份记录并不随本集合安装,于是案例是重述的,想拿它跟出处核对的读者得自己去找那份记录。泛化后的范围建议也比一份实例清单弱:"项目自己的子系统"说的是去哪儿找,而不是那里通常藏着什么;而给每条模式都写上权衡的因素与推翻条件,也让参考文件比它替掉的那份实例更长,并且那些案例在采用者换成自己的之前,读起来就是一个项目的历史。

**留给读者什么。** 参考文件就是那份校准,所以一个自己攒下简化记录的项目,应当从那里引用自己的记录,而不是永远相信这几条模式;这套集合没有任何东西在守这件事,而文件把它的案例标明为源项目自己的材料,而不是规则的一部分。
