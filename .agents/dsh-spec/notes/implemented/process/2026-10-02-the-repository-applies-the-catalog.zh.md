# Agent Note: 本仓库采用这份规范目录

Status: implemented

[English](2026-10-02-the-repository-applies-the-catalog.md) | 中文

## Problem

[项目应用它自己挑选的规范](2026-09-22-a-project-applies-the-norms-it-chooses.zh.md)记下了本仓库不应用自己的目录:这些规范就是从它提炼出来的,装回来就是把同一份指导写两遍,而两处说法迟早会漂。当时有一条测试守着这条线。

有两件事变了。目录被压缩成对任何项目都成立的规则,而不再是本仓库自己的机器;每条规范又多了一行不变量,由管理器从目录本身渲染进 `AGENTS.md` 的钩子,而不是手写;`norms.md` 里每个块的正文,才是较长的说明。

## Decision

本仓库应用这份目录。`norms install --all` 写出 `.agents/dsh-spec/norms/norms.md` 与 `applied.yaml`,`AGENTS.md` 带上钩子。守着相反结论的那条测试被反转:改为断言文件存在、钩子在位。

钩子承载通用不变量。每条规范的规则只说一次,就是管理器渲染进钩子的那行 `invariant`;`AGENTS.md` 的常设条款只留本仓库自己加的内容。同一条规则写两遍,就是一条会漂的规则。

上一篇保留它拥有的东西——机制、记录,以及"选择归项目"这件事;本篇拥有的是它对"本仓库"那一项决定的翻转。

## Alternatives considered

**继续什么都不应用。** 落选:其中好几条规则此前只写在常驻指令里,而一条只有翻开文件才遇到的规则,正是长程运行会丢掉的规则。钩子把每条红线摆到每一次会话面前。

**应用目录,但不动那篇旧 note。** 落选:读者会读到两篇已实现的记录,对本仓库是否应用规范各说各话,而且彼此没有链接。

**把红线手写进 `AGENTS.md`。** 落选:那就是同一条规则的第二个出处,两者会漂——正是上一篇要避免的失败。

## Consequences

- 改一条规范,改到的是本仓库生成出来的文本:`body` 落在 `.agents/dsh-spec/norms/norms.md`,`invariant` 落在 `AGENTS.md` 的钩子。而 `norms update` 会拒绝覆盖手改过的块——保护采用者的那道漂移检查,同样保护本仓库。
- 目录既是本仓库发布的,也是本仓库遵守的:一条在这里不成立的规则,不该留在里面。
- 每应用一条规范,`AGENTS.md` 就多一行红线;本仓库应用的十四条规范,对应十四行。
