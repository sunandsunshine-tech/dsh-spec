# Agent Note: 逐行门禁把标记区留作未读

Status: proposed

[English](2026-09-23-a-line-gate-leaves-a-marked-region-unread.md) | 中文

## Problem

逐行读源码的门禁看不见结构。`verify-md-link-syntax` 只要在一行里碰到批量改写留下的那两种形状就报,因为区分它们的那点信息——那对括号原本是不是链接——不在行里。于是一份有意原样保留某段文字的文件只剩两个坏选择:把冻结的文字改到门禁满意,或者让门禁一直红着,再教所有人忽略它。

整文件的情形已经有答案:冻结归档把封存的三件套移出语料,门禁根本读不到它。可这个答案救不了**活文档里的某一段**——它周围是有人写的、会变的、必须被读的正文。

这套机制上游有,而在抽取时丢了。dsh 的 `findReferenceViolations` 接受一个可选的 `excludedRange` 选择器,它的 `historical-schema-region.ts` 就靠它把一页历史格式文档里生成的 schema 摘录留作未读。本模式的 `repo-files.ts` 当初是按 `split` 抽的,只留了 glob 展开,逐行扫描器与那个钩子都没过来,这里也就无从表达「这一段是刻意保留成这样的」。

## Proposal

把机制移植过来,并给它唯一的家与可见的效果。

`findReferenceViolations` 连同它的 `excludedRange` 参数一起过来。新增的 `excluded-region.ts` 拥有标记对的名字——文档在独立成行的位置写 `<!-- gate-exclude:start -->` 与 `<!-- gate-exclude:end -->`——并返回两标记之间那段作为门禁传入的选择器。`verify-md-link-syntax` 接上它,于是标记区在那里被留作未读,而不必每个门禁各做一遍。

两条规则防止它变成藏文字的手段。标记名只有一个字面量,就在那个模块里,所以谁在语料里 grep 一个拼法,就能找到全部标记区。而半套标记不构成区域:除非恰好一个开始、一个结束且顺序正确,选择器返回 undefined,门禁读整个文件。

门禁点名它跳过了什么。一次把某段留作未读的运行,会在小结旁边打印文件与行范围——对没读过的文字报绿却不说明,正是这套集合的证据规则要防的那种失法。

## Alternatives considered

- **不移植这套机制。** 移植来的扫描器在本仓库没有消费方,所以丢掉看着不花钱;其实不然:这套技能集合要发给那些文档会引用、会冻结文字的项目,而采用者加不了引擎里没有的钩子。
- **把标记名做成项目设置。** 用一份文件列标记名,项目就能自创拼法,于是按一个拼法 grep 的人找不到其余的;这是约定,不是偏好。
- **改成按路径跳过。** 「这个文件不读」已经由范围模块表达,而它表达不了「活文件处处都读、只有一段不读」。
- **静默跳过。** 悄悄少读的门禁比会失败的门禁更糟:那行绿是评审唯一拿得到的证据,它就不再是它说的意思了。

## Acceptance criteria

- `repo-files.ts` 导出 `ReferenceViolation` 与 `findReferenceViolations`,后者接受 `excludedRange`。
- `excluded-region.ts` 以一个字面量持有标记名,并且只在一对有序标记恰好齐备时返回范围。
- `verify-md-link-syntax` 把标记区留作未读,并打印它跳过的文件与行范围。
- 半套标记会被照读,两个结果都有用例覆盖。
- 注册表按扫描器取来的那个修订记录 `repo-files.ts`,relation 与 note 一并更新。

## Risks

那段文字不再被**任何**门禁读取,不只是引发这个机制的那一个;所以标一次就压掉了未来所有逐行检查,项目若标了一大段,等于悄悄缩小了自己的语料,而只有那行打印出来的跳过记录会说出来。另外这个标记在文件之外看不见,所以看一份「先红后绿」的 diff 的人只能信那行跳过记录,而不能像范围清单那样直接看到排除。
