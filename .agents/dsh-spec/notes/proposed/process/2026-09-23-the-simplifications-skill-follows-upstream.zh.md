# Agent Note: 简化技能跟上游这次的改写

Status: proposed

[English](2026-09-23-the-simplifications-skill-follows-upstream.md) | 中文

## Problem

我们的 `dsh-find-simplifications` 改写自上游一份更早的文本:157 行,枚举什么算强候选——没有消费者的方法、彼此镜像的表示、投机性的通用性、手写的轮子——然后让读者逐个证明或否决。上游把它换成了一份短得多的指南:讲清范围,给出六个发现用的提问,再讲可达性、归属与失败语义、基础设施替换、以及记录与验证,并把所有实例搬进一个参考文件。

旧形状在这套集合发布出去的场景里有两个问题。它的判据是一份逐条打勾的清单,而不是一组要问的问题:一条判据都不沾的候选永远没人考虑,而沾上一条的就被当成已证明。它的语境也属于某一个项目:例子里点名的是那个仓库自己的子系统、它的两个提供方、它的包管理器;别的项目里的读者得先翻译一遍,那些话才有意义。

## Proposal

采用上游的结构,并对它的文字套用本集合的抽取标准。

六节照搬。dsh 专属的锚点或泛化、或删掉:它要读的文档路径改成"项目自己关于架构、防御模式与测试留下什么";它的笔记链接改成这套集合的笔记契约;它的子系统清单改成"项目自己的子系统";它的包管理器与文档命令改成项目的聚合检查与它自己的门禁;它的两条产品约束——两个提供方是刻意的、某种存储格式是唯一第一方提供方——删掉,因为那是一个产品的决定,不是关于简化的规则。

实例搬进 `references/historical-patterns.md`,写成"模式 + 它教了什么",不带上游的引用:那些笔记并不随这套集合安装,指向它们的链接是没人能跟的指针。在这里解析得到的三个指针照留——散文标准、推送前检查、以及拥有替代处置的归档工作流——因为每个都指向这套集合发布的技能。

## Alternatives considered

- **留着 157 行那版,把新提问补进去。** 那样一份文档里会同时存在两套组织同一主题的方式,读者还得自己判断眼前这个候选归哪一半管。
- **照搬新文本,连路径一起。** 那就会发布一批采用者项目里并不存在的文件引用,而读者学到的第一件事是:这个技能是给别人写的。
- **搬新文本但不带模式参考。** 六个提问于是成了整个技能,而它们需要的校准——不可达的特性长什么样、为什么包变少不算证明——就没了。
- **留着参考文件里的引用,接受死链。** 冻结的笔记不能修,那条链接会永远坏着,而这里没有任何门禁会去检查一个没被安装的笔记。

## Acceptance criteria

- `SKILL.md` 载有六节,不含 dsh 专属的路径、命令、子系统或产品约束,描述在目录预算之内。
- `references/historical-patterns.md` 逐条给出模式与教训,不引用这套集合不发布的笔记。
- 两份文件里的每个链接都能解析,参考文件可从入口到达。
- 结构门禁与链接门禁通过,全套检查为绿。

## Risks

模式参考失去了证据。读者再也打不开某条教训出自哪份记录,于是模式只能被相信或重新发现,而不能被核对;另一个选择是一条解析不到任何地方的链接。泛化后的范围建议也比原来那份清单弱:"项目自己的子系统"告诉读者去哪儿找,却没告诉他那里通常藏着什么——而那正是实例原本提供的东西。
