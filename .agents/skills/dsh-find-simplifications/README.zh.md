# dsh-find-simplifications

[English](README.md) | 中文

## Summary

在候选有证据、决定有归属之前，「找些可简化的东西」还不是一项任务。本技能通查一个仓库里那些代价高于收益的表面——死掉的、重复的、投机的、过度构建的、加了又删的，以及在已有依赖时仍手写的——然后逐条证明或否决候选，并把值得留下的那些记录成 Agent Note。它是指导，不是清单：跟随代码，保持判断，宁可要少数几条证据扎实的候选，也不要一堆单薄的猜测。

## 何时加载它

当工作是在本仓库里寻找不明显的简化候选时加载它；删除冗余注释或实现细节过重的文档时加载它；撰写提案型 Agent Note 或内联 `TODO`/`FIXME`/`XXX` 笔记时加载它；审计或合并已被取代的 Agent Note 时加载它；或者从另一个拉取请求或分支里收拢有价值的简化想法时加载它。

## 什么才算候选

一条强候选会删除、折叠或降级某个真实存在的东西，并且证据表明当前设计的代价高于收益：没有生产消费方的公开方法、事件、配置开关、辅助函数、包、持久事件或测试产物；同一事实的两份表示，尤其是持久记录与内存中的瞬时事件之间；接缝上每个实现都必须支持、却没有任何调用方的方法；只为测试或演示而存在的包；没有产品归属者的投机性产品通用化；只为保护一个无人使用的 API 而存在的不变量、回滚路径或预期输出；或者手写代码在做维护良好的包、或引擎下限上的 Node 内置模块已经提供的事。通查从最大的生产代码增量开始，而不是从显而易见的未使用符号开始；伴随不变量只有在比较可能产生分歧、且彼此独立产生的观测时，才算有用。

## 它不会提什么

- **它不会为一条单薄的候选立项。** 一个错别字、一次 `knip` 运行，或者没有调用点证据的「这看起来很复杂」，都不构成 Agent Note；正确但太小的想法改为一条带稳定标签的定向 `TODO`。
- **它不会不去胜过记录中的理由就改动被记录下来的边界。** 有意重复的适配器对、只有一个一方实现的后端中立接口、内置依赖和决策记录都是已经定下的事：候选必须扛得住记录中的推理，而不只是引用一条策略。
- **它不会移除仍有生产调用方的东西**——那是功能决定，不是清理——也不会强行制造与目标无关的改动，而公开 API 与必需行为毫无变化。
- **它不会把每次代码通查都扩张成一次仓库级笔记审计**，也绝不编辑已封存的笔记：保留判断与封存机制属于 [`dsh-archive-agent-notes`](../dsh-archive-agent-notes/SKILL.md)。
- **它不会仅仅为了保住候选数量**而从兄弟分支搬运重复或可信度更低的提案。

## 它的检查如何运行

它的证据是搜索与阅读，不是门禁：消费方被分为生产、非生产或有歧义三类，然后递归搜索确切的符号、事件名、模块名、配置键、方法名和线上字符串，先读调用点，再动笔。值得留下的提案成为 `.agents/dsh-spec/notes/<lifecycle>/<class>/` 下的一个文件，按 [笔记约定](../dsh-spec-manager/templates/notes-README.md.template) 撰写。本技能只交付散文，不含任何代码；门禁位于整个集合唯一的代码归属 `../dsh-spec-manager/scripts/`，并按名称通过它们旁边的分发器 `run.ts` 寻址：

```sh
pnpm dlx --allow-build=esbuild tsx@4.22.4 .agents/skills/dsh-spec-manager/scripts/run.ts --all --root .
```

对于只涉及文档的笔记工作，检查就是该聚合命令加上 `git diff --check`；改动代码注释或技能时还要运行覆盖它的校验器，其余证据经由 [`dsh-pre-push-checks`](../dsh-pre-push-checks/SKILL.md) 选择。当通查包含散文时，注释必须保住什么由 [`dsh-prose-standard`](../dsh-prose-standard/SKILL.md) 管。
