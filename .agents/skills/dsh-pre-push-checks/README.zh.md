# dsh-pre-push-checks

[English](README.md) | 中文

## Summary

在推送之前把相关的本地证据跑一次。本技能的存在，是为了拦住那只伸手去跑整个仓库测试套件的手：证据由外发的差异选出，一道检查之所以运行，是因为改动可能影响它所覆盖的东西，而不是因为快要推送了。CI 负责穷举覆盖和平台矩阵；git 钩子保持窄小——pre-commit 修复已暂存的 lint、检查已暂存的空白并守护内置源码的元数据，pre-push 只跑增量类型检查。

## 何时加载它

在推送、强制推送、把 PR 标记为可供评审，或声称某个分支的检查通过之前加载它；在 `gh stack sync` 发布被改写过的分支之后立即加载它；在合并了变动过的基线、需要重新评估合并后的范围时也加载它。唯一的顺序例外是 `gh stack sync` 本身：它把变基与推送级联成一次操作，因此无法在改写与发布之间插入本地验证。

## 按改动面选择证据

确认检出与分支，核实实时的 PR 基线或栈父分支，抓取它，并从 `git diff --name-only <verified-base-ref>...HEAD` 加上 worktree 仍然持有的内容取得范围。然后选择能为该回归失败的最窄测试或专用检查：

| 改动触及 | 证据 |
|---|---|
| 模块或脚本行为 | 归属的测试文件，或其中聚焦的测试；共享约定变动时加上相邻模块的测试 |
| 决策记录或与文档相连的注释 | 笔记门禁，按名称通过分发器选择 |
| 配对文档或其译文 | `verify-translation-pairing` |
| `skills/` | 覆盖所触及技能的各道门禁，加上本仓库的 `scripts/verify-skill-structure.ts` |
| 读者会到达的散文 | `verify-md-links`、`verify-md-link-syntax`、`verify-md-metadata` |
| 模型、编辑器、CLI（命令行界面）或终端可见的输出 | 拥有该输出的聚焦记录输出场景，或真实可运行的示例 |
| manifest、导出、构建配置或入口点 | 构建门禁、相关的卫生检查，以及针对构建产物的冒烟测试 |
| 真实 provider 或 agent（智能体）行为 | 凭据可用时跑相关的端到端目标——并且绝不打印密钥 |

单元覆盖率相关时，同时点名归属的测试和这些测试必须证明的源码范围，并在所选范围内保持配置好的阈值。

## 它拒绝运行什么

- **除了钩子之外没有通用的本地基线**，也不仅仅因为随后要提交或推送就重复一次已经通过的检查——包括会与 pre-push 钩子重复的类型检查。
- **不做完整的本地预演**，除非用户要求，除非正在诊断一次 CI 失败，或者这次改动横跨面太广、任何更窄的组合都不可信。
- **不用裸 `--force`。** 独立分支的历史改写针对刚抓取的远端，用 `--force-with-lease=<branch>:<observed-oid>` 发布，这样并发移动会中止推送。
- **不因为 `gh stack sync` 返回了就声称栈已就绪。** 每一层被改写的分支都会重新确定范围并对照实时基线重新验证，在所选的检查通过之前 PR 一直保持未合并。
- **不掩盖未覆盖的文件**：绝不用 `--passWithNoTests`，绝不降低阈值，绝不为了让一次运行变绿而缩小源码范围。

## 它的检查如何运行

门禁是代码，位于整个集合唯一的代码归属 `../dsh-spec-manager/scripts/`；本技能只交付散文，不含任何代码。它按名称通过旁边的分发器 `run.ts` 寻址，从不按路径，而分发器用该目录里的门禁脚本解析名称，遇到未知名称就拒绝，而不是跳过。有一道门禁有意不在上表占一行：凭据扫描不按路径选择，因为任何改动都可能引入凭据，所以它随聚合检查一起跑。

```sh
pnpm dlx --allow-build=esbuild tsx@4.22.4 .agents/skills/dsh-spec-manager/scripts/run.ts verify-agent-note-format --root .
pnpm dlx --allow-build=esbuild tsx@4.22.4 .agents/skills/dsh-spec-manager/scripts/run.ts --all --root .
```

`--all` 运行引擎目录里的每一道门禁，某一道失败时失败，一道都没有时也失败——因此它就是「整套检查」的含义，属于推送前或里程碑节点，而所选子集则持续运行。
