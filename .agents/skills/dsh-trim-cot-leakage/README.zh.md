# dsh-trim-cot-leakage

[English](README.md) | 中文

## Summary

思维链泄漏是写自产出它的那次会话内部的散文：它引用只有那次会话看得见的产物，叙述改动而不是叙述状态，或者与一位已经离开的评审人争辩。本技能找出这些段落并修复它们，而修复不是单纯删除——带有事实性从句的段落，要把每一条从句重述到在 HEAD 上站得住，只删掉围绕它的过程记录；一条事实都不带的段落，例如审计编号或控制流叙述，则整段删除。

## 何时加载它

在审计或修复读起来像泄漏的推理记录的散文时加载它：注释、API 文档、文档、提示词、诊断信息或决策记录。它的对象包括死掉的设计会话引用，例如 `(decision 7)` 或 `design §4.7`；栈与 PR（Pull Request）视角；改动叙述与版本印记；评审安排与面向评审人的辩解；重述与推导过程；含糊的规划残留；以及出现在错误语言里的撰写语言片段。

## 唯一一条检验

对每一段可疑文字：一位在 HEAD 上的读者，接触不到任何会话记录、PR 讨论串或未提交草稿，能否解析每一个引用并验证每一条断言？不能，就把仍然成立的事实按仓库的视角重述，删掉其余部分。能，它就不是泄漏，无论听起来多么像历史——不过可解析只满足本技能的门槛；在 README、文档页或 API 注释这类当前状态的表面上，一段可解析的改动故事仍然是改动叙述。

## 修剪之后留下什么

不带辅助的引用清理在两个方向都会出错，因此保留规则按原文执行：议题引用（`#1470`、`TODO(name):`）在任何表面上都保留；Agent Note 里对已合并 PR 和议题的引用是受认可的证据；抑制说明——linter 禁用理由、覆盖率忽略理由、空 catch 的解释——是必需的散文，其错误的理由要修正而不是删除；现在时反事实的回归钉子、实测边界与运行时的旧/新状态保留；带自己 § 编号的外部标准保留；项目口吻和笔记的「替代方案」小节保留。[`examples.md`](references/examples.md) 逐类校准。

## 它拒绝做什么

- **它绝不删除带有事实的段落**而不先重述那条事实；它要防的风险，是一次修剪把义务翻转成背书，或者丢掉了出处。
- **它绝不触碰 `vendor/` 或 `.agents/dsh-spec/notes/archived/`**，也绝不在缺少归属行为证据时改动模型可见或用户可见的字符串。
- **它绝不为了修散文而编辑已记录的 fixture 或快照。** 那些是派生物：修正归属的源文件或场景，并且只在被授权的行为改动需要新证据时才重新生成。
- **它不把召回探针组当作定义。** 这些探针天生过匹配、也天生漏匹配，因此每一轮还要不拿任何模式去通读范围内最密集的散文；而一个零命中的模式，在它能命中一个已知正例之前什么也证明不了。

## 它的检查如何运行

[召回探针组](references/recall-batteries.md) 是 ripgrep 探针，不是门禁，而本技能只交付散文，不含任何代码。机械运行的是项目自己的检查，按名称通过整个集合唯一代码归属 `../dsh-spec-manager/scripts/` 里的分发器寻址：

```sh
pnpm dlx --allow-build=esbuild tsx@4.22.4 .agents/skills/dsh-spec-manager/scripts/run.ts --all --root .
```

一次修剪可能弄坏它移动过的链接，或弄坏它修正过的配对，因此在跑聚合检查之前，双语围栏要逐字节复制到两侧，并用 `verify-translation-pairing --write` 重新记录该配对。
