读者:准备把一个仓库在 GitHub 上设为 public 的维护者,或已经 public 但要做一次基线审计的维护者。用法:从上到下作答;`适用` 条件不成立的题直接跳过,[`checklist.md`](checklist.md) 里对应的任务也不会出现。

表单不复制来源内容,只引用编号;各文件的分工见文末「文件构成」。

## 作答方式(给 agent 与填表人)

- **先取证,再作答。** 事实题的答案在仓库里:文件、Settings、git 历史、依赖清单、release 与 tag。取证结果写在答案旁,便于复核。
- **`作答:实测`** — agent 可直接依据取证结果选择。
- **`作答:决定`** — 涉及法律、品牌、成本或团队偏好;agent 给建议,不替用户决定。
- **`作答:预期`** — 关于未来(维护者投入、资金、长期状态);必须向用户提问,并先解释每个选项的意味与代价。
- **不要只勾选。** 每个选择连同它触发的任务编号一起输出,任务正文在 [`checklist.md`](checklist.md)。

## 字段契约(供脚本与生成器解析)

题库文件 [`questions.md`](questions.md) 的排版是固定的,任何脚本都可以按下面的形状解析;把它渲染成可交互 HTML 时,题目映射为 fieldset、单选映射为 radio、多选映射为 checkbox、`为什么问`/`社区主流` 与各选项 tips 映射为说明文本、`→` 映射为任务链接。

| 元素 | 形状 | 说明 |
|---|---|---|
| 分组 | `## <字母> <名称>` | F/L/P/H/S/A/R/C/I/G 十组 |
| 题目 | `### Q-<字母><数字> <标题>` | 题目 id 全局唯一,被 `checklist.md` 引用 |
| 元信息 | `**类型** <单选\|多选> · **适用** <条件> · **作答** <实测\|决定\|预期> · **依据** [S..][S..]` | 固定顺序,`·` 分隔 |
| 题目说明 | `> **为什么问(tips)** …` 与 `> **社区主流(tips)** …` | 一个引用块、两段,顺序固定 |
| 选项 | `- **<选项名>**` | 顶格,无其他内容 |
| 选项字段 | `  - **意味(tips)** …` / `  - **主流何时选(tips)** …` / `  - **代价(tips)** …` | 缩进两格,顺序固定,`代价` 可缺 |
| 选项元信息 | `  - [置信] · [S..] · → \`任务\`` | 缩进两格,末行;置信取值见下 |

**置信取值** `[平台规则]`(GitHub 的机制或默认值)、`[共识]`、`[争议]`、`[少数]`、`[材料稀薄]`、`[过时]`。同一道题里可以同时存在多个 `[共识]` 选项——共识指「主流会这样选」,不等于「只有一种对」。

**`适用` 的写法** `任意`,或对另一题答案的引用,如 `F4 含注册中心发布`、`F5 为「有」`、`I2 非「禁止」`、`F6 含 vendored 或派生内容`。

## 文件构成

- 本文件 `form.md` —— 说明、agent 钩子与字段契约;这里不放题目。
- [`questions.md`](questions.md) —— 62 道题的题库,按本文件的字段契约排版。
- [`checklist.md`](checklist.md) —— 由选择推导的任务总表。
- [`sources.md`](sources.md) —— 每一条 `[Snn]` 的出处、日期与复核台账。
- [`example-answers.md`](example-answers.md) —— 填表结果示例:实测题带证据,决定题带建议,末尾附交互问询样例。
- [`example-plan.md`](example-plan.md) —— 由填表结果推导的公开执行规划示例(阶段、依赖、验收、明确不做的项)。
- [`making-this-repository-public.md`](making-this-repository-public.md) —— 本仓库公开前的实测报告(归档,只有中文一侧)。

## 填完之后

把每题选中的选项收集起来,每个选项右端的 `→` 编号就是触发任务;到 [`checklist.md`](checklist.md) 里按 `PRE` / `DAY` / `P30` / `LONG` 四段执行。没有出现过的任务编号说明对应事实不成立,直接跳过。

表单本身不随仓库公开状态变化而变化;会变化的是 `sources.md` 里标注为「平台规则」的来源——[`sources.md`](sources.md) 的复核台账给出了下次复核日。来源更新后,只需回到引用该来源的题目,改选项或改「主流何时选」的措辞。

有七条任务不由任何选项触发,它们按定义始终适用或纯属可选:`DAY-01`(切换可见性)、`DAY-13`(匿名验证)、`P30-04`(观察外部输入)、`LONG-03`(复核来源台账)属于前者;`DAY-14`(发布公告)、`P30-02`(首个公开版本的完整说明)、`P30-06`(接入 Scorecard)属于后者。它们的触发关系同样记在 [`checklist.md`](checklist.md) 末的速查表里。
