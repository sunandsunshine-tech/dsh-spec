# dsh-code-review

[English](README.md) | 中文

## Summary

评审是一个人判断一次改动是否正确，而不是判断模板是否被填满。本技能让评审者对好这个代码库评审所依据的东西——根 `AGENTS.md` 与各子树自己的常驻指令、防御式模式指南、要求的测试层级、决策记录——并列出仅凭代码看不出的那些检查：意图与接口约定、生命周期与并发、能力与消费方是否匹配、范围与必要性、执行路径、边界、真实入口路径、测试强度，以及记录输出的改动。它的报告指出路径和有问题的层面；它不替代阅读差异。

## 何时加载它

在本仓库评审一个 PR（Pull Request）时加载它，在收到评审意见时也加载它。对于双语改动，还要读翻译规则和术语表，并且无论如何都按差异本身的质量来评审。

## 评审者的路径

先核实实时的基线和确切的头，然后用 `git diff --name-only <verified-base-ref>...<verified-head-ref>` 确定改动范围，再读差异以及足够理解设计的周边代码；在改基或合并之后重新核实两者。优先看正确性、生命周期、安全和被破坏的必需行为，而不是风格——一条有据可依的阻塞项胜过一长串吹毛求疵。说明缺陷、位置、影响和证据；把局部缺陷内联放在最贴近的相关差异范围上，跨领域的架构或范围问题用 PR 级评论；把阻塞项与建议分开，并省略已由通过的门禁守住的问题。收到评审意见时，逐条核实，凭技术理由修复或反驳，不做表演式的附和。

## 它拒绝成为什么

- **它不是一份完整清单**，也不替代对它总结的那份差异的语义评审。
- **它不发明规则。** 本项目评审所依据的规则是指令文件里的常驻指令；当这里的一条检查在那里找不到对应条目时，去问维护者，而不是发明一条规则。
- **它不把自动化检查当作质量的证明。** 新散文需要语义评审，而一个通过的配对哈希证明的是结构与记录，不是译文说了同一件事。
- **它不接受对一次测试运行的转述当作那次测试运行**，也不接受把覆盖率当作场景正确的证据。
- **它不因为与决策记录意见不同就否决。** 对 Agent Note 的分歧是一次设计讨论。

## 它的检查如何运行

本技能只交付散文，不含任何代码。门禁位于整个集合唯一的代码归属 `../dsh-spec-manager/scripts/`，并按名称通过它们旁边的分发器 `run.ts` 寻址；一次改动所欠的证据清单由 [`dsh-pre-push-checks`](../dsh-pre-push-checks/SKILL.md) 选择，而聚合检查就是整套检查：

```sh
pnpm dlx --allow-build=esbuild tsx@4.22.4 .agents/skills/dsh-spec-manager/scripts/run.ts --all --root .
```

评审者要确认作者运行了这次差异所选出的检查，并确认 CI 覆盖了穷举矩阵；两者都不能替代只有读者才能弥合的语义空缺。
